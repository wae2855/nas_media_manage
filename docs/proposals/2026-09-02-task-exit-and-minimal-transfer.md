# 任务退出、来源处置与最少传输方案

- **Requirement**: [REQ-20260902-021000](../tracking/requirements-board.md)
- **Discovery**: [全流程评审](../brainstorms/2026-09-02-task-exit-and-minimal-transfer-brainstorm.md)
- **ADR**: [ADR-0021](../decisions/0021-task-exit-and-direct-library-staging.md)
- **Plan**: [实施计划（已完成）](../_archive/2026-09-02-task-exit-and-minimal-transfer/2026-09-02-feat-task-exit-and-minimal-transfer-plan.md)

## 目标

把“任务不要了”和“来源文件不要了”拆成用户看得懂、系统可审计的两个决定；补齐排队、运行、待确认、重复、失败、跳过、取消、完成与重新整理的退出路径。同时保持先识别决策、后传输大文件，并让新任务默认直接写入目标任务暂存，减少一次完整中转复制。

## 产品合同

- 活动/异常任务主动作叫“结束处理”，不是含糊的“删除”。
- 弹窗明确选择：保留新资源、移入本地回收区；只有全局已启用高风险模式时才显示永久删除。
- “删除记录”永远只删除数据库历史，不删除来源或片库文件。
- 目标重复提供“保留片库并保留新资源”和“保留片库并回收新资源”；原片库指纹不变。
- 运行中请求显示“正在安全停止”；片库文件包提交后不再接受取消。
- 来源处置失败时任务记录必须保留并说明下一步，不能先删记录。

## 实现边界

- 新增持久化停止请求、来源处置和结果字段；状态转换仍由 tasks feature 统一管理。
- 增加状态感知的任务处置服务；旧 delete API 保持兼容但不再使用误导文案。
- 大文件复制和哈希阶段加入协作式检查点；停止异常由 runner/confirm 单独捕获并安全收尾。
- 新任务从来源直接复制到目标任务暂存；ADR-0022 已取消旧中转断点，所有重试均从来源重新识别和完整执行。
- 目标文件包仍执行完整性校验、任务清单、字幕先发布、视频最后发布和 no-replace。
- 单任务来源处置只处理登记的视频与字幕；整组来源目录仍走来源单元协调器。

## 非目标

- 不强制杀死 Python 线程。
- 不允许普通任务动作删除、移动或重命名目标片库文件。
- 不把失败、跳过或取消伪装为“已完成”。
- 不在本轮开放对多个任务共用来源目录的递归清空。
