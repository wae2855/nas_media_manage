# 手动刮削确认与随片文件包安全入库提案

- **Requirement**: [REQ-20260901-020743](../tracking/requirements-board.md)
- **Discovery**: [全流程评审](../brainstorms/2026-09-01-manual-scrape-media-bundle-brainstorm.md)
- **Plan**: [已批准实施计划](../plans/2026-09-01-feat-manual-scrape-media-bundle-plan.md)

## 问题

手动刮削目前没有电影/剧集和资料语言选择，候选结果数量有限；点击候选后只保存少量名称字段并立即进入同步入库。用户无法在移动文件前核对完整资料、维度、目标片库、视频名和字幕名。

视频与字幕也没有作为同一个可恢复文件包表达。多字幕进度可能倒退，语言/路径状态不完整，视频先发布后字幕失败可能形成不易恢复的半完成作品；目标暂存、日志、来源清理和回收站的状态因此不够可信。

## 目标

- 手动搜索可选择电影/剧集/全部和资料语言，默认返回最多 20 条。
- 选择候选只更新作品资料、维度和入库预览，任务仍待确认。
- 用户核对后点击“确认并在后台入库”，关闭网页仍继续执行。
- 列表和详情及时更新片名、海报、年份、类型、维度、目标路径和字幕计划。
- 视频和全部随片字幕以一个文件包复制、校验、发布、恢复和展示，字节进度单调可信。
- 任何既有片库文件不被静默覆盖或删除；异常不会被普通“成功”隐藏。

## 推荐方案

### 1. 拆开“选择资料”和“确认入库”

候选选择提交稳定的 Provider ID、类型和语言。后端读取完整详情，重新执行维度映射、规则分类、命名和冲突预检，返回更新后的待确认详情；此时不移动片库或处理来源。

用户另点“确认并在后台入库”。API 快速排队，后台 worker 幂等续跑；列表和运行详情轮询真实状态，浏览器生命周期不参与任务生命周期。

### 2. 建立随片文件包

扫描时确定性关联视频与字幕，记录语言、大小和指纹。目标暂存与入库进度以视频加字幕总字节聚合，同时显示当前成员及序号。

目标片库采用“任务专属暂存 → 全部完整性校验 → 发布字幕 → 最后发布视频”。视频是文件包提交标记；提交前失败只回滚任务自己创建且指纹匹配的内容。提交后来源处理失败作为显式警告，不重复写入片库。

### 3. 任务信息分层

列表显示作品结论、关键维度、目标片库和当前阶段；详情依次显示作品资料、入库预览、分类判断、随片文件、进度事件。确认后详情切换只读运行态并局部刷新。

终态分别说明影片、字幕、来源处理结果，杜绝“影片已入库但字幕或来源失败仍显示完全成功”。

### 4. 目标暂存、日志、回收与恢复一致

目标侧任务暂存和启动恢复按文件包及成员记录；日志记录阶段边界和当前文件；回收站将来源整组显示为“1 视频 + N 字幕 + M 其他文件”，目标冲突回收与来源清理分组。重启依据提交标记和指纹决定安全回退、复核成功或要求人工检查，不续接旧步骤。

### 5. 先确认目标和冲突，再传输大文件

发布名解析、TMDB 识别、轻量媒体探测、片库规则落点和只读冲突预检都直接基于来源执行。只有目标明确且用户已处理冲突后，才把视频和字幕直接复制到目标侧任务私有暂存；选择保留片库现有文件时不复制，也不自动清理来源。

来源清理在“清理垃圾”与“整组清空来源”模式下共用一个从属二选一：默认移入本地回收区，或按 ADR-0019 显式选择永久删除。永久删除必须经不可恢复确认、来源单元快照门禁和任务删除隔离区执行，不能触及目标片库。

### 6. 兜底入库与重新整理保持两条任务记录

未匹配正式入库规则时不开放手工目录选择。待确认页只允许调整维度、重新刮削，或明确确认“放入待整理区”；确认后影片进入配置的兜底目录，原入库任务以 `SUCCESS/DONE` 结束，并附“待整理”结果标记，不再显示“需确认”。

已完成任务保持只读。用户点击“重新整理”时创建一条关联的新任务，以片库中现有视频和字幕为输入，重新选择资料或调整维度后仍由入库规则决定新位置。新任务未匹配正式规则时不得确认；匹配后执行无覆盖、安全回退的片库内文件包移动。原任务只追加关联结果，不回退状态、不改写其历史入库路径。

## 安全与产品边界

- 目标片库仍只新增；替换必须经用户确认并先回收到本地回收区。
- 字幕目标冲突也不能静默覆盖。
- 回滚仅限任务自建、允许目录内、指纹匹配的暂存/发布文件。
- 视频发布前不处理来源；文件包提交后才允许执行来源策略。
- 片库替换的旧文件始终进入本地回收区；来源永久删除配置不能改变这条边界。
- 非字节阶段不显示虚假百分比，不承诺 ETA。

## 影响面

- 后端：tasks/search、provider、manual review/confirm、import-flow、subtitle repository、scanner/naming、filesystem recovery、source cleanup、recycle。
- API：搜索条件、候选应用、后台确认、任务详情和进度字段。
- 前端：手动刮削弹窗、任务列表/详情实时态、随片文件和回收分组、移动端适配。
- 数据：任务文件包状态、当前成员进度和逐字幕状态迁移。
- 测试/文档：状态机、文件流、安全矩阵、API、移动端与 fnOS 验收。

## 备选方案

- **只补电影/剧集和语言选项**：不能解决选中即入库、资料不完整和字幕半完成，否决。
- **视频先入库，字幕失败算警告**：实现较小，但用户会得到不完整作品，恢复和来源清理复杂，否决。
- **字幕失败重跑整部视频**：对 NAS 大文件成本过高，否决。
- **暂存完整文件包、视频最后发布**：推荐，实施面较大但安全、恢复和用户认知最一致。

## 评审门槛

产品确认候选/确认分离、20 条结果、字幕编号与文件包发布策略后才进入代码。实现必须先通过文件包失败与重启恢复证明，再开放 fnOS 验收包。
