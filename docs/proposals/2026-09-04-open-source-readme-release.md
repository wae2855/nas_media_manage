# 开源项目 README 与公开发布方案

## 问题（现状与痛点）

现有 README 和 GitHub 简介仍描述已移除的中心中转、AI 刮削与 Hermes，仓库没有许可证。完整 Git 历史还包含疑似真实 API Key、令牌和 secret，不能原样切换公开。

## 目标（可验证）

- README 准确说明当前功能、fnOS/开发安装、安全边界、贡献方式和自愿赞助。
- 直接复用产品配置开始页的赞赏码与微信二维码。
- 使用用户确认的 MIT License。
- 公开仓库不包含历史凭据、运行配置、数据库、日志或构建产物。

## 方案概述（推荐方案 + 关键取舍）

先在当前私有仓库完成 README、MIT 和文档验证。用户选择保留原 URL，因此清除包含旧凭据的历史文件，重写所有分支和标签并强制同步；复扫完整历史无敏感命中后才切换公开。历史删除不能替代 Provider 侧吊销。

## 影响面（代码/配置/API/测试/文档）

- 文档：根 README、MIT、需求/计划/验收记录。
- GitHub：简介、主题、可见性和可能的历史发布方式。
- 运行代码、配置格式和 fnOS 安装包内容不变。

## 备选方案（为何不选）

- 直接把当前仓库改为公开：会暴露历史疑似凭据，否决。
- 只删除当前配置文件：Git 历史仍可读取旧内容，不能解决问题。
- 创建全新清洁历史公开仓库：安全性更直观，但会更换仓库地址；用户选择保留原地址。
