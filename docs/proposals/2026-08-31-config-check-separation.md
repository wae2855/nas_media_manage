# 配置检查职责分离与目录操作边界提案

- **Requirement**: [REQ-20260831-214244](../tracking/requirements-board.md)
- **Plan**: [实施计划](../plans/2026-08-31-fix-config-check-separation-plan.md)

## 问题

存储检查页面同时展示目录健康和旧规则关联异常，导致用户在选择硬盘时被迫理解业务分流规则。完成页虽然已有聚合检查，但“运行开场检查”不如“配置检查”直观，规则问题的修复导航也没有进入片库整理。

同时，文件系统的目录写权限不能区分新增与删除。目标片库的“不删除”承诺必须由应用操作边界保证，不能由 ACL 或写入探针代替。

## 决策

1. 存储检查只管理和检查目录，不展示、编辑或跳转规则。
2. 片库整理继续独立负责每条规则的片库选择，本轮不调整页面。
3. 完成页主动作统一命名为“配置检查”，聚合目录、规则目标、TMDB、按需 LLM 和自动运行状态。
4. 规则未绑定、引用不存在/停用片库或相关目录不可访问时，只在配置检查中阻断并指向片库整理。
5. 冻结目录角色操作矩阵：来源、回收、日志和缓存可在各自安全边界内读写及清理；片库只允许读取、新增和受控更新，通用删除、清理、改名与覆盖禁止。用户逐项确认替换是唯一例外，旧文件必须先进入本地回收。中心中转角色已由 ADR-0022 删除。

## 用户流程

```text
存储检查：选择/授权目录 → 查看路径、挂载、权限、容量
片库整理：逐条选择规则目标片库
完成：点击“配置检查” → 一次查看全部运行阻塞项 → 去对应阶段修复
```

## 非目标

- 不自动猜测规则归属。
- 不调整片库整理结构。
- 不新增另一套前端规则校验事实源。
- 不放宽目标片库现有文件保护。

## 验收摘要

- 存储页和目录弹窗不出现旧规则列表。
- 旧规则问题在配置检查中准确显示并跳到片库整理。
- 片库目录仍可独立、动态添加和保存。
- 安全标准明确物理目录能力与产品允许操作的区别。
