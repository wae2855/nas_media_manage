# 存储安全与配置界面简化重构提案

## 问题（现状与痛点）

当前胶卷式配置导航有明确的影院辨识度，但阶段内同时暴露目录、扫描、清理、LLM、命名和系统参数，首次用户容易放弃。fnOS 安装值没有完整成为 Web 配置的可信起点；运行链路还缺少云盘掉线、文件未稳定、跨盘复制校验、回收恢复事务和容量门禁。

因此，这不是单纯的页面重排。若界面先宣称“配置完成”，现有文件链路可能在 BT 下载中、云盘中断或空间不足时误处理源文件。

## 目标（可验证）

- 保留现有胶卷导航形式、黑金影院主题、剧照背景和金色激活态。
- fnOS 安装提供的目录可直接进入运行配置；Web 不重复询问有效值。
- 首次用户只处理异常目录、TMDB 和整理预设；其余明确标记“推荐设置，通常无需修改”。
- 来源和目标可为本地或 fnOS 已挂载目录；中转、回收、数据库和日志必须位于本地存储。
- 所有跨设备移动遵循“暂存、验证、发布、最后处理源”；中断后可恢复或安全重试。
- 云盘离线时暂停相关任务并显示原因，恢复后对账续接，而非形成失败风暴。
- 源视频默认保留；源垃圾清理与入库后处理是两个独立、显式选择。

## 用户故事

### STORY-001 安装值直接复用

作为 fnOS 用户，我希望安装时选择的来源、片库和回收目录自动出现在配置页，并在有效时无需再次确认。

验收：首次安装写入一次；升级和重装不覆盖；页面展示值的来源与最近校验结果。

### STORY-002 只处理配置异常

作为首次用户，我希望系统先采用推荐值，只要求我处理会阻止运行的问题。

验收：配置页给出 `可开始/需处理/暂不可自动运行` 结论；高级表单默认折叠。

### STORY-003 云盘中断不造成误删

作为云盘用户，我希望挂载短暂离线时停止扫描、复制和清理，恢复后继续而不丢文件。

验收：离线与真实失败分开；在途副本和本地回收内容保留；恢复后重新验证源版本。

### STORY-004 安全清理与恢复

作为 BT 或云盘用户，我希望明确选择是否保留源视频和是否清理垃圾，并能从本地回收站恢复。

验收：默认保留；预览与执行对象一致；恢复目标离线时保持待恢复，不删除回收副本。

## 方案概述（推荐方案 + 关键取舍）

### 存储角色

| 角色 | 允许位置 | 默认 | 根目录行为 |
|---|---|---|---|
| 来源 | 本地或已挂载远程 | 安装时选择 | 必须存在，只验证不创建 |
| 片库目标 | 本地或已挂载远程 | 安装时选择 | 必须存在，只验证不创建 |
| 中转 | 仅本地 | 应用私有目录 | 可创建应用子目录 |
| 回收 | 仅本地 | 安装时选择 | 根必须存在，可创建应用子目录 |
| DB/日志/资源 | 仅本地 | 应用私有目录 | 应用管理 |

### 配置状态

`UNCONFIGURED → VALIDATING → READY`，任何硬错误进入 `BLOCKED`。服务可以启动用于修复配置，但扫描、自动运行、清理、恢复均受 READY 门禁约束。

### 来源健康状态

`ONLINE → DEGRADED → OFFLINE → RECOVERING → ONLINE`。挂载消失不得被解释为空目录，也不得自动创建同名目录。

### 胶卷配置目标预览

```text
┌ 黑金影院标题：片库搭建 ─────── [运行模拟] [高级配置] ┐
│ ◫ 开始 │ ◫ 文件来源 │ ◫ 存储检查 │ ◫ 作品识别 │ ◫ 片库整理 │ ◫ 自动运行 │ ◫ 完成 │
└────────────────────────────────────────────┘

当前阶段：存储检查                                      [重新检查]
┌ 安装时已配置 · 通常无需修改 ─────────────────────────┐
│ 来源  /vol.../downloads       已授权 · 云盘挂载 · 在线 │
│ 片库  /vol.../media           可写 · 剩余空间未知      │
│ 中转  应用本地目录            本地 · 空间充足           │
│ 回收  /vol.../recycle/app     本地 · 空间充足           │
└────────────────────────────────────────────┘
只有黄色/红色项展开处理动作；绿色项保持摘要状态。
```

### 配置内容分层

- 必须处理：目录硬错误、TMDB 缺失、没有可用片库规则。
- 推荐默认：扫描、命名、并发、日志和安全余量，显示何时才需要调整。
- 显式风险选择：自动运行、入库后源处理、垃圾清理。
- 高级配置：完整参数和现有维度入口，不进入首次流程。

## 影响面

- 配置：schema、迁移、校验、原子保存、运行快照、就绪门禁。
- 文件系统：稳定文件门禁、容量预留、可恢复复制、路径边界。
- 回收：服务端记录 ID、本地根约束、恢复事务、覆盖项二次回收。
- 任务：原子领取、位置健康、等待原因、入库和清理结果分离。
- fnOS：首次安装导入、升级保留、授权和真实设备验收。
- 前端：胶卷内容重组、状态摘要、异常驱动配置、响应式和无障碍测试。

## 本轮非目标

- 不直接集成 WebDAV、SMB、NFS、Alist 或网盘厂商 API；只消费 fnOS 已挂载路径。
- 不自动永久清空回收站换取空间。
- 不在本轮重做维度映射和各国限制级归一。保留现有逻辑与高级入口，后续单独头脑风暴“系统预置 + 用户覆盖 + 必须确认策略”。
- 不改变 TMDB 主导的两级识别边界。

## 备选方案（为何不选）

- 只重排页面：无法兑现“配置通过即可安全运行”，否决。
- 禁止所有远程来源和目标：安全但不能覆盖真实 fnOS 使用场景，否决。
- 回收目录允许云盘：离线恢复、空间释放和回收可靠性不可控，否决。
- 每个高级值都记录是否被用户修改：增加配置来源复杂度；本轮只标记“当前推荐”，不声称“从未修改”。
