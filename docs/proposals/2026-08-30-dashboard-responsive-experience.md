# 首页语义与全站双端体验优化提案

## 问题（现状与痛点）

首页把待人工确认数量显示成视频处理进度，“今日入库”、最近活动和最近影片也没有采用真实业务口径。任务工作台在 390px 以下裁切判断结果和操作，回收站在 768px 就超宽；长弹窗与固定底部导航还会让手机主操作不可达。

## 目标（可验证）

- 首页只有真实运行任务显示真实进度；待确认、失败和暂停分别表达。
- 今日入库按当天成功完成统计，最近活动最多 5 条业务事件，轮播展示最近 12 部成功入库影片。
- 缩略图缓存同时遵守 500 张和 200 MB 软上限，不触碰影视、回收和支持二维码文件。
- 1280、768、390、360、320px 下核心流程无裁切、无遮挡、操作可达。
- 保留桌面高信息密度、影院主题和配置胶卷导航。

## 方案概述（推荐方案 + 关键取舍）

后端提供有界首页业务摘要和最近成功任务，以任务状态、完成时间及图片关联替代累计数、原始日志和文件修改时间。前端按运行、待确认、失败、暂停和空闲状态渲染互斥提示。

桌面继续使用现有布局；768px 以下回收站、390px 以下任务工作台采用分层卡片。通用移动弹窗使用固定头尾和内部滚动，页面操作区为底部导航预留安全距离。320px 定义为安全可用边界，允许减少装饰密度。

先以任务和回收站作为证明切片，通过五个视口后再推广通用响应式规范。

## 影响面（代码/配置/API/测试/文档）

- 后端：任务只读查询、首页摘要 API、缩略图列表与缓存治理。
- 前端：首页、任务、回收、共享弹窗、配置完成页、模拟器、胶卷轨道和响应式样式。
- 测试：API、缓存安全、首页语义、静态结构和 Playwright 多视口。
- 文档：API、前端信息架构、测试覆盖、需求与验收台账。
- 配置：不新增用户配置项。

## 备选方案（为何不选）

- 仅修改 CSS 缩小内容：无法解决首页业务语义，也会继续隐藏任务和回收操作。
- 手机使用完全独立页面：会形成两套行为和长期维护成本。
- 继续读取技术日志生成活动：内部文案不稳定，无法保证用户理解和事件去重。
- 缓存只限制数量或容量：无法同时防止大量小图和少量异常大图占满空间。
