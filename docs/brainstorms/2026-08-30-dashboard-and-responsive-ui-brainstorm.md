# 首页状态与全站响应式体验评审

> 当前状态：仅记录与评审，不实施代码。首页方案已经确认；需要完成全站桌面端与多种手机宽度评审后，再统一进入计划和开发。

## Problem Statement

产品主要同时服务电脑端与手机端。当前影院主题和胶卷导航方向保留，但首页部分状态语义不准确，并且尚未对全部页面进行系统性的移动端验收。目标是在不改变产品气质的前提下，让所有核心流程在桌面和手机上都能读懂、操作、完成。

## 已确认：首页待实施清单

- [ ] 首页状态卡改为状态驱动：只有真实运行任务展示真实进度条。
- [ ] 没有运行任务但存在待确认时，展示黄色行动提示和“去处理”，不显示进度条。
- [ ] 同时存在运行任务和人工待办时，主区域展示当前任务进度，附加待确认/失败数量提示。
- [ ] 轮播改为按任务完成时间选择最近 12 部成功入库影片，同一作品去重。
- [ ] 轮播速度由 2.8 秒放慢至约 4.5 秒；悬停、键盘聚焦和减少动态效果时暂停。
- [ ] 海报缩略图作为可再生成缓存管理，默认建议 500 张或 200 MB 软上限，保护运行中、待确认和当前轮播图片。
- [ ] 最近活动由原始技术日志改成业务事件，首页最多展示 5 行。
- [ ] “今日入库”按当天成功完成时间真实统计，不再使用全部成功与跳过任务总数。
- [ ] 没有运行任务时弱化或禁用“暂停处理”；没有失败任务时弱化或禁用“重试失败项”。
- [ ] 顶部状态区分“服务正常”“后台整理中”“后台整理已暂停”。

## 已验证现状

- 当前 27 项全部处于 `AWAIT_REVIEW`，首页进度条实际使用 `PENDING / (PENDING + FAILED)`，不是文件处理进度。
- 轮播当前已经按缩略图文件修改时间倒序取 12 张，但不是按任务业务时间查询。
- 缩略图目录会持续增加，没有数量、容量或年龄清理边界；当前测试目录 20 张约 1.7 MB。
- 最近活动当前请求 `/logs?limit=6`，最多 6 行，但直接展示原始技术日志。
- “今日入库”当前实际展示全部 `SUCCESS + SKIPPED`，与标题不一致。

## 响应式评审结论

整体结论：桌面端结构稳定，配置流程在手机上也基本可用；任务工作台和回收站不是细节问题，而是移动信息结构尚未成立。进入开发时应保留桌面布局和胶卷导航，只为手机建立更紧凑的卡片层级、操作区和弹窗规则，不能仅靠缩字号或隐藏横向溢出来处理。

| 页面/区域 | 1280px 桌面 | 768px 小平板 | 390/360px 手机 | 320px 边界 | 结论 |
|---|---|---|---|---|---|
| 首页 | 通过 | 通过 | 通过，有小触控目标 | 可用，装饰可适当减少 | 调整状态语义、轮播与活动，不重做结构 |
| 任务工作台 | 通过 | 通过 | 失败，卡片右侧被裁切 | 严重失败 | P0：建立移动任务卡 |
| 回收站 | 通过 | 失败，行宽约 934px | 严重失败，操作不可达 | 严重失败 | P0：列表改为移动卡片 |
| 配置胶卷轨道 | 通过 | 通过 | 可用但缺少横滑提示 | 可用边界 | 保留胶卷形式，补充滑动可发现性 |

### P0：核心流程必须修正

#### 任务工作台

当前任务卡在 390/360/320px 仍保留约 530px 的内部内容宽度。页面本身使用横向隐藏，因此浏览器没有出现横向滚动条，但维度信息和右侧操作被直接裁掉，用户无法完成待确认任务。

移动端建议改为分层卡片：

1. 第一层只展示 72px 海报、片名、状态、来源和最需要用户处理的原因。
2. 默认仅展示 2—3 个关键判断结果，其余维度放入“查看全部判断”。
3. “确认入库”等主操作使用整行按钮；次要操作进入“更多”。
4. 筛选项保留横向滑动，但增加边缘渐隐，选中项自动滚入可视区。
5. 批量选择后，批量操作条固定在底部导航上方，不能与导航重叠。

桌面端继续保留高信息密度卡片，不强行与手机共用同一排版。

#### 回收站

当前回收行在 768px 仍约 934px 宽，在手机端路径和恢复/清理操作都不可达。移动端应从桌面横向行改为纵向卡片：

1. 第一行展示文件名、回收状态和剩余保留时间。
2. 第二层展示大小、回收时间以及最多两行的原路径，并提供复制或展开。
3. “恢复”作为主操作；永久清理等破坏性操作放入明确的次级菜单并再次确认。
4. 回收类型、内部来源等技术字段移入详情，不占首屏。

### P1：全站移动交互规范

#### 固定底部导航与页面操作

底部影院导航本身尺寸合适，可以保留；问题在于它会覆盖滚动到视口底部的页面按钮。统一处理方式：

- 所有移动页面预留导航高度和系统安全区。
- 需要持续可见的主操作条固定在导航上方，而不是被导航覆盖。
- 弹窗打开或软键盘出现时，底部导航不应继续遮挡或抢占操作。
- 完成页、模拟器和批量处理优先套用这一规则。

#### 弹窗

任务详情在 320px 下内容高度约 1715px，LLM 配置约 1336px，保存/确认按钮都位于长内容末尾。手机端统一改为接近全屏的弹层：

- 使用 `100dvh` 边界并保留安全区，弹层内部滚动。
- 标题和关闭按钮固定在顶部，保存/确认/取消固定在底部。
- 关闭按钮及主要点击区域至少提供约 44px 的触控热区。
- 任务详情先展示结论、待处理原因和主操作，路径、日志、维度明细折叠到“更多信息”。
- LLM 和 Provider 配置把帮助说明折叠，连接测试结果紧邻测试按钮显示。
- 规则编辑当前堆叠关系基本正确，只需并入统一头尾和触控规范。

#### 小按钮与选择控件

目前筛选按钮约 36px、任务和规则操作约 34px、回收操作约 28px、部分复选框约 13—18px、弹窗关闭约 36px。视觉图标可以较小，但按钮或关联标签的有效触控热区应统一提高到约 44px，避免用户在手机上误触。

### P2：体验增强

#### 配置胶卷轨道

胶卷横向轨道是产品识别度，应完整保留。手机一次只能看到约两个步骤，建议增加两侧渐隐、首次“左右滑动查看更多”提示和 `当前步骤 / 总步骤`，切换步骤后继续自动居中。不要改成普通标签页或纵向菜单。

#### 首页移动细节

- 轮播支持手指滑动，并保持悬停、键盘聚焦和减少动态效果时暂停。
- 胶片画面的点击热区至少达到手机触控标准，即使可见画框较窄也应扩大透明热区。
- 最近活动固定 5 行后，首页高度会更稳定；更多记录通过独立入口查看。
- 320px 下可减少光晕、胶片边饰等装饰密度，但不能牺牲状态和主操作。

## 建议的支持边界

- 1280px 及常见桌面：完整桌面体验。
- 768px 小平板：核心流程完整可操作；允许采用手机卡片结构。
- 360—430px：移动端主要验收范围，功能和视觉都应完整。
- 320px：建议定义为“安全可用边界”——不裁切、不遮挡、主操作可达、文字可读，但不要求与 390px 保持完全相同的装饰密度。

这样可以覆盖旧款小屏设备，同时避免为了 320px 的装饰一致性破坏胶卷主题和主要手机体验。

## 与首页方案合并后的实施批次

本轮确认后建议作为同一个“全站双端体验优化”方案实施，但分批验收：

1. P0 移动核心流程：任务工作台、回收站、底部操作安全区。
2. P1 通用移动规范：弹窗、触控热区、完成页和模拟器操作区。
3. 首页语义优化：真实运行进度、人工待办、最近入库轮播、5 行业务活动和真实今日统计。
4. P2 主题细节：胶卷横滑提示、动效暂停和 320px 装饰降级。

每一批分别验证 1280、768、390、360 和 320px，避免移动调整回归桌面。

## Open Questions

- 极窄 320px 是否按建议定义为安全可用边界，不追求与 390px 同等装饰完成度。
- 海报缓存默认上限最终采用数量、容量，还是两者同时生效。

## Out of Scope

- 本轮不修改任何前端或后端代码。
- 在响应式评审和产品确认完成前，不进入实施计划。
