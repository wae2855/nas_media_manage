# Safety Standards

## File Delete Rule

所有删除或覆盖影视文件必须先移入回收站，禁止直接 `os.remove()` 删除源文件或入库文件。

## Temporary Files

临时文件可直接删除的边界：

- `.tmp`
- `.copying`
- 明确位于 `temp_dir` 的处理副本

临时文件名不等于可信身份。`.copying`、`.replacement.tmp`、权限探针、日志和回收记录必须拒绝符号链接及非普通文件；需要续传的临时文件还必须是当前用户持有的单链接文件。创建探针/记录使用随机名或 `O_CREAT|O_EXCL|O_NOFOLLOW`，发布使用“目标不存在才成功”的原子门禁，禁止 `os.replace` 覆盖并发出现的目标。

可再生成的界面 Thumbnail 缓存不是影视文件，可在同时满足以下条件时直接治理：Thumbnail 根本身不是符号链接且不与任何片库根重叠、真实路径位于该根目录、是单链接普通图片、未被运行中/待确认/当前最近影片引用。路径归属无法确认或删除失败时必须跳过且不得阻断入库流程。二维码等人工提供的静态资产不属于该缓存。

## Allowed Directories

文件移动和删除应传入 `allowed_base_dirs` 或等价保护，避免路径穿越和误删。

目录角色必须先经过绝对路径、`realpath` 与 `commonpath` 拓扑检查。来源、中转、回收、日志、资源缓存和每个目标片库根之间不得相同或互为父子；符号链接不能作为直接删除或回收对象。历史冲突配置在运行时也必须失败关闭，不能只依赖前端保存校验。

路径校验、权限检查、安全移动/删除和指纹基础能力位于 `media_importer/infrastructure/filesystem/`。`media_importer/core/safety.py` 只作为旧导入兼容 facade。

多片库根使用稳定 root ID。每条规则和兜底目录必须绑定一个存在且启用的根，保存与运行时都执行 `realpath/commonpath` 校验；禁止用多根能力恢复任意绝对目标。远程片库掉线时不得创建同名本地目录。

目标片库默认只新增。发现同作品候选或最终目标同名时，检测阶段必须零写入并进入 `PENDING/AWAIT_REVIEW`；普通确认和批量确认不得绕过。用户逐项选择替换时必须用 SHA-256 内容哈希重检现有文件；新文件完成长复制后，先以唯一临时名原子认领旧文件并再次复核内容，再把旧文件移入已验证的本地回收区，最后以 no-replace 协议发布新文件。回收不可用、内容变化、并发目标出现或发布失败必须停止并保留/恢复旧文件，禁止降级为永久删除。冲突操作只能作用于本任务实际目标根。

启动恢复、任务删除、通用重命名、来源清理和回收保留清理都不是片库管理入口。它们不得删除、移动或改名目标片库文件；已完成入库但尚未来得及落库状态的中断任务只修复为成功状态并保留文件。

没有 `library_roots` 的配置不得从绝对规则推断目标目录。旧规则迁移只能使用管理员通过目录选择器明确选择的根，按最长包含关系逐条转换；任一未覆盖项必须原子失败。移除片库只删除配置引用，绝不删除片库文件，且规则或兜底仍引用时必须阻止。

## Source Cleanup

源文件处理由三种互斥模式控制：

- `preserve_all`: 不写入源目录；
- `preserve_media`: 保留媒体，仅由源目录清理器回收规则/LLM 判定的垃圾；
- `recycle_source_unit`: 同一来源单元全部媒体任务成功且快照未变化后整组回收。

失败、跳过、待确认、存在未建任务媒体、快照变化或挂载/回收目录异常时，来源单元必须保持不变。源目录根本身永远不得作为文件夹来源单元移动。

主任务完成、跳过或临时文件场景的源文件策略位于 `media_importer/features/source_files/`。源目录清理器仍位于 `media_importer/features/source_cleaning/`。

## Deploy Directory

`deploy/` 目录不是默认开发源。同步部署目录必须作为明确任务执行。
