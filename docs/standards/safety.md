# Safety Standards

## File Delete Rule

目标片库影视文件的删除或覆盖必须先移入本地回收站，禁止直接删除。来源内容默认同样进入本地回收；唯一例外是用户显式启用 ADR-0019 的“永久删除来源”。整组来源必须通过提交状态、来源单元快照和挂载身份门禁；智能清理垃圾必须排除所有任务成员并通过来源挂载和拓扑门禁；两者都只能删除任务隔离区内已认领内容。即使启用该例外，也禁止对原始业务路径直接调用 `os.remove()`、`unlink()` 或递归删除。

## Temporary Files

临时文件可直接删除的边界：

- 任务清单明确登记、位于本任务最终目标根内并带本任务标识的 `.bundle.tmp`
- 上述任务暂存对应的 `.copying`
- 应用私有数据目录内、业务归属可证明的普通 `.tmp`

临时文件名不等于可信身份。`.copying`、`.replacement.tmp`、权限探针、日志和回收记录必须拒绝符号链接及非普通文件；需要续传的临时文件还必须是当前用户持有的单链接文件。创建探针/记录使用随机名或 `O_CREAT|O_EXCL|O_NOFOLLOW`，发布使用“目标不存在才成功”的原子门禁，禁止 `os.replace` 覆盖并发出现的目标。

权限探针还必须写入本轮随机令牌，删除前重新打开并核对令牌与当前文件身份。FUSE 返回异常关闭结果时允许容错继续核对，但不能按名称清理未知历史探针；无法证明为本轮文件时失败关闭。

可再生成的界面 Thumbnail 缓存不是影视文件，可在同时满足以下条件时直接治理：Thumbnail 根本身不是符号链接且不与任何片库根重叠、真实路径位于该根目录、是单链接普通图片、未被运行中/待确认/当前最近影片引用。路径归属无法确认或删除失败时必须跳过且不得阻断入库流程。二维码等人工提供的静态资产不属于该缓存。

## Allowed Directories

文件移动和删除应传入 `allowed_base_dirs` 或等价保护，避免路径穿越和误删。

目录角色必须先经过绝对路径、`realpath` 与 `commonpath` 拓扑检查。来源、回收、日志、资源缓存和每个目标片库根之间不得相同或互为父子；符号链接不能作为直接删除或回收对象。冲突配置在运行时也必须失败关闭，不能只依赖前端保存校验。

路径校验、权限检查、安全移动/删除和指纹基础能力位于 `media_importer/infrastructure/filesystem/`。`media_importer/core/safety.py` 只作为旧导入兼容 facade。

### 目录角色操作矩阵（冻结）

文件系统返回的读写权限只说明物理能力，不能决定产品允许执行什么操作。尤其在 POSIX 文件系统中，目录写权限通常同时允许创建和删除，因此目标片库的删除禁令必须由业务文件操作白名单保证。

| 目录角色 | 读取 | 新增/更新 | 允许清理的对象 | 产品硬边界 |
|---|---|---|---|---|
| 来源 | 允许 | 仅在所选来源处理策略需要时 | 仅规则确认的垃圾或已完成且快照未变化的来源单元；默认进入本地回收，显式高风险模式可按 ADR-0019 经隔离认领后永久删除 | 保留全部模式零写入；挂载、快照或任务状态异常时零处理；永久删除不得影响片库 |
| 本地回收 | 允许 | 允许 | 仅有回收账本且满足用户动作/保留策略的条目 | 恢复失败保留回收副本；禁止跨越已验证回收根 |
| 运行日志 | 允许 | 允许 | 仅应用日志轮转和保留清理 | 拒绝符号链接、硬链接替身及片库重叠目录 |
| 海报/缩略图缓存 | 允许 | 允许 | 仅满足缓存治理条件的可再生成资源 | 人工二维码和被任务/最近影片引用的资源不得清理 |
| 目标片库 | 允许 | 只允许新增入库；已有文件默认只读；已完成兜底作品可由关联重新整理任务整组移动 | 禁止通用删除、清理、改名或覆盖 | 逐项确认替换时旧文件必须先入本地回收；重新整理只允许 no-replace 移动本任务影片和字幕，禁止永久删除兜底 |

存储检查可以测试目录是否具备运行所需的物理读写能力，并把目标片库能力投影为 `read/create/update=true, delete=false`；该投影表达产品上限，不声称 ACL 本身阻止删除。

fnOS 应用私有目录只允许识别本应用 `${TRIM_PKGVAR}` 或 `@appdata/nas-media-importer` 边界，禁止把其他应用的 `@appdata` 当作免授权目录。私有日志和资源缓存由系统托管并实测进程权限；一旦用户改到共享目录，就必须重新进入 fnOS 授权与挂载身份门禁。

多片库根使用稳定 root ID。每条规则和兜底目录必须绑定一个存在且启用的根，保存与运行时都执行 `realpath/commonpath` 校验；禁止用多根能力恢复任意绝对目标。远程片库掉线时不得创建同名本地目录。

目标片库默认只新增。发现同作品候选或最终目标同名时，检测阶段必须零写入并进入 `PENDING/AWAIT_REVIEW`；普通确认和批量确认不得绕过。用户逐项选择替换时必须用 SHA-256 内容哈希重检现有文件；新文件完成长复制后，先以唯一临时名原子认领旧文件并再次复核内容，再把旧文件移入已验证的本地回收区，最后以 no-replace 协议发布新文件。回收不可用、内容变化、并发目标出现或发布失败必须停止并保留/恢复旧文件，禁止降级为永久删除。冲突操作只能作用于本任务实际目标根。

替换是作品文件包级能力，不能把“视频替换成功、字幕处理失败”当作可接受结果。当前原子替换只覆盖单视频；只要待入库作品含字幕，服务端和前端都必须拒绝替换，只允许保留片库现有文件或另存一份，直至视频和字幕整包替换事务及故障注入测试完成。

重新整理是目标片库通用禁移动规则的窄例外：只允许从 `SUCCESS/DONE + FALLBACK_PENDING` 父任务创建关联任务，只能操作父任务记录的现存普通影片与随片字幕，来源和目标都必须位于当前已配置片库根。移动复用任务绑定的文件包清单、SHA-256、字幕先发布/影片后发布、no-replace 和重启恢复协议；目标同名、路径越界、挂载变化或任一成员异常时必须保留双方，禁止删除或覆盖。

启动恢复、任务删除、通用重命名、来源清理和回收保留清理都不是片库管理入口。它们不得删除、移动或改名正式目标片库文件；唯一例外是提交前回退本任务已登记且指纹吻合的字幕时，先退回同任务 `.bundle.tmp` 再清理该临时文件。已完整提交但尚未来得及落库状态的中断任务只复核全部成员并修复为成功，同时保留来源。

任务“结束处理”只允许操作该任务在数据库登记的原始来源视频和字幕，不得递归处理同目录其他文件。运行中先协作停止并回退本任务目标暂存；视频提交到最终路径后拒绝停止文件流程。任务“删除记录”不得执行任何文件操作。

中心中转目录已取消。确认前禁止大文件传输，正常链路在确认后只复制一次到目标侧任务暂存；唯一例外是下述“来源快照稳定、目标摘要不一致”时的一次受限干净重试。提交前中断只清理任务清单证明归属的目标临时文件并保留来源；完整提交后中断只复核并恢复成功；任何歧义均保留现场并要求人工检查。用户显式重试从来源重新刮削和完整执行，不复用旧临时文件。后台空闲 watcher 不读取任何目标片库。

完整性错误必须按证据提示：复制或来源哈希后的文件快照变化只能提示等待来源稳定；来源快照稳定但目标摘要不一致只能提示目标存储、挂载或读取可能异常，不得武断认定上游变化。普通入库可对后一种情况清理本任务精确 `.bundle.tmp.copying` 后从零重试一次；该任务临时文件清理必须验证授权目录、后缀、当前用户、单硬链接普通文件和打开前后 inode，不受通用删除的 50 GiB 保护上限影响。任何第二次不一致、清理身份异常或来源变化都必须失败关闭，禁止继续重试、发布目标或处理来源。

没有 `library_roots` 的配置不得从绝对规则推断目标目录。管理员可先通过目录选择器保存片库根，但每条规则和非空兜底目录都必须再人工选择一个存在且启用的 root ID；系统不得按默认根、添加顺序或路径包含关系自动分配。规则未选择或引用失效时，规则保存、配置检查和运行路径全部失败关闭；未被规则使用的片库合法。移除片库只删除配置引用，绝不删除片库文件，且规则或兜底仍引用时必须阻止。

## Source Cleanup

源文件处理由三种互斥模式控制：

- `preserve_all`: 不写入源目录；
- `preserve_media`: 保留媒体，仅由源目录清理器回收规则/LLM 判定的垃圾；
- `recycle_source_unit`: 同一来源单元全部媒体任务成功且快照未变化后整组回收。

`preserve_media` 与 `recycle_source_unit` 还必须使用互斥的 `source_policy.disposal_mode`：`local_recycle`（默认、可恢复）或 `permanent_delete`（来源专用、不可恢复）。永久删除必须先把精确快照成员认领进同一来源根内的任务专属 `.nas-media-delete-<unit-id>.deleting` 隔离区并落删除账本，只允许删除该隔离区；禁止扫描隐藏目录、直接递归删除原始来源路径或在回收失败时自动降级。

隔离区身份按挂载能力分层：本地盘必须匹配 rename 前后的 device 与 inode；明确识别的远程/FUSE 挂载必须匹配来源根真实路径、文件系统类型、挂载点、挂载来源和 locality，并复核账本声明的相对树、类型、大小和 mtime。远程模式只允许在隔离区内部逐层路径删除；额外成员、符号链接、特殊文件、嵌套挂载、挂载身份变化或未知挂载均立即停止。旧账本不得因为缺少新字段而默认放宽，只能由当前明确的远程挂载事实安全推导。

失败、跳过、待确认、存在未建任务媒体、快照变化或挂载异常时，来源单元必须保持不变；选择本地回收时回收目录异常同样保持不变。源目录根本身永远不得作为文件夹来源单元移动或删除。用户选择“保留片库现有文件”时不得自动永久删除来源。

永久删除续做返回 `BLOCKED` 或 `PARTIAL` 时，协调器必须立刻停止并把具体原因写入来源单元和任务详情；不得再把已认领的原路径缺失解释成新的“来源目录不存在”。

主任务完成、跳过或临时文件场景的源文件策略位于 `media_importer/features/source_files/`。源目录清理器仍位于 `media_importer/features/source_cleaning/`。

进度回调是观察能力，不是文件操作授权。任何进度实现都不得减少续传前缀检查、源/目标 SHA-256、`fsync`、no-replace 发布或来源快照复核；来源整组回收结束前任务不得无说明地显示整体完成。即使来源处理失败，已发布的目标片库文件仍受片库禁删边界保护。

## Deploy Directory

`deploy/` 目录不是默认开发源。同步部署目录必须作为明确任务执行。
