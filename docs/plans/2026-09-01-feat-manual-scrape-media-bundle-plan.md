## 2026-09-03 文件名与目录名联合识别切片

fnOS 真机样本“`双瞳 / Double Vision (2002)`”确认：视频 basename 只有英文名，第一层影片文件夹同时包含中文名、英文名和年份；TMDB 已返回正确作品，但现有匹配器没有把目录标题作为作品身份依据，且中文查询仍可能用英文主标题复核，导致正确结果进入人工确认。

本切片沿用任务 0 的统一身份解析方向，并冻结以下产品边界：

- [x] 文件 basename 始终是主证据；标题精确且年份一致时，任何无关目录名都不得阻断自动通过。
- [x] 目录 basename 必须独立清洗并通过有效性门禁后才成为辅助证据；源目录根、通用下载目录、技术结构目录、日期/哈希目录和多影片容器不得参与标题加权。
- [x] 中文、英文和目录候选分别查询，不拼接原始字符串；各查询必须用自己的标题复核候选，并按 `provider + media_type + provider_id` 合并证据。
- [x] 文件证据不足时，目录证据只有与同一 Provider 作品及兼容年份收敛才可补强自动通过；可信冲突、年份冲突和类型冲突继续进入人工确认。
- [x] 根直属单文件只使用文件名；`BDMV/STREAM/Season xx` 等结构目录可有限向上寻找有效标题目录，且不得越过配置的来源根。
- [x] 元数据选择与匹配结论共用同一份身份证据，任务详情保留文件名、目录名、查询和收敛/忽略原因。
- [x] 用“双瞳”、无关目录下强文件名、根直属单文件、可信冲突、多影片目录、BDMV 和剧集目录建立专项回归；不得增加目录递归扫描或页面加载磁盘读取。

验收标准：真机样本的中文目录与英文文件名收敛到 TMDB `57100` 时自动通过；强文件名置于任意无关目录时结论不变；目录证据不能单独把冲突或弱文件名错误自动通过。

本地证据（2026-09-03）：全量 1032 项通过；ruff、compileall、文档检查通过；完整真实 Chromium 文件流程矩阵扩展为 F01-F13，最新 `20260903T123229` 运行 13/13 通过并保留 17 张截图、文件树、SHA-256、任务和浏览器错误证据。新增场景确认广告伴随视频不会阻断《双瞳》的中英文身份收敛，多影片合集仍不会套用目录名。fnOS 真机样本仍待安装包验收。

让程序先从复杂真实发布名中稳定提取作品身份，再让用户选对作品、看懂入库结果并放心关闭网页；让视频和字幕作为一个完整、可恢复、可追踪的文件包安全进入片库。

## 前置产品与安全决策

### 发布名不是黑名单问题

采用“结构解析 + 多候选查询 + 保守自动通过 + 持续语料回归”四层模型：

1. 先识别年份、季集、版本、清晰度、片源、视频/音频编码、语言/字幕、流媒体、修订标志和发布组边界。
2. 保留中文、英文、文件夹名等多个标题候选，不把未知词无条件删掉。
3. 未知文本只有位于年份、季集或连续技术标签等强边界之后，才可降为“未分类标签”；强边界之前继续作为标题候选。
4. 自动通过除分数外，还必须满足标题/别名、年份、类型和候选分差门禁；有疑点就进入人工确认。

发布组识别优先使用 `[组名]`、末尾 `-GROUP`、技术标签后的大写后缀等结构，字幕组名称词典只补充例外。这样既能覆盖新组名，也避免把片名中的 `Korean`、`Extended`、数字或年份误删。

### 初始语料覆盖合同

建立不少于 800 条带期望标签的发布名回归集，按类别设最低配额而不是堆一张混合清单：

| 类别 | 最低数量 | 重点覆盖 |
|---|---:|---|
| 国际电影发布名 | 250 | 标题/年份、版本、碟号、片源、编码、发布组、网站标记 |
| 中文及东亚发布名 | 250 | 中英双标题、简繁/中英/特效字幕、国语/粤语/日韩语、字幕组前后缀、中文版本词 |
| 剧集/动漫/多集 | 150 | SxxEyy、1x02、EP、绝对集数、季包、多集范围、动漫组名 |
| 对抗与歧义样本 | 150 | 片名含年份/数字/4K/HDR/WEB/Korean/Extended、错误年份、无年份、广告串和散列串 |

语料来源分三类管理并记录来源/许可证：

- GuessIt 等开源解析器公开 fixtures 只在许可证和 NOTICE 评审通过后直接复用；否则只参考其行为类别，重新编写独立样本。
- Jellyfin 等项目的命名表达式用于覆盖面核对，不直接复制受许可证约束的实现。
- 用户在本机手动确认的“原始文件名 + 选中的 Provider ID/类型”形成本地增量回归记录；只保留 basename 和必要标签，不上传完整路径，不由单个样本自动修改全局规则。

常见标签词典至少分开维护：版本（EXTENDED/UNCUT/导演剪辑/未删减/修复版）、片源与清晰度（WEB-DL/BluRay/REMUX/BD1080P/4K）、视频/音频/HDR、语言与字幕（CHS/CHT/简繁/中英特效/内封/外挂/KOREAN/MULTI）、平台（NF/AMZN/DSNP 等）、修订（PROPER/REPACK/INTERNAL）、发布组/字幕组/网站广告。词典命中只生成结构属性和解析依据，不直接等价于“从标题删除”。

### 入库路径模板合同

入库路径模板只负责所选片库根下的**目录**，最终视频/字幕文件名由文件名模板决定。例：片库根为 `/vol5/1000/movies`：

- `movies` → `/vol5/1000/movies/movies/<最终影片文件名>`；
- `movies/{title_cn}` → `/vol5/1000/movies/movies/小姐/<最终影片文件名>`；
- `{title_cn} ({year})` → `/vol5/1000/movies/小姐 (2016)/<最终影片文件名>`。

禁止空值、`.`、以 `/` 或 `\\` 开头、Windows 盘符/UNC、任何 `..` 路径段、未知变量，以及渲染后落回片库根的模板。旧配置若违反规则，由“配置检查”明确阻断并要求人工修改，禁止静默改写路径。

### 来源清理边界合同

- `来源/影片.mkv`：来源根下的直属文件共同组成“散文件组”；全部直属媒体成功后，快照中的直属文件逐个移入本地回收区，来源根本身保留。
- `来源/阿甘正传/...`：第一层 `阿甘正传` 是一个来源单元；内部任意深度的文件夹和文件会在全部媒体成功、快照未变化后整组移入本地回收区。
- `来源/合集/阿甘正传/...`：第一层 `合集` 才是来源单元，不自动猜内层电影目录；合集内任一媒体未完成时整个合集保留。
- 没有任何媒体任务可证明归属的空目录、纯文档目录或后来新增目录，不因为选择“清空来源”就自动删除；预览和任务结果必须把这些剩余项明确列出。
- 新增文件、未完成下载标记、符号链接、任务失败/待确认、挂载失效、回收不可用或容量不足都会阻止处理并保留原内容。

配置页以普通人语言说明以上边界，并提供按需、只读、限量的“预览来源处理范围”；云盘目录不在页面加载时自动深扫。

“入库后清空来源”下增加处置方式从属项：

- `移入本地回收区`：默认，适合本地下载和希望可恢复的用户；跨盘时会产生一次额外复制和校验。
- `永久删除来源`：作为进阶高风险选项，适合已确认目标入库且不希望把网盘内容再复制到本地回收的场景；按 ADR-0019 使用独立不可恢复确认、任务删除隔离区、持久化账本和全链路故障测试。

永久删除即使获批也只能发生在目标文件包完整提交、所有同组任务成功、来源快照完全一致、挂载身份未变化且无符号链接/特殊文件之后；不得在回收失败时自动降级为删除。用户在重复冲突中选择“保留片库现有文件”时，默认同时保留来源，不自动触发永久删除。

### 先识别、再判重、后搬运合同

旧流程“来源 → 完整复制到中心中转 → 刮削 → 分类 → 查重 → 入库”会让最终选择保留片库现有文件的网盘任务也先完整下载一次。现行流程调整为：

1. 只读检查来源挂载、文件 stat 和来源单元边界，不复制大文件。
2. 从发布名/父目录解析身份并执行 TMDB 刮削；不确定时先人工选对电影/剧集。
3. 对源文件执行轻量媒体探测，补分辨率等文件维度；探测不可用时显示未知并按规则进入确认，不因缺值猜测。
4. 根据已确认身份和维度选择目标片库、规则目录与最终文件名。
5. 只在该目标片库内执行两层冲突检查：精确目标路径；同 Provider ID 或标题别名+年份（剧集再加季/集）的同作品候选。
6. 有冲突时在任何大文件复制前让用户选择“保留片库文件 / 两个都保留 / 替换片库文件”。分辨率、媒体信息和大小只用于比较展示，不再自动决定覆盖。
7. 只有“无冲突”“两个都保留”或“明确替换”才检查目标空间，并执行来源 → 目标侧任务私有暂存的一次校验复制。
8. 长复制结束后重新验证来源快照和冲突快照；目标新出现、旧文件变化或挂载变化时重新进入确认。
9. 目标侧任务私有暂存校验完成后执行 no-replace 文件包发布；替换时旧片库文件仍先进入本地回收区。
10. 目标文件包提交成功后，最后按来源处置方式处理来源。

冲突预检不得为了展示结果就对网盘源文件或现有片库文件计算全量 SHA-256。首屏先用 Provider 身份、标题/年份、路径、大小和轻量媒体探测；只有用户选择替换或真正开始搬运时才进行完整指纹与并发复核。

为避免每个任务递归扫描整块磁盘，目标片库建立只读增量索引：优先使用本产品历史任务中的 Provider ID/最终路径，再以片库文件名解析补足外部已有影片；候选冲突出现后才按需 ffprobe。索引异常或过期只能增加人工确认，不能漏过精确目标路径冲突或自动覆盖。

## 状态与交互合同

| 用户阶段 | 任务状态/动作 | 列表与详情文案 | 允许操作 |
|---|---|---|---|
| 尚未选对资料 | AWAIT_REVIEW | 需要人工确认作品 | 手动搜索、重试识别 |
| 已应用候选 | AWAIT_REVIEW | 资料已更新，等待确认入库 | 查看预览、重新选择、确认 |

| 后台运行 | RUNNING | 当前阶段 + 当前文件 + 字节进度 | 只读查看 |
| 文件包提交、来源处理中 | RUNNING/source_cleanup | 影片和字幕已入库，正在处理来源 | 只读查看 |
| 全部完成 | SUCCESS/DONE | 影片、字幕、来源均完成 | 查看、打开路径 |
| 片库完成但来源异常 | SUCCESS/DONE + warning | 片库已安全写入，来源处理未完成 | 重试来源处理 |
| 提交前失败 | FAILED/recoverable | 入库未完成，片库未出现新影片 | 重试/检查配置 |

手动候选应用不进入运行进度；确认入库后不得继续编辑资料，避免路径和在途文件分叉。

### 单元与合同

- 发布名：双标题、年份/季集、版本、语言字幕、片源/编码、发布组、未知标签、父目录证据和逐步 trace。
- 反例：片名本身含 2012/F1/4K/HDR/WEB/Korean/Extended 等词时不得被误删；新增未知字幕组不能破坏标题。
- 匹配：中文/英文/父目录多查询、电影/剧集类型、年份疑点、候选分差、Top-20 和唯一候选解析器。

- 字幕：相似视频名不误配、多语言、同语言多条、未知语言、缺失/变化、模板命名。

- 冲突索引：Provider ID、标题别名+年份、季集、精确路径、跨规则旧路径、索引过期和外部新增文件。

### 安全与故障注入

- 目标视频/字幕竞争、用户确认保留/替换、替换旧文件进入本地回收。
- 字幕暂存失败、目标验证失败、发布第 1/第 N 个字幕失败、视频发布失败。
- 字幕已发布但视频未发布时崩溃；视频发布后、提交状态落库前后崩溃。
- 来源/目标挂载失效，源文件变化，磁盘空间不足，数据库写入失败。
- 证明回滚只触及任务自建且指纹匹配文件，既有片库文件零删除。
- 证明来源只在整个文件包提交后处理，片库提交后重启不重复写入。
- 长复制期间来源变化、目标新出现、现有冲突文件变化、片库索引过期时必须重新确认，不能沿用旧决定。
- 若永久删除来源获批：删除前各门禁逐项故障注入；目标未提交、部分字幕失败、快照变化、挂载变化、特殊文件、权限失败均证明来源零删除。

## 验收标准

- 不少于 800 条发布名语料全部有期望解析标签；结构字段解析准确率不低于 98%，自动通过精确率不低于 99.5%，对抗集错误自动通过为 0。
- 用户示例 `小姐.加长版.中英特效字幕.The.Handmaiden.2016.EXTENDED.KOREAN.BD1080P.X264` 能得到中/英文标题、2016、加长版、字幕/语言、1080p、编码等结构字段，并把正确作品排在候选首位或明确转人工确认。
- 用户选择候选后 2.5 秒内列表和详情展示同一份新资料，且没有文件移动。
- 搜索可明确选择类型和资料语言，默认返回不超过 20 条候选。

## 风险与拒绝条件

- **语料不可穷举**：用类别配额、结构解析、反例和本地确认增量覆盖；若只能靠不断加删除词，不进入自动通过。
- **开源依赖与打包**：GuessIt 仅在 LGPL 合规、NOTICE、离线纯 Python wheel 和 fnOS 包体/启动验收通过后引入；否则保留对照测试而不入生产依赖。
- **标题误删**：未知标签默认保留为候选信息；若标题含技术词的反例出现错误自动通过，阻断交付。
- **状态复杂度**：以文件包提交点和幂等 CAS 收敛；若恢复状态无法被测试穷举，不交付。
- **多文件非原子**：视频最后发布并限制回滚；若会误删既有文件，立即拒绝。
- **大文件性能**：不因字幕失败重复制视频；进度落库继续节流。
- **自动刷新干扰**：编辑态暂停刷新，运行态仅局部更新；若弹窗跳动或输入丢失，不交付。
- **资料漂移**：确认时固定候选快照和配置版本；若目标会在后台静默改变，阻断并让用户复核。
- **fnOS 云盘差异**：所有挂载和权限失败必须可恢复、可解释；不能以本地模拟替代真机验收结论。
- **来源边界误解**：不猜内层电影目录；若无法向用户明确展示第一层来源单元范围，不允许开启自动清空来源。
- **永久删除不可恢复**：ADR-0019 已批准来源专用窄例外；若删除隔离区、账本恢复、危险确认或故障矩阵任一项未通过，只交付本地回收模式。
- **片库索引陈旧**：精确目标路径在复制前和发布前强制实时复核；索引只能发现更多候选，不能成为绕过 no-replace 的依据。
- **路径模板歧义**：必须展示当前片库根后的完整示例；若 UI、保存校验和运行落点不一致，不交付。
