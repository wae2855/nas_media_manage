# Frontend Cinema Redesign Plan

一句话：基于已确认的黑金影院风格原型，重做前端展示层和页面结构；先让用户逐页验收视觉与信息架构，再接功能和补 UI/E2E。当前展示层约完成 80%，功能接线主线已切换到 [2026-06-06-frontend-function-migration-plan.md](/Users/wangwei/Documents/code/nas_media_manage/docs/plans/2026-06-06-frontend-function-migration-plan.md)。

## Background

当前前端仍是旧单页管理台形态，灰蓝色后台观感明显，且 `index.html`、`config.js`、`tasks.js` 和多份 CSS 超过 500 行。用户已确认新版方向：

- 黑色 + 金色影院主题。
- 写实海报墙氛围。
- 移动端优先。
- 首页大卡片入口。
- 展示先确认，功能后统一接线。

参考原型：

- `docs/prototypes/cinema-dashboard-demo.html`
- `docs/prototypes/cinema-task-list-demo.html`
- `docs/prototypes/cinema-recycle-demo.html`
- `docs/prototypes/cinema-config-demo.html`
- `docs/prototypes/cinema-config-directory-demo.html`

## Goals

- 真实前端采用黑金影院主题，整体替换旧灰蓝管理台观感。
- 页面结构从旧 `overview/config/tasks/recycle` 重组为移动优先的页面入口。
- 首页只保留最关键的状态、快速动作、三大入口和最近活动。
- 系统配置页按初级用户视角组织：先 01-04 主步骤，再展开 05-11 更多配置。
- 先完成展示和导航，允许用户逐页对照旧界面验收内容取舍。
- 功能接线和深层 UI/E2E 在展示结构确认后统一完成。

- 前端展示层约完成 80%。

- 系统配置的基础流程轨、目录配置、入库规则、高级配置主入口和大部分高级配置展示页已完成视觉与交互基线。

- 当前剩余主线不再是“继续探索视觉方向”，而是“保持视觉基线稳定，分批接入真实保存、测试、加载和任务操作能力”。

## Frozen UI Rules

以下规则视为当前展示层冻结基线；后续功能接线不得随意改动：

- 黑金影院主题、移动端优先、大卡片入口、海报式底图语言保持不变。
- 底部导航固定为：首页、任务、回收、配置。
- 系统配置基础流程固定为 7 步胶片轨：开始、源目录、中转目录、回收目录、刮削配置、AI配置、入库规则。
- 胶片轨卡片只展示主标题，不承载状态文案；方向图标统一为厚圆角金色右向 chevron。
- 7 个流程卡支持独立底图资源；有图时以暗化海报方式填充，无图时回退默认黑金底色。
- 基础配置主区域统一采用“标题 + 右侧保存按钮 + 一列一项为主”的阅读模式。
- 复杂低频内容优先折叠或按阶段收起，不在首屏堆满。
- 高级配置继续承接复杂策略页；基础配置只保留新手完成最小闭环所需的核心配置。
- 顶部品牌栏保持吸顶，底部导航保持固定；任务页筛选条与系统配置流程胶片轨作为页内导航层吸顶。
- 高级配置主页与各高级配置子页采用“页头吸顶 + 滚动后收紧”的模式：保留标题、路径与主操作作为导航锚点，但滚动后自动压缩高度，避免遮挡正文。
- 图标体系按“导航级 / 功能级”拆分：导航级图标用于品牌、首页入口、底部导航；功能级图标用于扫描、暂停、重试、状态、测试等操作。
- 任务页、回收站、系统配置与高级配置页头统一使用可替换的电影感 Hero 气氛层：先通过黑金遮罩、光影和纹理建立氛围，后续只替换海报资源，不再重做结构。

## Non-Goals

- 不在第一阶段一次接完所有 API 功能。
- 不在第一阶段重写后端 API。
- 不保留旧后台式密集表格布局作为主体验。
- 不继续向旧大文件追加复杂逻辑；新前端应按页面、状态和样式拆分。

## Design Decisions

已确认：

- 首页顶部保留写实海报墙/私人影院氛围。
- 首页顶部按钮为：立即扫描、暂停队列、重试失败。
- 首页状态卡为：待处理、需要确认、今日入库，点击后进入对应筛选状态的任务列表。
- 首页 3 个状态卡始终保持一排展示，宽度缩小时同步收缩，不改为纵向堆叠；标题与内容居中。
- 首页入口卡为：任务列表、回收站、系统配置。
- 首页保留最近活动。
- 首页不展示系统健康，移动到系统页。
- 移动端底部导航收敛为 4 项：首页、任务、回收、配置。
- 系统配置首页改为 4 个横向小卡片：源目录、中转目录、回收目录、入库规则；4 个卡片始终保持同一行，按四等分宽度随浏览器宽度联动缩放，卡片之间保持紧凑小间距。
- 系统配置基础配置区进一步升级为“流程胶片轨”，顶部不再使用 4 张大卡片，而是使用可横向滑动的 7 步流程轨：开始、源目录、中转目录、回收目录、刮削配置、AI配置、入库规则。
- 流程胶片轨视觉必须像一条连续电影胶片：上下连续齿孔、内部按画格分隔，当前步骤用金色投影高光突出；不要做成几张独立卡片各自打孔。
- 基础配置 7 个流程轨卡片只展示主标题；有效/无效等状态不在卡片内展示，避免流程入口变成状态面板。右侧统一使用厚圆角的金色向右 chevron 方向图标表达逐步配置，并与黑金影院主题协调。
- 基础配置 7 个流程轨卡片允许使用独立海报底图资源填充画幅区；图片统一加深色遮罩后平铺展示，缺图时自动回退默认黑金底色，不允许因为资源缺失破坏布局。
- 首页第一批核心图标已统一为 SVG 体系：品牌、主操作按钮、状态卡、入口卡、底部导航不再使用字符图标。
- 第二批图标统一已完成：高级配置入口卡与模拟测试说明卡尾部不再使用“配置 / 说明”文字尾标，统一改为金色右向进入图标；规则页折叠、提示词折叠、置信度折叠与最近活动状态图标全部切换到同一套 SVG 语言。
- 高级配置相关页面已经启用“紧凑吸顶页头”交互，用于在长配置页里持续提示用户当前所处层级，同时减少返回和保存按钮的寻找成本。
- 【开始】作为默认步骤，主内容区优先展示配置顺序、权限前提和完成标准，帮助初级用户先建立心智模型，再进入具体表单；当前基础流程顺序固定为“目录 -> 刮削配置 -> AI配置 -> 入库规则收口”。
- 【刮削配置】和【AI配置】在基础配置流程中作为正式步骤出现，但主内容区先承接阶段说明和跳转入口，详细字段仍进入对应的高级配置子页完成。
- 【刮削配置】和【AI配置】后续收口为基础流程内可直接编辑的表单区：刮削配置承接旧“元数据源配置”的 Provider 卡片与测试入口，AI配置承接旧“LLM配置”的模型、端点、超时、重试与 SSL 选项；两者主内容区右上角均保留保存按钮。
- 刮削配置中的 Provider 卡片需要支持“仅保留头部 / 收起内容”的轻折叠体验：关闭右上角开关时，保留 Provider 名称与开关，隐藏具体字段和测试操作。
- AI配置字段命名统一面向初级用户：模型名称改为“主要模型ID”，备选模型改为“备选模型ID”，快速模型改为“快速模型ID”；超时、重试、阈值各自独占一行，不再包在空的“调用参数”父卡片里。
- AI配置中的快速模型提示语统一为“留空则使用主要模型”，避免和备选模型心智混淆。
- 4 个基础配置卡片的副标题“有效 / 无效”最终由系统真实校验结果返回驱动，用于反映对应配置是否通过校验；不作为前端硬编码文案长期保留。
- 系统配置右上角按钮改为“高级配置”。
- 系统配置页提供“查看旧版配置”入口，便于逐项对照旧前端验收细节。
- 系统配置下部主区域与上方 4 个卡片联动，点击卡片切换对应内容控件。
- 源目录主区域去掉“旧字段承接”“旧页面对应”等说明性标签，优先展示真实控件。
- 源目录主区域底部增加“源目录智能清理”开关；开启后展开原“源目录自动清理”核心控件。
- “源目录自动清理”区域包含：清理模式、AI辅助判断、AI清理提示词、合并策略、指定删除后缀名、指定保护后缀名、黑名单模式、垃圾视频大小阈值、清理空目录、执行时间。
- “清理模式”和“AI辅助判断”各自独占一行；单选按钮放在文案左侧。
- “AI清理提示词”展开区位于“AI辅助判断”之下、“合并策略”之上。
- “AI清理提示词”按钮改为二次点击切换显示/收起输入框。
- “合并策略”选项文案保持原版完整表述。
- “合并策略”卡片按整排展示，不限制为窄列宽。
- “执行时间”字段更名为“定时执行”。
- “源目录智能清理”标题补充提示：不选择代表全部清空。
- “保存”按钮放到主区域“源目录”标题右侧。
- “源目录路径”独占一整行，行末提供“测试权限”按钮；补充源目录使用说明与 fnOS 共享盘授权提示，并标记为必填项。
- “递归扫描”和“最大扫描深度”合并为一个父卡片，并且整块独占一整行；仅在开启递归扫描时显示“最大扫描深度”控件。
- 中转目录点击后，主区域直接展示原版核心内容：“中转目录路径”独占一整行，行末提供“测试权限”按钮，并保留旧版路径说明和风险提示；路径字段标记为必填项。
- 回收目录点击后，主区域直接展示原版核心内容：“回收目录路径”独占一整行，行末提供“测试权限”按钮，并保留旧版路径说明和风险提示；“回收站文件保留天数”独占一整行；路径字段标记为必填项。
- 中转目录、回收目录主区域补充“保存”按钮，位置与源目录保持一致。
- 入库规则主区域去掉当前占位展示，改为真实结构：规则列表、模板变量说明、兜底入库目录，并在标题右侧提供“保存”按钮；规则列表标记为必填项。
- 入库规则列表保持“一条规则一行”的阅读模式；空状态下用列表内的 `+` 入口承接新增规则，保留“测试所有入库规则目录权限”动作和原版权限说明。
- 模板变量说明按“基础变量 / 剧集变量 / 画质变量 / AI 维度变量”分组展示；每组单独一行，可折叠，只读展示不提供编辑删除。
- “兜底入库目录”独占一整行，保留权限测试入口；注释更新为“不设置则匹配不到时按失败处理”。
- 高级配置页单独承接 7 个纵向卡片：入库名称规范、影视分类维度、AI刮削提示词、置信度计算、安全配置、Hermes通知、系统设置；卡片不显示数字编号。
- 点击“高级配置”后，在大标题下方增加轻量路径导航（如“系统配置 / 高级配置”），用于提示当前所处层级；进入高级配置子页后继续扩展为完整路径提示。
- “入库名称规范”页主区域承接旧版入库选项中的 4 个核心配置：电影文件名模板、电视剧文件名模板、字幕文件名模板、入库同名文件处理策略；每项独占一行，右上角提供保存按钮。
- “影视分类维度”页直接承接旧版维度控件内容，展示已启用维度、可添加维度及其启用/禁用/映射/恢复默认能力。
- “AI刮削提示词”页改为 3 个折叠区：LLM纯AI、LLM+TMDB、编写指南；前两个折叠区均保留“恢复默认”“预览完整提示词”按钮，预览通过弹窗展示完整结果。
- “置信度计算配置”页不复用旧版密集参数表作为主视图，改为移动端风险控制台：当前策略摘要、决策阈值滑杆、搜索匹配策略、AI 推理保护、维度来源信任、模拟测试、高级参数与咨询助手。
- 置信度页顶部用分段阈值条解释“自动入库 / 需要确认 / 需要审核 / 失败”的边界；自动入库、需确认、需审核三个阈值不再使用独立滑杆，改为在风险边界图上拖动手柄调整，并同步显示实时数字。
- 置信度页保留旧字段语义，滑杆和卡片直接承接 `pass_threshold`、`confirm_threshold`、`review_threshold`、`provider_match_threshold`、标题匹配 T 值、R 值和纯 AI 上限等配置键，避免后续 API 接线时引入额外转换。
- 置信度页的“Provider 最低匹配”仍保留滑杆与实时数字，因为它不是风险边界图的一段，而是 Provider 搜索回退门槛。
- 置信度页的“维度来源信任”不是只读摘要：每个维度内部默认折叠，展开后支持 Provider、AI、文件名三类来源的可信开关，并支持调整三者优先级顺序。
- 置信度页的“搜索匹配策略”默认折叠，避免首屏被低频参数占满。
- “配置模拟测试”不放在置信度子页，改放在“高级配置”主页下方；它是跨 AI 提示词、置信度、入库规则的整体配置测试入口。基础配置页后续如需要，只放轻入口跳转到高级配置测试区。
- “配置模拟测试”已进一步升级为高级配置内的独立页面入口，不再停留在高级配置主页本身；主页只保留“模拟测试”按钮，避免打断导航页节奏。
- “模拟测试”入口从高级配置主页右上角上移到系统配置主页右上角，与“高级配置”并列，表达“完成基础配置后可直接试跑”的心智。
- 配置模拟测试页中的说明块采用一行一个的纵向结构，而不是三列卡片；后续真实模拟返回结果需要明确解释 3 类信息：AI 提示词如何影响识别、当前置信度边界为何命中该队列、入库规则命中了哪一条或为何未命中。
- 置信度页的公式说明和咨询助手进入底部高级折叠区，服务高级用户和 AI 调参，不压在普通用户首屏。
- 置信度页咨询助手输入框必须整行展示，默认至少 10 行高度；公式说明字体层级应低于卡片标题，避免视觉喧宾夺主。
- “安全配置”“Hermes通知”“系统设置”页复用原展示方案，优先承接旧版真实字段与分组，不保留摘要说明卡片。
- “系统设置”页在日志目录下补充“资源目录”路径项，带测试权限按钮；用于承接图片、声音等应用资源文件目录，后续功能接线时需要补齐真实配置键与保存逻辑。
- 高级配置相关页面片段从 `index.html` 拆出到独立 partial，主入口只保留挂载点与页面骨架，避免入口文件继续超出 500 行。
- 置信度页样式与逻辑拆分为 `cinema-confidence.css` 和 `cinema-confidence.js`，避免继续膨胀通用高级配置文件和前端壳层脚本。

当前已收口范围：系统配置中的基础配置 4 个板块（源目录、中转目录、回收目录、入库规则）展示结构与文案基线已确认，后续仅按用户新验收意见局部调整。

补充收口范围：

- 胶片流程轨视觉方向、方向图标、底图填充机制已确认。
- 基础配置中的 `刮削配置 / AI配置` 已确认进入流程内，不再退回单独说明页模式。
- 前端当前允许存在“未认证 / 未接线”的展示态，但必须明确提示，不能停留在误导性的加载中状态。

## Target Pages

| Advanced Config | 7 个纵向高级配置卡入口 | Static skeleton, API later |

## File Strategy

建议新结构：

```text
media_importer/webui/
├── index.html
├── css/
│   ├── tokens.css
│   ├── layout.css
│   ├── components.css
│   └── pages/
├── js/
│   ├── app.js
│   ├── shared/
│   └── pages/
└── assets/
```

原则：

- 单文件建议不超过 500 行。
- 共享样式只放 tokens、布局、基础组件。
- 页面逻辑放 `js/pages/`，不要集中到一个大 `config.js`。
- API 调用集中到 `js/shared/api/`。

## Testing Plan

每阶段至少运行：

- `git diff --check`
- `python3 -m pytest tests/test_architecture_guards.py`
- Playwright 页面截图检查：Dashboard / System Config / 当前验收页

功能接线后运行：

- `python3 -m pytest tests/`
- 新增/更新 Playwright UI tests。
- 桌面与移动端截图检查。

展示层阶段补充规则：

- 若接口因 API Key 未认证返回 401，页面必须展示明确提示，不得表现成永久 loading。
- 新增接线优先先做读操作验证，再做写操作验证，最后再接危险或副作用动作。

## Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| 展示重做时遗漏旧功能 | 高 | 逐页对照旧界面验收，功能未确认前保留 fallback |
| 配置页内容复杂导致再次膨胀 | 高 | 入口页 + 独立子页，不在一个页面塞完 |
| 移动端卡片过大或溢出 | 中 | 每阶段做移动端截图和 Playwright 检查 |
| 先做展示导致功能暂不可用 | 中 | 明确 Phase 2 为展示壳，Phase 4 统一接线 |
| 旧测试不适配新 UI | 中 | 先保留 API/后端测试，UI 测试在新版稳定后重写 |
