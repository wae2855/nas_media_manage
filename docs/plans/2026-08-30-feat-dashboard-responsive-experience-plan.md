# 首页语义与全站双端体验优化计划

把已经确认的首页状态、最近入库、活动列表方案，与任务、回收站、配置和弹窗的移动端整改合并实施；保留桌面高信息密度和影院胶卷风格。

## Problem Statement

首页把待人工确认错误表达成了视频处理进度，“今日入库”和最近活动也不是标题所描述的业务口径。任务工作台在 390px 以下会裁掉判断结果和操作，回收站在 768px 就会超宽；固定底部导航和长弹窗还会让手机上的主操作难以到达。

这会造成两类直接问题：用户误判后台仍在处理，以及手机用户无法完成确认、恢复等核心流程。

## Target End State

- 首页只在真实运行任务存在时展示真实进度；待确认、失败和暂停使用独立状态提示。
- 今日入库、最近活动和最近影片都依据任务业务时间与业务状态，而不是累计数、原始日志或图片文件时间。
- 最近影片展示最近 12 部成功入库作品并去重；缩略图缓存同时受 500 张和 200 MB 软上限约束。
- 最近活动最多 5 条，使用普通用户能看懂的业务事件。
- 任务和回收站在 768、390、360、320px 下无裁切，主操作可达。
- 手机端长弹窗具备固定头部、固定操作区和内部滚动；底部导航不再遮挡页面主操作。
- 配置胶卷轨道保持现有形式，只增强滑动提示、当前位置与触控可用性。
- 1280px 桌面布局不因移动端调整而退化。

## Scope

- 首页状态与操作按钮语义、指标、最近业务活动和影片轮播。
- 支撑上述语义所需的任务汇总/最近任务 API 查询与缩略图缓存治理。
- 任务工作台、回收站、通用弹窗、配置完成页、模拟器、胶卷轨道的响应式样式和必要的轻量结构调整。
- 相关 API、静态结构、单元、集成和 Playwright 响应式测试。
- 需求看板、API/前端/测试事实文档同步。

## Non-Goals

- 不改变任务状态机、文件入库、恢复或永久清理业务规则。
- 不改变桌面端信息架构，不把胶卷轨道改成普通标签页或纵向菜单。
- 不新增可由用户配置的缓存参数；本轮使用产品预置安全边界。
- 不把 320px 做成与 390px 完全相同的装饰效果，只保证安全可用。
- 不接入新的图片服务、日志系统或前端框架。

## Proposed Solution

### 1. 建立首页业务摘要

在任务 feature/repository 已有查询能力上增加只读首页摘要：按 `status + stage` 区分 queued、running、await_review、failed、today_success；按 `completed_at` 返回最近成功入库任务和最多 5 条业务事件。队列暂停状态继续来自现有 queue service。

首页前端根据摘要渲染互斥状态：

- `running > 0`：显示真实处理进度，附带排队、待确认、失败数量。
- `running = 0 && await_review > 0`：黄色行动提示和“去处理”，无进度条。
- `failed > 0`：失败提示和重试入口；没有失败项时禁用重试。
- `paused`：明确“后台整理已暂停”；没有真实运行任务时禁用暂停。
- 其余：服务正常、等待新影片。

业务活动从最近任务状态推导，不展示内部步骤名和技术日志。首批事件覆盖：入库完成、等待确认、处理失败、已跳过、已取消、排队/处理中；同一任务只显示当前最有意义的一条事件。

### 2. 最近影片与缓存治理

最近影片按 `completed_at DESC` 查询 `SUCCESS + DONE + import_success`，使用任务保存的 `thumbnail_path`，以 `provider_type + provider_id` 为优先去重键，无 provider 时回退到入库路径或规范化片名年份。API 只返回实际存在且位于允许 Thumbnail 目录中的图片。

缩略图治理在图片写入成功后和列表读取时采用轻量兜底清理：按最近成功任务、运行中和待确认任务保护仍被引用的图片；对其余可再生成缓存按时间从旧到新删除，直到数量不超过 500 且总容量不超过 200 MB。任何越界、无法确认归属或清理失败都只记录告警，不影响入库主流程。

### 3. 双密度响应式布局

- 桌面继续使用现有三列任务卡和横向回收行。
- 任务卡在手机上改为“海报+标题状态”首层、原因/关键判断第二层、全宽操作第三层；维度默认展示前 3 个，其余通过详情查看。
- 回收站在 768px 及以下改为纵向卡片，原路径允许两行省略并可展开；恢复为主操作，永久清理仍保留明确危险样式和确认流程。
- 筛选轨道可横滑、边缘渐隐、当前项自动进入可视区；批量操作固定在底部导航上方。

### 4. 通用移动交互

- 手机弹窗使用 `100dvh` 内部布局：头部和操作区固定，正文独立滚动，关闭和操作热区不小于约 44px。
- 页面和固定操作区统一加入底部导航及 `safe-area-inset-bottom` 安全距离；弹窗打开时底部导航不参与交互。
- 完成页标题操作在窄屏独占一行；模拟器主操作位于底部导航上方。
- 胶卷轨道保留视觉形式，补充渐隐、滑动提示和当前步骤计数。
- 轮播间隔调整为约 4.5 秒，支持触摸滑动，并在悬停、键盘聚焦、页面不可见和 `prefers-reduced-motion` 时暂停。

## Decision Rationale

- 使用任务事实而不是继续加工原始日志，因为首页要表达用户流程，不应依赖易变的技术文案。
- 最近影片由任务关联图片，避免文件修改时间与真实入库顺序不一致。
- 缓存数量和容量同时生效，能同时覆盖大量小图和少量异常大图。
- 保留同一份语义 HTML，通过断点调整信息层级；避免维护两套业务行为，同时允许桌面和手机采用不同密度。
- 320px 采用安全可用边界，保护核心操作而不牺牲 360—430px 的主题表现。

## Subjective Contract

- **目标感受**：桌面仍像片库控制台，手机像为单手确认和恢复专门整理过的工作台。
- **反目标**：不把手机页面缩成迷你桌面；不靠 `overflow-x: hidden` 掩盖内容；不把影院主题改成通用后台模板。
- **正向参考**：现有配置开始页、胶卷阶段卡和金色低饱和层级。
- **反向参考**：整行表格硬塞手机、长弹窗按钮只能滚到底部找到、多个同权重危险操作并排。
- **语气规则**：状态说结果和下一步，不暴露 PASS、stage、原始日志步骤等内部词汇。

## Test Plan

### 后端/API

- 首页摘要在跨天、空数据、仅待确认、运行+待确认、失败、跳过和暂停状态下返回正确口径。
- 最近影片严格按完成时间排序、作品去重、缺图跳过、路径越界拒绝。
- 缓存同时满足 `<=500` 和 `<=200 MB`；运行/待确认/当前轮播图片受保护；删除失败不影响请求和入库。

### 前端静态与行为

- 首页没有把 PENDING 总数作为进度；活动限制 5；轮播间隔和暂停条件可验证。
- 没有运行/失败任务时相应按钮禁用；点击待确认提示进入正确筛选。
- 任务维度折叠、回收操作、弹窗头尾和胶卷提示保留可访问名称。

### Playwright 真实页面

- 使用模拟任务、长路径、7+ 维度、回收冲突、LLM 长表单数据。
- 1280、768、390、360、320px 分别检查 `scrollWidth <= clientWidth`，并检查元素矩形没有被视口或底部导航裁切。
- 手机端完成：打开待确认任务→查看原因→确认入口可见；打开回收项→恢复入口可见；打开任务/规则/LLM 弹窗→关闭与底部操作可达。
- 轮播支持点击、触摸滑动、焦点暂停和减少动态效果；浏览器控制台无新增错误。

## Acceptance Criteria

- 只有 `PENDING/RUNNING` 任务触发进度展示，进度来自真实任务 percentage；仅待确认时无进度条。
- 今日入库只统计本地当天成功完成的入库任务；最近活动最多 5 条业务事件。
- 轮播最多 12 部最近成功入库作品、去重、约 4.5 秒切换，并满足暂停/减少动态效果要求。
- 缩略图可再生成缓存同时满足 500 张和 200 MB 软上限，受保护图片不被清理。
- 1280、768、390、360、320px 无核心内容横向裁切；任务确认、回收恢复和主操作不被底部导航遮挡。
- 手机长弹窗关闭、取消和保存/确认始终可达，主要触控热区约 44px。
- 胶卷导航形式和桌面端结构保持不变。
- 所有新增与既有回归测试通过；本地技术验收和用户验收分别报告。

## Constraints and Boundaries

- 文件清理只能处理已确认属于 Thumbnail 缓存目录的可再生成图片；不得触碰源文件、入库文件、回收文件或二维码资产。
- 图片服务继续防路径穿越；新增 API 不返回服务器绝对目录。
- 时间口径明确使用服务器本地时区的自然日，并在测试中冻结边界。
- 现有 dirty worktree 中的配置开始页、二维码和时间线改动属于同一用户工作流，必须保留；`.opencode/` 不纳入本次修改。
- 本轮不自动提交、推送或部署，等待用户另行授权。

## Risk Analysis

- **误删图片**：只清理真实 Thumbnail 根目录内、非保护集合、允许扩展名的普通文件；使用 realpath containment；异常 fail-safe。
- **时间统计跨日错误**：统一由后端按本地日界生成范围，测试 00:00 边界，不让浏览器自行猜测时区。
- **API 扫描任务过多**：使用有界 SQL 查询和索引字段，不把全表任务返回前端。
- **移动样式污染桌面**：证明切片先验收，移动规则全部放在明确断点内，随后运行多视口回归。
- **底部固定操作与键盘冲突**：使用 `dvh`、safe area 和内部滚动；表单弹窗以真实移动视口验证。
- **当前未提交改动冲突**：编辑前逐文件查看差异，只追加或精确修改任务相关区域，不回滚现有内容。

## Rollout and Rejection Rules

- 任务与回收站证明切片在五个视口通过后，才推广弹窗和全站触控规则。
- 后端摘要测试通过后，首页才切换到新 API；失败时保留清晰的不可读取状态，不回退伪进度。
- 出现任何源/入库/回收文件被缓存治理触达、桌面端核心信息减少、320px 主操作不可达、或进度仍混入待确认数量，均视为拒绝交付。
