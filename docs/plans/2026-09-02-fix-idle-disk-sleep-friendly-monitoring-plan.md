# 空闲状态硬盘休眠友好的后台监控

- **Requirement**: [REQ-20260902-013607](../tracking/requirements-board.md)
- **Status**: in-progress

在保留来源目录定时发现能力的前提下，停止空闲 watcher、状态查询和首页刷新对全部目标片库的周期性元数据访问及写入探针。

## Problem Statement

旧 watcher 每轮先执行全量 `inspect_storage_readiness`，因此即使没有任务，也会对来源、回收、日志、资源和全部片库执行挂载、权限、容量及写入探针；回收目录还会随每轮扫描递归清理。首页每 15 秒刷新时重复解析片库真实路径并扫描海报缓存。对启用硬盘休眠的 NAS，这些访问会周期性唤醒多个磁盘。

## Target End State

- 空闲 watcher 每轮只读取来源目录及来源挂载身份。
- 发现稳定新文件后才验证处理支持目录；分类确定目标后只验证本任务选中的片库。
- 门禁失败时不把候选记为已处理，目录恢复后可自动重试。
- 回收站过期清理最多每日一次，不随来源轮询频率运行。
- 首页无业务变化时，15 秒摘要刷新只读取数据库和内存缓存，不重复访问目标片库或遍历海报目录。
- 用户点击“配置检查”、变更目录、服务启动及真正文件操作前仍保留必要的完整安全验证。

## Scope and Non-Goals

### Scope

- watcher 的来源轻量门禁、候选派发和回收维护节流。
- storage readiness 的按角色/按选中片库检查能力。
- 入库分类后、查重前的单目标片库门禁。
- watcher 状态响应和首页缩略图边界/缓存的无变化快路径。
- 对应测试、监控/配置/任务事实文档及需求追踪。

### Non-Goals

- 不新增“休眠模式”配置项；正确的默认行为即应休眠友好。
- 不改变来源扫描周期和用户已保存的 30～600 秒选择。
- 不改变片库冲突、覆盖确认和回收安全合同。
- 不实现片库全局索引，也不改变刮削、维度或任务状态机。

## Proposed Solution

1. 将 readiness 拆成明确作用域：来源扫描、处理支持目录、完整配置、选中目标片库。完整检查合同保持不变。
2. watcher 每轮只执行来源扫描门禁。稳定候选出现后执行支持目录门禁；门禁或回调失败时保留候选观察状态并在下一轮重试。
3. 分类结果产生 `import_path` 后，以配置中的规范化片库根做无 I/O 归属判断，再仅对该根执行挂载、授权、写入探针和容量检查，之后才进入目标查重。
4. 回收维护使用单调时钟节流到 24 小时，首次启动不立即遍历；显式回收页面仍可按用户请求读取。
5. watcher 正常运行时，状态 API 使用 watcher 最近一次运行事实，不再为展示状态调用全量 readiness；无法启动的阻断状态仍允许显式诊断。
6. 首页缩略图目录按配置路径缓存；最近影片文件验证按数据库快照缓存；缓存裁剪最多每日一次。片库保护边界使用配置保存时已规范化的根/身份快照，不在每次摘要请求中重新 `realpath` 片库。

## Decision Rationale

- 不采用“把轮询周期拉长”：只能降低概率，不能解决所有片库被同时唤醒的问题。
- 不采用用户可选休眠模式：会增加配置复杂度，并允许默认行为继续不合理。
- 不取消运行前安全门禁：目录离线、挂载替换、空间不足仍必须失败关闭；仅把检查推迟到真正需要对应磁盘的阶段。
- 不缓存最终文件操作的安全判断：真正查重、创建目录、写入和替换前仍使用实时文件系统事实。

## Constraints and Boundaries

- 目标片库仍只允许读取、创建/更新和用户确认后的安全替换；通用删除保持禁止。
- 来源离线时保留 `_known_files`，不得把离线误判为空目录。
- 候选稳定性窗口、广告/小视频过滤和任务去重语义不变。
- 缩略图缓存治理必须继续拒绝符号链接根及与片库重叠的目录，优化不能削弱该安全边界。
- fnOS 关闭前端后 watcher 继续运行，但空闲时只触达来源盘。

## Assumptions

| Assumption | Status | Evidence |
|---|---|---|
| 配置保存后的 `library_roots[].path` 已是真实规范路径 | Verified | `canonicalize_library_config` 保存时执行 `realpath(abspath)` |
| pipeline 可在稳定候选出现后再检查支持目录 | Verified | `run_all` 当前本就在任务扫描前执行完整 readiness |
| 分类阶段能从 `import_path` 唯一确定选中片库 | Verified | 规则/fallback 必须显式绑定 root ID，片库根互斥 |
| 首页数据库快照不变时最近影片结果可复用 | Verified | 最近影片仅由任务快照和缩略图路径生成 |
| 每日一次回收维护满足当前保留期语义 | Verified | 保留期以整天计算，当前每轮执行没有分钟级业务要求 |

## Risk Analysis

| Risk | Mitigation |
|---|---|
| 非目标支持目录在空闲期间离线，状态暂未立即更新 | 稳定候选出现后、任何任务创建/复制前执行实时支持目录门禁；配置检查仍可显式全检 |
| 门禁失败导致新文件永久漏处理 | 只有门禁与回调成功后才写入 `_known_files`，专项测试验证恢复后重试 |
| 单目标归属判断错误触达错误磁盘 | 使用互斥、规范化片库根做词法 containment；无法唯一归属直接阻断，不回退默认片库 |
| 首页缓存隐藏刚完成影片 | 数据库快照键包含任务/海报关键字段，变化立即失效 |
| 缩略图边界缓存造成安全回退 | 仅缓存配置保存时规范化的片库根；缩略图根自身每次危险操作仍做 `lstat`/realpath 检查 |

- [x] 1. 注册需求与一页方案，冻结四阶段磁盘访问矩阵。
- [x] 2. 为 storage readiness 增加来源、支持目录和单目标片库作用域，保持完整检查兼容。
- [x] 3. 重构 watcher：空闲仅查来源、候选出现后查支持目录、派发失败可重试、回收维护每日节流。
- [x] 4. 在分类后/查重前增加单目标片库实时门禁，并覆盖确认与重新整理续跑路径。
- [x] 5. 消除 watcher 正常状态查询的全量 I/O，保留阻断诊断中文原因。
- [x] 6. 为首页缩略图目录、最近影片和裁剪增加配置/快照缓存，消除无变化请求对片库和缓存目录的重复访问。
- [x] 7. 增加文件系统调用观测测试：空闲轮询不得检查片库/支持目录；候选只检查选中片库；失败恢复不漏任务；回收每日一次；首页无变化不重复触盘。
- [x] 8. 跑专项、非 UI、架构、lint、编译与文档检查；完成自评审并进入待 fnOS 验收。

## Test Plan

- `tests/test_stable_source_gate.py`：空闲访问边界、候选恢复重试、回收节流。
- `tests/test_location_health.py`：scoped readiness 只检查指定角色/目标。
- `tests/test_feature_import_flow.py` 或新专项：分类后只验证选中片库，失效片库阻断在查重/写入前。
- `tests/test_feature_configuration_application.py`：运行 watcher 状态查询不调用全量 readiness。
- `tests/test_dashboard_summary.py`：相同快照复用、变化失效、裁剪节流、片库保护不回退。
- `tests/test_target_library_conflict_safety.py`、`tests/test_recycle_safety.py`：目标保护和回收合同回归。
- `tests/test_architecture_guards.py`、编译、ruff、文档检查。

## Acceptance Criteria

1. watcher 开启且没有新文件时，连续多轮测试只出现来源目录的 `stat/walk`，目标片库、回收、日志和资源目录均无访问。
2. 新文件稳定后，任务只触达规则选中的片库；其他已配置片库没有 `stat`、容量或写入探针。
3. 支持目录或选中片库离线时任务不越过门禁，目录恢复后同一来源文件自动继续，不需改名或重新放入。
4. `.write_test_*` 不再由空闲轮询或正常 watcher 状态查询写入片库。
5. 回收站在 24 小时窗口内最多遍历一次；来源扫描周期保持用户配置值。
6. 首页连续摘要请求且任务快照未变化时，不重复解析片库路径、不重复遍历海报目录；新入库影片仍在下一次刷新出现。
7. 配置检查仍对全部目录、规则和权限给出实时结果；目标片库安全、冲突确认和回收测试全部通过。
