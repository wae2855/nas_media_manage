# Provider 维度映射、内容分级与媒体候选过滤改造

- **Requirement**: [REQ-20260901-233114](../tracking/requirements-board.md)
- **ADR**: [ADR-0020](../decisions/0020-provider-capabilities-and-editable-dimension-mappings.md)
- **Status**: pending_acceptance（本地开发与打包完成，等待 fnOS 真机验收）

让明显广告视频在创建任务前被安全忽略，并把“Provider 原始结果 → 产品维度值”从代码硬编码改造成有合理预置、可人工编辑、可解释预览的统一能力。

## 问题陈述

本计划合并处理同一次 fnOS 真机验证暴露出的四个问题：

1. 扫描器只按视频扩展名建任务，0.3～0.6 MB、文件名带推广网址的广告视频也进入任务列表。
2. 源清理器虽有垃圾视频大小阈值，但发生在任务创建之后；已经成为任务的广告不会被清理器纠正。
3. `restricted_level` 把 TMDB 美国 `R` 代码硬编码成 `17+`，界面又把 `17+` 命名为“成人内容”，导致 TMDB `adult=false` 的《通天塔》被错误表达为成人内容，并可能命中错误片库规则。
4. 维度页残留未定义的 `trustHtml`，所有维度卡渲染失败；即使修复渲染，当前 API 也明确拒绝保存 `provider_mappings`，用户仍无法决定 Provider 原始值如何映射到自己的维度值。

这不是单纯修一张表。维度值会直接参与片库规则和最终路径，广告过滤又与来源单元整组处理相互约束；任何一侧只改前端或只改扫描器都会产生新的错误状态。

## 目标结果

- 文件夹中“25 GB 主视频 + 两个不足 1 MB 的推广视频”只创建一个影片任务；后台活动说明忽略了两个明显广告文件，任务列表不出现广告任务。
- 模糊小视频默认不被误删：没有高可信推广证据或同目录主视频对照时，系统宁可正常建任务，也不静默忽略真实短片。
- 扫描、来源单元任务覆盖判断和源清理使用同一份候选判定及同一份扫描快照；忽略广告不会让整组来源永远卡在“尚未创建任务”。
- 每个 Provider 来源维度都明确展示“刮削得到什么、现在映射成什么、未映射时怎么办”。用户可以编辑并保存，不依赖 Python 常量决定业务分类。
- 《通天塔》的 TMDB 证据展示为 `adult=false / US:R`；`R` 默认落到“限制观看”，不再等于“成人内容”。
- 香港本地分级优先于其他地区：`I → 0-6`、`IIA/IIB → 13-16`、`III → 17+`；香港三级片即使 TMDB `adult=false`，仍能进入“限制观看”，但不会被误标成成人电影。
- “年龄/观看分级”和“成人电影标记”分开表达，避免把年龄限制与成人电影混为同一概念。
- 配置主页面仍保持简洁：维度卡默认折叠，只显示值数量、Provider、映射数量、未匹配策略和最近示例；完整映射只在明确点击后打开。
- 桌面与 390/360/320 px 手机宽度均无横向滚动；编辑弹层不会因点击遮罩误关闭。

## 用户工作流

### 普通用户

1. 使用产品预置映射，不需要逐条配置。
2. 在“影视分类维度”看到摘要：`TMDB · 18 条映射 · 未匹配时待确认`。
3. 只有出现未映射值、旧规则待复核或用户主动展开时，才进入映射编辑。
4. 完成页“配置检查”检查：启用维度是否有可用映射、规则引用的维度值是否存在、Provider 是否启用、未匹配策略是否明确。

### 高级用户

1. 展开某个维度，先维护本产品的维度值。
2. 点击“编辑 Provider 映射”，在弹层中选择 Provider 和原始数据项。
3. 把 Provider 原始值逐项映射到已有维度值，设置优先级与未映配结果。
4. 用最近影片或内置示例预览：`通天塔 · TMDB / US / R → 限制观看`。
5. 保存后，新任务和仍在待确认、尚未开始文件操作的任务使用新映射；已成功入库的历史任务不自动移动。

## 范围与非目标

### 范围

- 明显广告/小伴生视频的任务创建前候选判定、配置迁移、扫描摘要和来源单元一致性。
- 修复维度页 `trustHtml` 渲染错误并增加 console-error 回归门禁。
- Provider 能力描述、版本化映射合同、通用映射执行器、验证、保存、恢复预置和解释证据；适配 TMDB 的 genres、地区、语言、发行分级、adult 和可用关键词字段。
- “观看分级”与“成人电影标记”语义拆分、旧限制级规则复核提示及配置检查。
- 维度摘要卡、Provider 映射编辑弹层、实际影片预览、桌面与移动端适配。
- 手动刮削应用候选、自动刮削和重新整理任务统一调用同一映射执行器。

### 非目标

- 不允许用户编写 Python、JavaScript、任意表达式或任意正则作为维度映射逻辑；也不承诺 TMDB 能提供完整可靠的裸露、暴力、血腥分项，数据不足时必须显示未知或进入人工确认。
- 不让 LLM 参与影片匹配或维度判断，继续遵守 ADR-0010。
- 不因映射修改自动移动、删除或覆盖已入库影片。
- 不把几十条映射直接平铺在胶卷主配置页，不新增第二套“高级设置首页”；不把扫描时“忽略建任务”等同于立即删除来源文件。
- 不在本计划中改变目标片库只新增、冲突需确认和本地回收安全边界。

## 核心方案

### 1. 共用媒体候选判定

新增 feature 级 `MediaCandidatePolicy`，由扫描器、来源单元协调器和源清理器共同调用。它只返回判定，不直接移动或删除文件：

| 判定 | 含义 | 是否建任务 |
|---|---|---|
| `ACCEPT` | 正常影片候选或证据不足 | 是 |
| `IGNORE_PROMOTION` | 高可信推广/网址广告视频 | 否 |
| `IGNORE_SMALL_COMPANION` | 同来源单元存在明确主视频，且该文件同时满足小体积和比例门禁 | 否 |

默认规则采用“强名称证据 OR 小文件双门禁”，而不是单一大小阈值：

- 强名称证据：网址结构、引流句式、扫码/访问站点等产品预置模式；模式来自可版本化数据配置，不在扫描函数中散落站点名称。
- 小文件双门禁：默认小于 50 MB；同来源单元至少有一个不小于 500 MB 的视频；小文件不超过最大视频的 2%。三个条件同时满足才忽略。
- `sample`、`trailer`、花絮等可能是用户真实想保留的内容，默认不因名称单独忽略；可由高级用户加入自定义模式。文件无法读取大小、来源单元不稳定、规则冲突或判定异常时统一 `ACCEPT`，失败方向是多一个待处理任务而不是漏掉影片。

判定结果、规则版本、原因和扫描时文件快照写入来源单元记录。后续整组来源处理读取这份已冻结结果，不按修改后的配置重新猜测。被忽略文件只有在用户选择的来源处理策略本来就允许处理、主影片完整提交且来源快照未变化时，才作为来源单元成员进入本地回收或受控永久删除；`preserve_all` 下始终保留。

原 `source_cleaner.junk_video_max_size_mb` 迁移到统一候选策略，避免页面出现两套“垃圾视频大小”参数；源清理器继续负责非任务垃圾的处置，但不再独立定义什么是媒体候选。

### 2. 维度值与映射彻底分层

每个维度由三个层次组成：

1. **维度定义**：稳定内部键、中文名称、颜色、启用状态。
2. **维度值域**：稳定 value ID 与用户可改的显示名称；入库规则只引用稳定 ID。
3. **Provider 映射**：Provider 原始数据、匹配条件、目标 value ID、优先级和未匹配策略。

内置 value ID 不允许直接改键；可以改中文显示名。删除或停用一个值前，服务端检查 Provider 映射、入库规则、兜底规则和待确认任务引用，存在引用时阻止并给出具体位置。新增自定义值生成稳定 ID，后续改显示名不破坏规则。

### 3. Provider 能力描述与版本化映射合同

Provider 适配器只负责声明“它能提供哪些标准化原始数据”，不决定这些数据属于哪个产品维度。首期定义有限且可验证的数据形状：

- `scalar`：如 `adult=true/false`、`original_language=ko`；
- `set`：如 genres/keywords ID 集合；
- `country_value`：如 `release_dates.certification` 的国家 + 分级值；
- `media_type`：电影/剧集等 Provider 固有类型。

映射使用版本化 JSON 数据，不允许任意执行表达式。示意合同：

```json
{
  "tmdb": {
    "schema_version": 2,
    "sources": [
      {"key": "certification", "field": "release_dates.certification", "shape": "country_value"}
    ],
    "country_priority": ["CN", "HK", "TW", "JP", "KR", "US", "GB"],
    "rules": [
      {"id": "us-r", "source": "certification", "country": "US", "inputs": ["R"], "target": "17+", "priority": 40}
    ],
    "unmatched": {"mode": "review"}
  }
}
```

规则引擎只硬编码安全的操作类型、排序和验证；`R → 17+`、`Genre 99 → 纪录片` 等业务映射移动到版本化出厂预置数据。新装写入预置，升级保留用户覆盖，“恢复产品预置”才重新载入当前版本预置。

保存映射时服务端验证：Provider/字段受支持、规则 ID 唯一、原始值格式正确、目标值存在、优先级无歧义、未匹配策略有效。GET 返回内容哈希，PUT 带原哈希；另一个设备已修改时拒绝覆盖并要求刷新。

### 4. 映射解释证据

每次维度计算同时返回并保存精简证据：

```text
维度：观看分级
Provider：TMDB
原始数据：US / R
命中规则：us-r
结果：17+（限制观看）
映射版本：2 / 内容哈希前缀
```

任务详情只展示普通人说明；技术日志保留 Provider 字段、规则 ID 和版本。不得保存 API Key 或完整 Provider 响应。手动应用候选、重新刮削和自动任务都调用同一执行器，避免同一电影在不同入口得到不同维度。

### 5. 观看分级与成人电影标记拆分

保留内部键 `restricted_level` 以兼容现有规则，但产品名称改为“观看分级”，`17+` 显示名改为“限制观看”，不再写“成人内容”。该维度表达各国年龄/观看认证。

新增可选维度 `content_sensitivity`，只表达 Provider 的成人电影布尔标记：

| 值 | 用户名称 | 含义 |
|---|---|---|
| `normal` | 否 | Provider 未标记为成人电影，不代表适合全年龄 |
| `adult` | 是 | Provider 明确标记为成人电影 |

出厂预置采用保守策略：

- TMDB `adult=false/true` 分别映射到 `normal/adult`，界面只显示“否/是”；Provider 缺少字段时进入人工确认。
- 美国 `R`、英国 `15/18` 等年龄分级只进入“观看分级”，不自动得出 `content_sensitivity=adult`；成人电影标记也不扩展解释暴力、裸露、宗教等内容警示。

旧规则若使用 `restricted_level=17+` 指向成人/X-rated 片库，升级后保留原引用但在维度页和“配置检查”中标记“旧限制级规则需要复核”。系统不自动改目标片库，不按添加顺序猜测新规则；用户可保留现状，或改用 `content_sensitivity`。在用户完成一次明确复核前，相关新任务不得以“成人内容”文案自动通过。

## 前端界面设计

### 设计方向

- 延续现有胶卷、黑金、摄影棚质感；不新增白底管理后台或平行高级首页。
- 主页面强调“结论摘要”，映射弹层强调“原始值 → 我的分类”，不暴露 JSON、数据库字段名和 match_type。
- 默认折叠、逐层展开：普通用户看一行摘要，高级用户才进入完整映射。
- 所有说明用真实例子，不用抽象的“匹配策略”“聚合规则”堆叠文案。

### 维度卡默认态

```text
┌──────────────────────────────────────────────────────┐
│ 观看分级                                      已启用 │
│ 把 Provider 的观看认证归入你自己的分类               │
│                                                      │
│ 4 个分类值 · TMDB 18 条映射 · 未匹配时待确认     ›   │
└──────────────────────────────────────────────────────┘
```

只出现异常时增加一行金色提醒：`发现 2 个未映射值` 或 `1 条旧规则需要复核`。正常状态不展示大段说明。

### 维度卡展开态

```text
┌ 观看分级 ────────────────────────────────────────────┐
│ 分类值                                               │
│ [幼儿/儿童] [家庭向] [青少年向] [限制观看]    [管理] │
│                                                      │
│ 刮削结果怎么归类                                     │
│ TMDB · 发行分级 · 18 条规则 · 未匹配时待确认  [编辑] │
│ 最近示例：通天塔 · US / R → 限制观看                 │
│                                                      │
│                               [恢复产品预置] [收起]  │
└──────────────────────────────────────────────────────┘
```

“分类值”和“Provider 映射”分开保存，避免用户只想改标签时误改整张映射。恢复预置必须二次确认并说明只影响本维度。

### Provider 映射编辑弹层：桌面

```text

│ TMDB  [其他 Provider 以后出现时在这里切换]            │
│ 把 TMDB 返回的发行分级，归入右侧自己的分类。           │
├──────────────────────────────────────────────────────┤
│ [映射规则] [实际影片预览]                             │
│                                                      │
│ 数据来源  发行分级                                    │
│ 地区顺序  中国大陆 › 港澳台 › 日本 › 韩国 › 美国 …   │
│                                              [调整]  │
│                                                      │
│ 美国  3 条                                      [⌄]  │
│   G / TV-Y                → [幼儿/儿童      ▾]        │
│   PG / TV-PG              → [家庭向          ▾]        │
│   R                       → [限制观看        ▾]        │
│ 英国  4 条                                      [›]  │
│                                                      │
│ + 添加 Provider 原始值                               │
│ 未找到映射时： (●) 需要人工确认  ( ) 使用默认值      │
├──────────────────────────────────────────────────────┤
│ 本次修改只影响新任务和未开始文件操作的待确认任务。    │
│                                      [取消] [保存映射]│
└──────────────────────────────────────────────────────┘
```

- 国家/分组默认折叠，当前有异常或最近命中的组自动展开。
- 行右侧始终是现有维度值下拉框；不要求用户记忆内部 value ID。
- 未映射原始值单独置顶并显示观察次数，用户可以一键选择目标值。
- “实际影片预览”不在切换 tab 时自动请求外网；用户明确点击某个最近影片后才重新读取 Provider 数据。
- 保存失败、冲突和连通问题都在弹层内展示，不能只依赖外部 Toast。

### Provider 映射编辑弹层：手机

手机使用全屏 sheet，不使用横向表格：

```text
┌ 观看分级 · TMDB                         关闭 ┐
│ 18 条映射 · 2 条待处理                        │
│ [规则] [影片预览]                             │
│                                               │
│ 美国                                      ⌄  │
│ ┌ TMDB 返回                                  │
│ │ R                                          │
│ │ 映射到  [限制观看 ▾]                       │
│ └─────────────────────────────────────────── │
│                                               │
│ 未找到映射时                                 │
│ ● 需要人工确认                               │
│                                               │
│ [取消]                         [保存映射]     │
└───────────────────────────────────────────────┘
```

- 320 px 宽度不出现横向滚动；按钮最小点击高度 44 px。
- 底部操作区 sticky，但不遮挡最后一条映射。
- 弹层必须用关闭/取消/保存离开，点击遮罩不关闭。
- 屏幕阅读器能读出“TMDB 原始值 R，当前映射到限制观看”。

### 媒体候选过滤配置

放在“文件来源”内部的默认折叠项，不占首屏：

```text
忽略明显广告和小视频片段                         已开启
使用推荐规则，通常无需修改                          [展开]
```

展开后只提供三个普通用户能理解的参数：小视频上限、相对主视频比例、附加名称规则；高可信系统规则可以查看但不能被无意清空。保存旁显示示例结果，不把被忽略文件放进任务列表。

## API 与数据边界

计划新增或收敛以下合同，具体路径在 ADR/实现前冻结：

- `GET /api/providers/{type}/dimension-capabilities`：返回可映射数据项、数据形状和可显示的原始值目录，不返回密钥。
- `GET /api/dimensions/{name}/mappings/{provider}`：返回当前映射、摘要、未映射观察值和内容哈希。
- `PUT /api/dimensions/{name}/mappings/{provider}`：带旧哈希原子保存并返回验证后的摘要。
- `POST /api/dimensions/{name}/mappings/{provider}/preview`：对明确选择的 Provider 影片或纯本地样例预览，不执行入库。
- 扩展扫描结果：任务数、忽略数、按原因汇总；后台扫描只写限频活动，不为每个广告建任务。

`provider_mappings` 继续是映射事实源，但升级为版本化合同。出厂预置移入独立数据资产；数据库保存用户当前值。配置 YAML 不复制一份映射，避免 DB/YAML 双事实源。

### 真实场景

1. `Babel.2006...mp4` 约 25 GB，加两个 0.3/0.6 MB 推广视频：一个任务、两个忽略摘要。
2. 30 MB 独立短片，无主视频和推广名称：正常建任务。
3. 两个大视频同目录：均建任务，不把较小正片当广告。
4. 《通天塔》固定 TMDB 响应 `adult=false, US:R, GB:15, JP:PG12`：观看分级为限制观看，成人电影标记不自动为成人。

7. 映射保存后手动重新刮削：资料、维度、目标规则和路径预览一起刷新，但确认前零文件操作。
8. 来源整组永久删除模式：只有主任务成功和快照复核后，忽略广告才随来源单元进入任务删除隔离区；任何异常全部保留。

## 决策理由与备选方案

| 方案 | 结论 | 原因 |
|---|---|---|
| 只在扫描器加 50 MB 阈值 | 不选 | 会误伤短片，且来源单元仍把小视频当作缺失任务 |
| 只用广告文件名正则 | 不选 | 发布站点变化快，也可能误伤片名；需要大小/同目录上下文共同佐证 |
| 把所有映射继续写在 `dimension_manager.py`，前端只改标签 | 不选 | 用户无法覆盖，各 Provider 无法独立扩展，错误仍不可解释 |
| 让用户编辑原始 JSON/表达式 | 不选 | 复杂、容易写出越界或不确定规则，移动端不可用 |
| 每种维度写一套独立编辑器 | 不选 | 当前前端已经出现多套映射与保存语义漂移，后续 Provider 会继续复制 bug |
| 通用能力描述 + 有限规则类型 + 同一编辑壳 | 采用 | 能覆盖当前字段，保持可验证、可扩展和普通用户默认无感 |
| 把 R 直接改映射为青少年向 | 不选 | 解决了成人误称，却制造了年龄分级事实错误 |
| 拆分观看分级与成人电影标记 | 采用 | 与 Provider 数据语义和用户片库用途一致，允许独立人工映射 |

## 主观契约与预览门禁

- **目标感受**：像在把“TMDB 的说法”翻译成“我的片库分类”，不是在编程。
- **反目标**：不出现 JSON、正则、布尔表达式、数据库键值大表；不让用户为了默认可用逐条保存几十行。
- **正向参考**：现有胶卷阶段、黑金卡片、规则模板变量助手的默认折叠设计。
- **反向参考**：当前维度页“无需手动编辑”的硬编码说明、所有字段平铺、错误只用 Toast、移动端横向表格。
- **语气**：用“Provider 返回值 / 我的分类 / 未找到时怎么办”，不用“match_type / operator / schema”。
- **代表性证明切片**：`观看分级 + TMDB + 通天塔`，必须同时证明摘要、编辑、预览、保存、刷新和移动端。
- **扩散规则**：代表性切片经人工评审并通过 UI/API/迁移测试后，才适配题材、地区、语言等其他维度。
- **拒绝标准**：普通用户首次打开就看到几十条映射；手机需要左右拖动；R 仍显示成人内容；映射保存后刷新丢失；旧规则被自动改片库；忽略广告后来源单元无法完成。
- **必需预览产物**：四种 viewport 截图、正常/未映射/旧规则待复核三种状态、映射保存前后《通天塔》实际预览。

## 自评审结论

### 正确性

方案把“业务映射值”移出执行代码，同时保留 Provider 字段标准化和有限操作类型，既满足人工配置，也没有开放不可验证脚本。手动、自动和重新整理共用同一映射入口，避免入口差异。

### 数据与文件安全

广告过滤只决定是否建任务，不直接授权删除；来源处置仍受任务提交、来源单元快照、挂载身份、回收/隔离区和目标片库禁删边界约束。已完成影片不会因映射变化自动移动。

### 用户简洁性

主页面只增加摘要和一个“编辑映射”动作，复杂度收进不可误关的弹层；普通用户保留开箱即用预置，高级用户能看见并修改每条 Provider 映射。移动端不使用表格。

### 可落地性

当前 DB、Provider 适配器、任务 scrape trace、维度页面和配置检查都有可复用入口；最大新增工作是 v2 映射合同、通用执行器和统一编辑器，不需要引入前端框架。广告过滤需要同步来源单元，是中等改动但边界明确。

### 最终判定

**方案可开发，但必须按代表性切片门禁推进。** 先修维度渲染和完成“观看分级 + TMDB + 通天塔”预览，不允许一开始就把新 UI 复制到全部维度；先证明候选快照与来源清理闭环，再允许广告过滤进入自动 watcher。
