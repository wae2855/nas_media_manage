# 配置开始页开发者支持卡计划

在配置“开始”页末尾增加一个克制的独立开发者支持区域，不干扰首次配置主流程，也不暗示付费后才能使用功能。

## Problem Statement

项目目前没有向愿意支持独立开发者的用户提供入口。用户希望展示自己的收款码，但仓库中尚无真实二维码资源，因此本轮先建立稳定的展示结构、文案和可替换图片入口，禁止生成或伪造收款信息。

## Target End State

- 开始页全部配置说明之后出现“支持独立开发”卡片。
- 文案明确打赏完全自愿、不影响功能与更新。
- 收款码和微信码并排展示，各有清晰标题和无障碍文本；使用普通图片元素直接加载，底层保留不可扫描的占位背景。
- 视觉延续当前影院金色、胶片与片尾鸣谢语义，移动端不溢出。

## Scope

- 修改 `media_importer/webui/index.html` 和现有配置页 CSS。
- 新增一个不含支付信息的占位 SVG 资源。
- 增加静态结构测试、更新前端测试映射和需求看板。

## Non-Goals

- 不接入支付接口、金额选择、支付状态或用户追踪。
- 不在没有真实素材时生成收款码。
- 不弹窗、不自动展开、不遮挡配置按钮，不改胶卷导航。

## Subjective Contract

- **目标感受**：像电影片尾的一句温和鸣谢，而不是配置流程里的广告位。
- **反目标**：不使用“求打赏”“解锁功能”“限时支持”等施压话术。
- **正向参考**：现有 `start-hero-card` 的低饱和金色光影和信息层级。
- **反向参考**：高亮支付按钮、悬浮二维码、自动弹窗、两个二维码用途不清导致的促销感。
- **语气**：感谢、自愿、透明；普通用户可一眼忽略而继续配置。

## Representative Preview

```text
┌─ END CREDITS · 支持独立开发 ─────────────────────┐
│ 如果这个项目帮你省下了整理时间，可以请开发者喝杯咖啡。 │  ┌────────┐
│ 完全自愿，不打赏也不影响任何功能、更新与问题反馈。       │  │ 收款码 │
│                                                     │  └────────┘
└─────────────────────────────────────────────────────┘
```

如果真实页面中该区域比“检查需要处理的项目”按钮更醒目，或首屏就抢占配置注意力，则退回调整。
