# ADR-0022: 取消中心中转并采用整任务重启恢复

Date: 2026-09-02
Status: Accepted
Requirement: REQ-20260902-033000
Amends: ADR-0021 decisions 6 and 9

## Context

ADR-0021 已让新任务在全部识别和冲突决策完成后直接写入目标侧任务暂存，但仍为旧任务保留中心中转断点、配置和启动恢复。产品尚未发布，用户明确不要旧任务和历史文件兼容。继续保留两套文件流会增加一次目录授权、额外磁盘概念和不可预测的重试语义。

## Decision

1. 删除中心中转存储角色。配置、API、前端、fnOS 授权和运行时不再接受或返回 `temp_dir`。
2. 删除 `file_location=temp` 和来源到中心中转步骤；任务文件位置只表达来源或已提交目标等真实业务位置。
3. 唯一新入库链路为：来源只读识别与决策 → 目标侧任务私有暂存 → 校验 → no-replace 文件包提交 → 来源处置。
4. 目标侧暂存是提交实现细节，不是用户目录、业务断点或可独立恢复来源。
5. 任务重试总是从来源重新刮削、规则判断、冲突判断和完整传输，不续接任何旧业务步骤或旧大文件。
6. 提交前中断：仅清理任务清单明确列出且同时满足目标根、任务标识和临时后缀约束的 `.copying` / `.bundle.tmp`；来源保持不变，任务失败。
7. 完整提交后中断：仅当清单中的所有正式成员路径、大小和 SHA-256 均一致时修复为成功，不再次复制。
8. 清单越界、部分提交、正式文件缺失或指纹不符时禁止猜测。保留来源、正式文件和临时文件，任务进入需要人工检查。
9. 启动恢复仅访问数据库非终态任务清单列出的路径，不扫描中心中转或整座片库。
10. 本决策不改变 ADR-0021 的协作式停止、来源处置和任务记录删除合同；只替代其中旧中转兼容部分。

## Consequences

- 用户少配置、少授权一个目录，新任务少一次完整大文件写入。
- 状态机和恢复组合显著减少，异常结果更容易解释和测试。
- 断电后可能丢失本次复制进度；用户接受整任务重来以换取简单和安全。
- 旧配置、旧任务和历史中转文件不再受支持，也不做迁移。

## Rejected alternatives

- 保留隐藏的内部中心中转：仍会产生双复制和两套恢复事实，否决。
- 跨重试续传目标 `.copying`：让临时文件成为隐式业务断点，增加误认与校验组合，否决。
- 部分成员存在时自动补齐并继续：提交边界不再清晰，可能把不一致片库认作成功，否决。
