# ADR-0012: 存储角色拓扑与目录边界

Date: 2026-08-28
Status: Accepted
Requirement: REQ-20260828-151346

## Context

fnOS 用户的来源通常是本地 BT 目录或云盘挂载目录，目标也可能是本地或另一云盘。当前配置仅保存路径字符串，无法证明目录是本地还是远程，也不能防止回收目录嵌套在来源中。路径测试还会创建不存在的根目录，可能在挂载失效时把同名本地目录误判为云盘恢复。

## Decision

1. 引入位置角色和能力投影，不以路径前缀猜测业务语义：来源、片库目标、本地中转、本地回收、应用私有数据。
2. 来源和目标允许本地或 fnOS 已挂载路径；中转、回收、DB、日志、资源必须位于本地主机存储。
3. 用户选择的来源、目标、回收根目录必须已存在；校验器只能检查，禁止创建。应用只可在已验证根内创建自己的业务子目录。
4. 所有根目录 canonicalize 后校验允许边界、符号链接、父子嵌套和挂载身份。来源、目标、中转、回收不得形成危险包含关系。
5. 位置健康独立于任务终态：`ONLINE/DEGRADED/OFFLINE/RECOVERING`。目录消失或扫描异常不得当作空目录。
6. 配置就绪采用 `UNCONFIGURED/VALIDATING/READY/BLOCKED`；服务可在非 READY 时启动配置 UI，所有文件副作用入口统一被门禁拦截。
7. 容量在配置、启动/恢复、任务开始前检查。无法读取空间不是安全状态；黄色仅允许人工运行，红色暂停或阻止。
8. 来源视频默认保留。来源处理模式与垃圾清理的从属关系由 [ADR-0014](0014-source-unit-lifecycle.md) 取代原“完全独立”定义；远程来源执行写操作前仍须重新验证在线、写权限和本地回收容量。
9. 位置校验持久化 `realpath + st_dev + filesystem type + mount point + mount source` 快照；每次文件副作用前复核。任一身份字段变化立即进入 `OFFLINE/BLOCKED`，不得把同名新建目录视为原挂载恢复。
10. `unknown` 位置采用最小权限：可作为来源或目标进行人工任务，但禁止 watcher、自动入库和任何源清理；中转和回收直接拒绝。只有位置身份、健康和所需能力被证明后才允许自动化。

### 位置能力矩阵

| 角色/位置 | 人工读取 | 自动扫描 | 写入 | 删除/源清理 |
|---|---|---|---|---|
| 本地来源 | 是 | 在线且文件稳定后 | 显式授权 | 显式策略 + 本地回收 |
| 已识别远程来源 | 是 | 身份稳定、在线且文件稳定后 | 每次重检 | 每次重检 + 本地回收容量足够 |
| unknown 来源 | 是 | 否 | 否 | 否 |
| 本地目标 | — | — | 容量通过后自动 | 仅按回收规则覆盖 |
| 已识别远程目标 | — | — | 身份稳定、在线、容量可判定时自动；容量未知仅人工 | 不直接删除 |
| unknown 目标 | — | — | 仅人工且完成目标回读校验 | 不直接删除 |
| 中转/回收 unknown 或远程 | — | — | 拒绝 | 拒绝 |

## Consequences

- 配置 API 和 UI 展示真实能力与校验时间，不再只展示路径字符串。
- 远程协议细节仍由 fnOS 挂载层负责；应用不承诺协议刷新时效。
- 精确识别挂载类型可能受 fnOS 平台信息限制；无法确认时按 `unknown` 最小权限处理。
- 回收恢复到离线远程目标时保持本地副本并等待，不形成数据丢失。

## Alternatives

- 所有目录都允许远程：无法保证中转、回收和 SQLite 的可靠性，否决。
- 所有远程都禁止：无法覆盖主流使用方式，否决。
- 不识别位置能力只做权限测试：挂载失效和同名本地目录无法区分，否决。
