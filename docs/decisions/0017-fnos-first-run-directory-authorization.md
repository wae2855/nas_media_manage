# ADR-0017: fnOS 首次启动目录授权与离线项目依赖

Date: 2026-08-30
Status: Accepted
Requirement: REQ-20260830-180954

## Context

fnOS 原生安装向导不提供目录浏览字段；继续手填不能完成共享目录授权。系统已有共享目录选择开放能力。与此同时，应用无法控制依赖包 `python312` 的安装进度，但可以消除项目依赖的在线下载。

## Decision

1. 安装向导只说明首次启动流程，不采集端口、服务 API Key 或目录；来源、片库和回收目录移动到首次 Web 启动。
2. fnOS 环境必须由应用主动进入官方共享目录选择/授权流程，并在独立回调页完成一次性 state 校验；只查询授权目录不能视为完成授权。普通浏览器或非 fnOS 开发环境才降级手填。
3. 服务端通过 fnOS Unix socket 查询当前应用已授权目录，token 只从进程环境读取，绝不写配置或返回前端。
4. 来源和片库可选择本地或远程挂载；回收只允许本地共享目录。最终以服务端存储角色校验为准。
5. manifest 继续依赖官方 `python312`，不内嵌完整 Python。
6. 项目 Python 依赖按架构预装进 FPK wheelhouse，安装时 `--no-index`；x86/arm 分包构建并校验平台。
7. 首次目录未配置完成时允许服务启动进入配置页，但自动扫描、移动、清理和恢复保持 BLOCKED。
8. fnOS manifest、服务运行配置和桌面 CGI 统一使用托管端口 `14591`；旧配置在安装或升级时只迁移该端口与服务认证，不覆盖用户目录和业务配置。
9. 目标片库不是预置槽位，也不能从旧规则读取作为首次配置输入；全新安装为 0 个，由用户动态创建 0～N 个。旧绝对规则进入独立的显式迁移状态。
10. 存储检查使用一份逐目录台账，不再把多个目标聚合成一个授权按钮。来源与回收选择成功后立即保存，目标片库完成命名/默认项确认后保存。
11. 回调不能只依赖 `window.opener`；同源存储事件作为移动端/新标签桥接，仍受一次性 state、应用名和十分钟有效期约束。
9. 目录路径与系统 ACL 是两份独立事实。fnOS 环境保存来源、片库或回收路径时，服务端必须确认该路径位于当前应用已授权根目录之内；卸载重装丢失 ACL 时旧路径显示“需要重新授权”，不能继续冒充可用配置。

## Consequences

- 用户不再记忆路径，选择同时完成 fnOS 授权。
- 系统 Python 首装仍可能耗时，但不会再叠加不确定的公网 pip 下载。
- 打包产物需要按架构发布，fnOS 开放能力需要真实设备 UAT。

## Alternatives

- 内嵌 Python：包体、升级和安全维护成本过高，否决。
- 保留安装向导手填：不支持浏览与授权，否决。
- 前端自行信任选择结果：缺少服务端权限事实，否决。
