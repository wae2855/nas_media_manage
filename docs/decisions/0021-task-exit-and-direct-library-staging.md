# ADR-0021: 协作式任务退出与直接目标暂存

Date: 2026-09-02
Status: Accepted (central-staging compatibility amended by ADR-0022)
Requirement: REQ-20260902-021000

## Context

任务页当前把删除记录写成“移入回收”，运行中又不能停止；用户无法可靠表达“保留片库现有文件，但不要这次新资源”。确认后的文件流固定经过本地中转，也会让超大影片多一次完整复制。

## Decision

1. 任务结果、来源处置、任务记录删除是三个独立事实。
2. 活动任务采用数据库持久化的协作式停止请求。每个只读步骤边界和大文件块检查请求；目标视频提交后拒绝取消并完成收尾。
3. 来源处置只允许 `keep`、`local_recycle` 和在 ADR-0019 已启用时的 `permanent_delete`。单任务只处理已登记的视频/字幕，绝不递归猜测同目录内容。
4. 目标片库路径永不进入普通任务处置集合。已完成任务的删除动作只删除记录。
5. 新任务在身份、规则、命名、冲突和人工决策完成前不传输大文件。
6. 决策完成后，来源直接复制到目标侧任务暂存并校验。目标发布仍是字幕先、视频最后、no-replace。中心中转兼容已由 ADR-0022 取消。
7. 来源在目标提交前保持原样。提交后按配置保留、回收或通过隔离账本永久删除。
8. 来源处置失败必须保留任务记录、来源和明确错误，不得谎报成功或自动降级到另一种删除方式。
9. 中心中转目录、旧任务断点和相关配置已由 ADR-0022 取消；中断任务统一从来源重新整理。
10. “本地回收”意味着可恢复，因此跨磁盘时仍可能产生一次来源到回收区的搬运；追求最少写入且明确不要来源的用户可显式启用 ADR-0019 的永久删除。系统不得用隐式物理删除冒充优化。

## Consequences

- 新任务通常减少一次整部影片复制和一次来源全量读取。
- 运行中停止会有短暂“正在安全停止”，而不是瞬时终止。
- 需要数据库迁移、传输检查点、状态感知 API、批量结果和双端 UI 测试。
- 不再支持旧中转任务或历史大文件迁移。
- 自动轮询不再因检查一个未使用的中转盘而唤醒休眠磁盘。

## Rejected alternatives

- 强制终止线程：可能留下半完成发布，否决。
- 一个删除按钮自动猜来源动作：不可预测，否决。
- 继续强制所有任务经过中转：额外大文件复制，否决。
