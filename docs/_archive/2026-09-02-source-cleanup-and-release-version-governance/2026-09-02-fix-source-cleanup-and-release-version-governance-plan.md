# 来源永久删除闭环与 fnOS 发版版本门禁实施计划

- **Requirement**: [REQ-20260902-172713](../../tracking/requirements-board.md)
- **Proposal**: [来源清理与发布治理](2026-09-02-source-cleanup-and-release-version-governance.md)
- **ADR**: [ADR-0023](../../decisions/0023-release-version-ledger-and-monotonic-build-gate.md)

本轮把真机暴露的来源处置停滞、FUSE 权限探针残留和同版本重复出包收敛为可测试、可查询、失败关闭的完整合同。

## 任务分解

- [x] 修复写权限探针关闭和清理协议，增加 FUSE 重复关闭、符号链接陷阱和遗留探针不误删测试。
- [x] 为 watcher 增加不扫描片库的来源处置维护回调；服务启动和每次来源轮询均可重试待处理来源单元。
- [x] 对物理快照未变化且缺少候选证据的来源单元补齐冻结判定，并验证广告/附带小视频不会阻塞整组处置。
- [x] 让任务/日志可见待处理、阻断、失败和完成原因，不把“影片已入库”与“来源已处理”混为一体。
- [x] 新增版本台账工具、受控台账和构建前后门禁；根 `VERSION` 升至 `0.3.24` 并移除测试中的固定版本常量。
- [x] 更新发布、部署、监控、来源文件、存储与安全事实文档。
- [x] 完成专项、全量、静态、文档及真实 Chromium 验证，执行发布门禁干运行；本轮未把本地结果标记为 fnOS 验收。

## 实施结果

- `LOCAL PASS`：1000/1000 全量测试通过，包含真实 Chromium 客户流程；18 项架构护栏、Ruff、compileall、shell、文档和 diff 检查通过。
- `RELEASE_GATE PASS`：`0.3.23` 同版本不同源码被拒绝，`0.3.24` 预检通过；状态查询如实显示“最近 fnOS 验收正常版本：暂无”。
- `LOCAL_BUILD NOT_RUN`：本轮未生成 `0.3.24` FPK，发布台账仍只登记 `0.3.23` 历史候选。
- `FNOS_UAT NOT_RUN`：等待用户要求生成安装包并在真机验证。

## 测试计划

- 单元：`check_write_permission` 故障注入；来源单元证据补齐与永久删除隔离协议；版本比较、指纹、候选记录和验收记录。
- 集成：watcher 无新文件时仍触发待处理来源重试；空闲路径不读取目标片库；运行时重载保持维护回调。
- 发布：构建脚本在同版本不同源码、降版、缺失台账时于构建前失败；新版本可通过预检；包内版本一致性继续由 `validate_fpk.py` 保证。
- UI/客户视角：本地服务查看任务详情和自动运行状态，确认来源处置说明不误报整体完成；桌面与移动端无新增布局回归。
- 必跑：相关 pytest、架构护栏、compileall、改动 Python Ruff、`bash -n deploy/build_fpk.sh`、`scripts/check_docs.py`，最后跑 `python -m pytest tests/`。

## 验收标准

1. rclone/FUSE 的关闭异常不会留下本轮探针或终止 watcher；未知历史探针不会被自动删除。
2. 已入库且满足快照/任务门禁的来源单元，无需新文件也会自动完成所选来源处置。
3. 任何来源变化、未知媒体、失败任务、片库重叠或挂载变化都继续保留来源并给出中文原因。
4. `release status` 能查询当前版本、最近候选和最近正常版本；没有已验收版本时明确显示“暂无”，不伪造历史。
5. `0.3.23` 的不同源码无法再出包；`0.3.24` 及更高版本可进入候选构建，同版本仅允许相同指纹重建。
6. 本地测试报告分别列出 LOCAL、LOCAL_BUILD 和 FNOS_UAT；未在真机执行时 FNOS_UAT 必须为 `NOT_RUN`。

## 风险

- 旧来源记录补证若放宽过度会误删：只允许物理快照逐项一致，判定仍冻结，任何异常失败关闭。
- 每次轮询重试可能影响休眠：回调先查 SQLite，只有待处理单元才访问其来源；禁止扫描目标片库。
- 台账可能与人工修改冲突：工具严格校验 JSON、SemVer、重复版本和哈希；构建脚本不得直接拼接台账内容。
- 当前工作树包含大量既有未提交修改：只增量修改本需求相关文件，不回退或覆盖其他改动。
