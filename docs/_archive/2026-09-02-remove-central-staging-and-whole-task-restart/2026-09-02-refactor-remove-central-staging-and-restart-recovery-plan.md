# 取消中心中转并补齐整任务重启恢复实施计划

- **Requirement**: [REQ-20260902-033000](../../tracking/requirements-board.md)
- **Proposal**: [取消中心中转与整任务重启方案](../../proposals/2026-09-02-remove-central-staging-and-restart-recovery.md)
- **ADR**: [ADR-0022](../../decisions/0022-remove-central-staging-and-whole-task-restart.md)
- **Status**: completed（本地实现与客户视角验收通过，fnOS 真机验收未执行）

一句话总结：删除用户可配置的中心中转目录及全部旧中转兼容分支，冻结“先识别决策、后直接写目标任务暂存”的唯一链路，并让服务重启只产生可证明的成功、可安全重来的失败或需人工检查三种结果。

## Problem Statement

上一轮已让新任务默认从来源直接写入目标侧任务暂存，但配置、fnOS 授权、旧任务恢复、任务状态和部分文件服务仍保留中心中转概念。它继续增加用户理解成本，也让重试与恢复存在两套语义：一套从来源重来，一套从旧中转断点继续。

用户已明确产品尚未发布，不需要旧任务、旧配置或历史中转文件兼容。继续保留兼容代码会扩大目标片库的安全审计面，并让“中断后到底从哪里继续”无法用一句话解释。

## Target End State

- 配置、API、fnOS 授权、前端、文档和运行时均不存在中心中转目录。
- 任务在作品身份、入库规则、最终路径和重复冲突全部确定前不复制大文件。
- 需要入库时，来源文件直接复制到目标片库同文件系统内、仅属于该任务的隐藏暂存文件；校验通过后执行 no-replace 文件包提交。
- 重试总是从来源重新刮削、重新决策、重新传输；不恢复业务步骤，不续接上一任务留下的大文件。
- 服务中断后只允许三种可解释结果：
  1. 提交前：删除有任务清单证明归属的 `.copying` / `.bundle.tmp`，来源不动，任务失败且可从头重试；
  2. 文件包已完整提交：复核任务清单与正式文件后修复为成功，不重复复制；
  3. 无法证明完整或安全回退：所有文件保持原状，任务进入“需要人工检查”，禁止自动继续。

## Scope

- 删除 `temp_dir` 配置合同、校验、保存、运行时刷新、开场检查、fnOS 目录授权和前端存储卡片。
- 删除 `file_location=temp`、`FileCopier` 业务入口、来源到中心中转步骤、旧中转重试和启动扫描清理。
- 简化导入、协作式停止、任务处置、重试和 bundle recovery。
- 修订安装配置、示例、架构/功能/安全/测试文档和需求看板。
- 增加中断恢复单元、集成和真实 Chromium 前台验收。

## Non-Goals

- 不支持旧任务、旧数据库状态或旧中心中转文件迁移。
- 不实现业务步骤级续跑或跨重试的大文件断点续传。
- 不改变片库重新整理的安全移动模型；重新整理仍不得删除或覆盖既有影片。
- 不改变来源保留、本地回收和受控永久删除三种来源处置合同。
- 不在本轮打包、提交或推送代码；除非用户后续单独授权。

## Proposed Solution

### 1. 唯一文件流

```text
来源只读发现
  → 刮削和人工确认
  → 规则选择与最终命名
  → 目标片库重复检查和人工决策
  → 目标任务隐藏暂存（.copying / .bundle.tmp）
  → 每成员校验
  → 字幕先发布、视频最后发布、禁止覆盖
  → 来源按用户策略收尾
```

目标隐藏暂存不是用户配置的“中转站”，不作为任务恢复来源，也不在存储检查中单列。它只存在于最终目标旁边，受目标片库授权、空间和任务清单约束。

### 2. 整任务重启

- 普通异常与协作式停止在视频提交前都清理任务自有临时文件。
- `retry` 清空刮削、规则、冲突、进度和 bundle journal 的运行结果，恢复来源位置，再进入排队。
- 重启恢复只读取数据库清单中列出的目标暂存和正式目标；不遍历整个片库，不扫描任何中心中转目录。
- 已提交恢复只在所有成员路径、大小和 SHA-256 都与持久清单一致时改为成功。
- 清单缺失、越界、正式文件部分存在或指纹不一致一律失败关闭并标记人工检查。

### 3. 配置与前端减法

- 存储检查仅保留来源、本地回收、运行日志、海报与缓存、0～N 个目标片库。
- 删除“本地中转”卡片、按钮、帮助文案、保存请求和 fnOS 授权角色。
- 页面仍使用既有胶片轨道、卡片密度、金色/绿色状态语言；不新增替代配置。
- 任务失败文案只回答“来源是否保留、片库是否提交、能否重新整理”，不暴露旧中转术语。

## Target Outcome And Anti-Goals

### 用户感受目标

普通用户只需理解：系统先确认影片和目标，确认后直接入库；中断时没有成功就从头重来，已经完整成功就自动认账，无法确定就提示人工检查。

### Anti-goals

- 不能用“缓存”“临时盘”等新名称把中心中转换皮保留。
- 不能在异常时把 `.copying` 当作可继续入库的正式来源。
- 不能为了自动恢复而扫描整座片库或唤醒无关磁盘。
- 不能把部分提交或指纹异常修复为成功。
- 不能让配置页出现空白占位、重复目录按钮或移动端横向溢出。

### References / Anti-references

- 正向参考：现有“存储检查”胶片轨道与统一目录卡片；ADR-0021 的先决策后传输和目标文件包 no-replace 提交。
- 反向参考：旧“来源 → 中转 → 目标”双复制、`file_location=temp` 断点、启动时扫描中转目录、配置页暴露内部实现目录。

### Taste Rules

- 只做减法，不创造新的设置项。
- 用户文案使用“入库前/已入库/需要人工检查”，不使用 journal、checkpoint、rollback 等工程词。
- 桌面和 390/360/320px 都保持单列可读，目录状态与操作按钮对齐现有规范。

### Representative Proof Slice And Rollout Rule

先完成“存储检查删除中转卡片 + 配置 API 不再返回 `temp_dir` + 一个来源直达目标且提交前失败被清干净”的纵向切片。该切片通过后，才传播到重试、启动恢复、fnOS 和全部测试。

### Rejection Criteria

- 任一公开配置/API/前端/fnOS 授权仍出现 `temp_dir` 或“本地中转”。
- 重试可以使用旧暂存文件继续，或进度不是从识别阶段重新开始。
- 提交前中断后来源发生变化，或目标留下无清单证明的可见半成品。
- 已提交恢复未验证全部成员就标记成功。
- 真实浏览器仍能看到中转配置，或任务异常结果没有普通人可理解的下一步。

## Decision Rationale

中心中转曾用于把远程来源先落本地并支撑断点，但现在最终身份、规则和重复决策都在传输前完成，目标侧已有任务私有暂存、哈希校验和提交日志。保留中心中转只会增加一次大文件写入、一个必须授权的目录和一套旧任务状态。

整任务重来比步骤续跑牺牲了异常后的部分传输时间，但显著缩小状态组合。影片整理是低频、大文件、数据安全优先的 NAS 任务；“宁可重来，不猜测成功”比复杂断点更易验证，也更符合用户已确认的简洁边界。

## Constraints And Boundaries

- 目标片库正式文件不得被普通异常清理、任务删除或重试删除。
- 只允许删除持久任务清单明确列出、真实路径位于目标根内、名称满足本任务临时后缀的文件。
- 来源在文件包提交前只读；来源处置仍必须在提交后走既有安全服务。
- 目标片库目录只做读取、新增和受控更新；覆盖仍需人工确认并先进入本地回收区。
- 文件路径必须经过 realpath/commonpath、符号链接和允许根校验。
- 后台空闲恢复不得遍历目标片库，只处理数据库中非终态任务的有限清单。

## Risk Analysis

| Risk | Impact | Mitigation |
|---|---|---|
| 清理目标暂存路径判断错误 | 严重，可能触碰正式片库 | 清单 + 任务 ID 后缀 + 目标根 + 临时后缀四重校验；反例测试覆盖符号链接、路径穿越和正式文件 |
| 删除配置后漏掉 fnOS 生成配置或授权 | 安装失败或设置未生效 | 源码、deploy staging、构建脚本和 FPK 校验一并测试；禁止打包快照成为事实源 |
| 普通复制异常留下 `.copying` | 重试行为与承诺不一致 | 对所有异常统一清理；启动恢复再次清理；用故障注入断言目标为空 |
| 提交边界数据库落盘顺序错误 | 完整文件被误判或部分文件被认作成功 | 视频最后发布；提交状态 fsync/事务持久化；恢复逐成员复核后才成功 |
| 移除 `file_location=temp` 影响任务删除/忽略 | 用户动作失败或误删 | 状态矩阵重写为 source/import 两类并运行任务处置全矩阵 |
| 为验证异常扫描整座片库 | 唤醒休眠磁盘 | 恢复仅访问任务清单列出的路径，增加访问计数测试 |

## Phased Implementation

### Phase 1 — 合同和纵向证明切片

- [x] 注册新需求，补充 ADR-0021 的替代决策或新 ADR，冻结无旧兼容和三类恢复结果。
- [x] 删除 `temp_dir` 的公开配置合同和存储检查卡片。
- [x] 单一来源直达目标的故障注入测试证明提交前异常：来源保持、目标临时清空、任务失败。

Exit：公开配置与前端不再出现中转，首个安全切片通过。

### Phase 2 — 业务链路收敛

- [x] 删除 FileCopier/`_step_copy`/`file_location=temp` 和中心中转清理分支。
- [x] 导入只允许来源直接复制；普通异常和协作式停止统一回退任务临时文件。
- [x] retry 永远清空运行结果并从来源重新排队。
- [x] 启动恢复实现提交前回退、已提交复核成功、歧义人工检查。
- [x] 保持来源处置、目标冲突和重新整理安全边界。

Exit：代码搜索无业务中转分支，状态和文件流测试通过。

### Phase 3 — fnOS、前端与文档完成

- [x] 删除 fnOS 授权、默认配置和安装说明中的中转目录。
- [x] 更新任务失败/恢复文案和移动端布局回归。
- [x] 更新架构、功能、安全、测试矩阵、需求看板和 ADR 索引。

Exit：源码与打包输入使用同一无中转合同，文档检查通过。

### Phase 4 — 真实前台验收与质量门禁

- [x] 在本地开发环境创建真实来源、片库、字幕和故障注入场景。
- [x] 通过真实 HTTP 服务与 Chromium 前台操作验证正常入库、提交前中断后从头重试、提交后恢复成功和歧义人工检查。
- [x] 桌面与 390/360/320px 检查配置页、任务列表和详情，无横向溢出、控制台异常或 HTTP 5xx。
- [x] 运行全量 pytest、ruff、compileall、JS 语法、架构护栏、文档检查和 diff check。
- [x] 完成后归档计划并记录 LOCAL PASS / fnOS NOT_RUN。

Exit：全部自动化与真实前台验收通过，无已知失败。

## Acceptance Criteria

1. `GET /api/config`、保存 API、配置 YAML、fnOS 生成配置和前端 DOM 均不包含 `temp_dir` 或中转目录入口。
2. 新任务确认前目标写入字节为 0；确认后视频和字幕只执行一次来源到目标任务暂存的有效载荷复制。
3. 提交前异常或停止：来源文件与字幕指纹不变，目标正式文件不存在，任务自有 `.copying` / `.bundle.tmp` 均删除，任务显示“未入库，可重新整理”。
4. 点击重试后刮削/规则/冲突/进度和 bundle journal 均重置，从来源识别阶段开始，绝不读取旧临时文件。
5. 文件包已完整提交但任务未标记成功时，重启只读取清单列出的成员并校验，恢复为成功且不再次复制。
6. 正式成员缺失、大小/哈希不符、清单越界或部分提交时，重启不删除任何正式文件或来源，任务显示“需要人工检查”。
7. 任务删除、来源处置、重复片保留、目标替换和重新整理的片库保护回归全部通过。
8. 本地真实 Chromium 从配置页和任务页完成上述用户路径；桌面及 390/360/320px 无横向溢出，控制台错误和 HTTP 5xx 为 0。
9. 全量测试、变更文件 Ruff、compileall、JavaScript 语法、架构护栏、文档检查和 `git diff --check` 全部 PASS。
