# 统一存储目录管理入口

把所有路径选择、授权、检查和修改动作收口到“存储检查”；其他配置页只保留与目录用途相关的业务策略。

## Problem Statement

- 文件来源既能在“文件来源”填写，又能在“存储检查”修改，存在双入口和状态漂移风险。
- 本地中转在存储清单中只能查看，运行日志却藏在进阶设置，用户无法形成稳定心智模型。
- 中转路径切换会影响正在运行或等待恢复的中转文件，不能只把它当作普通文本字段保存。

## Target End State

- “存储检查”是来源、中转、回收、运行日志、资源缓存与 0～N 个目标片库的唯一目录管理入口。
- “文件来源”仅配置扫描、来源保留/清理和递归策略，不再展示源目录输入框。
- 中转目录提示：优先与主要目标片库位于同一磁盘以减少跨盘搬运；也可使用本地 SSD 提升高频读写速度。
- 中转、回收、日志和资源目录只允许本地目录；fnOS 环境必须由系统选择器授权。
- 中转路径存在运行中任务或旧路径内仍有文件时拒绝切换，不移动、不删除遗留文件。
- 每次目录变更都在原子保存前完成存在性、权限、挂载类型、冲突和容量检查，成功后刷新统一清单。

## Scope and Non-Goals

### Scope

- 调整统一目录清单的角色、文案和修改动作。
- 增加目录角色保存契约和中转切换门禁。
- 删除文件来源页与进阶设置里的重复路径字段，同时保留兼容配置加载。
- 同步配置、前端信息架构和测试文档。

### Non-Goals

- 不自动迁移或删除旧中转目录里的任何文件。
- 不改变胶卷导航、来源清理业务逻辑或入库复制实现。
- 不允许远程挂载承担中转、回收、日志或资源缓存角色。
- 本轮不构建 FPK、不操作真机、不推送云端，除非用户另行要求。

## Proposed Solution

1. 后端把资源缓存加入 readiness 目录事实，并为目录更新返回角色级检查结果。
2. 前端统一由存储卡片触发目录选择；来源/回收/中转/日志/资源按角色立即保存，目标片库继续使用动态列表逻辑。
3. 中转变更前检查任务状态与旧目录内容；任何活跃/可恢复中转事实存在时拒绝切换并说明处理办法。
4. 从来源页移除路径输入，从进阶系统页移除日志/资源路径输入；现有字段仍能从旧配置读取并由统一清单展示。

## Decision Rationale

- 按“目录在哪里”与“目录里的文件怎么处理”拆分职责，比按历史配置区块分散入口更容易理解。
- 中转同盘减少一次跨磁盘读写路径；本地 SSD 适合高频并发读写，但最终选择仍取决于容量、耐久度和目标片库分布。
- 对非空中转目录采取拒绝切换而非自动搬迁，避免破坏断点续跑、误移动用户文件或制造不可回滚的长事务。

## Constraints and Boundaries

- 所有文件删除/覆盖继续遵守回收站安全红线。
- fnOS 目录授权不可由手填路径绕过。
- 资源缓存可重建，但本轮仍不自动清空旧缓存目录。
- 配置原子保存与 revision 冲突检测保持不变。

## Subjective Contract and Preview Gate

- Target outcome：用户只需记住“所有路径都去存储检查”，其他页面不再出现路径输入。
- Anti-goals：不新增第二套授权面板，不把系统目录变成首屏必填项，不用专业存储术语吓阻普通用户。
- Positive reference：现有“角色—状态/路径—容量—操作”单层目录卡片。
- Anti-reference：来源页文本框、进阶页日志文本框和存储卡片同时存在。
- Tone：普通用户先看到“系统默认，无需修改”；性能建议说明收益，也明确容量和本地磁盘边界。
- Proof slice：先完成来源路径移除和中转目录卡片/安全弹窗，在 1440px 与 390px 预览通过后扩展日志和资源。
- Rollout rule：proof slice 无重复入口、无横向溢出且保存后刷新一致，才扩展所有系统目录。
- Rejection：任何目录仍有第二个可编辑入口；非空中转可被切换；远程系统目录可保存；移动端按钮遮挡或路径溢出。
- Required previews：桌面与 390px 存储检查截图；来源页无路径字段截图；中转切换被拒绝和成功反馈证据。

## Acceptance Criteria

- 全局只有“存储检查”能新增或修改文件目录。
- 来源页保存策略时保留当前 `source_dir`，不会清空或覆盖。
- 空且无活跃任务的本地中转目录可切换；反例给出中文阻塞原因且配置不变。
- 日志、资源和回收目录拒绝远程挂载；所有新路径在保存前完成权限与容量检查。
- 桌面和手机端目录卡片无横向溢出，动作与提示层级清楚。
- 定向测试、架构护栏、非 UI/UI 回归、Ruff、compileall、JS 与文档检查通过。

## Risk Analysis

- 旧 UI payload 可能把已移除输入解析为空：构建 payload 时必须回退当前配置或彻底移除目录字段。
- logger 已打开旧文件句柄：保存日志路径后需明确“下次服务启动生效”或安全重建 logger，禁止假装即时切换。
- 中转目录里可能存在非任务文件：任何非空都保守阻止，用户确认清理后再切换。
- 多片库同盘关系只能作为建议，不能自动推断最佳盘或替用户移动数据。
