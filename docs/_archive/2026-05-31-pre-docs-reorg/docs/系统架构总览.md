# 影音库AI智能整理 — 系统架构总览

> 本文档是项目的主入口文档，通过章节链接到各功能模块的独立技术文档。

## 1. 项目简介

影音库AI智能整理运行在飞牛 fnOS NAS 设备上，自动完成影视文件的识别、刮削、分类和入库。核心流程：

```
源目录扫描 → 文件复制到中转 → AI+TMDB刮削 → 置信度计算 → 人工确认(可选) → 分类入库 → 通知
```

**技术栈**：Python 3 + SQLite + 原生 HTTP API + 原生 JS 前端

**部署方式**：fnOS .fpk 应用包，通过飞牛应用中心安装

**pipeline ↔ storage**：文件操作全链路

**pipeline ↔ core/safety**：安全操作
- `move_to_recycle()`：替代直接删除，移入回收站

**api ↔ core**：配置和任务操作
- `load_config()`/`save_config_section()`：配置读写
- `get_task()`/`list_tasks()`/`retry_task()`：任务查询和操作

## 3. 核心流程

### 3.1 文件流转路径

```
源目录(source) ──复制──→ 中转目录(temp) ──移动──→ 入库目录(import)
     │                      │                        │
     │                      │                        ├→ 电影/{title} ({year})/{title} ({year}).{ext}
     │                      │                        └→ 电视剧/{title} ({year})/Season {s}/{title} - S{s}E{e}.{ext}
     │                      │
     │                      ├──→ 验证通过 ──────────────→ 分类→去重→重命名→入库 ──→ SUCCESS
     │                      │                                                  │
     │                      │                                                  └→ 源文件清理:
     │                      │                                                       cleanup_source_after_done=true → 移入回收站
     │                      │                                                       cleanup_source_after_done=false → 保留源目录
     │                      │
     │                      ├──→ 需确认(CONFIRMING) ──→ 文件停留在临时区，等待用户决策
     │                      │                           ├── 确认入库 → 继续入库流程 → SUCCESS
     │                      │                           ├── 重分类 → 修改维度→重新匹配规则→入库
     │                      │                           ├── 重命名源文件 → 重新刮削
     │                      │                           └── 忽略 → 临时文件直接删除，任务SKIPPED
     │                      │                                    源文件保留在源目录不动
     │                      │
     │                      └──→ 失败(FAILED) ──→ 临时文件直接删除
     │                                                源文件保留在源目录，等待用户决策
     │                                                ├── 重试 → 从源文件重新走流程
     │                                                └── 忽略 → 源文件按 cleanup_source_after_done 配置处理
     │                                                          cleanup_source_after_done=true → 移入回收站
     │                                                          cleanup_source_after_done=false → 保留源目录
     │
     └── 入库去重替换 ──→ 原文件移入回收站(recycle) ← 被替换的旧版本文件
         (高清替换场景: 新任务入库时，quality策略判定新文件更优，
          原入库文件移入回收站，新文件替换入库)

删除任务(非PROCESSING均可删除):
  删除时提示用户是否删除任务关联文件
  ├── 选择删除文件 → 关联文件移入回收站（不直接删除）
  │     ├── file_location=source → 源文件移入回收站
  │     ├── file_location=temp   → 临时文件移入回收站
  │     ├── file_location=import → 入库文件移入回收站
  │     └── file_location=recycle → 回收站文件保留不动
  └── 选择保留文件 → 仅删除任务记录，文件不动

回收站(recycle):
  ├── 入库成功后清理的源文件（cleanup_source_after_done=true）
  ├── 处理失败被忽略的源文件（cleanup_source_after_done=true）
  ├── 被去重替换的旧版本文件（高清替换场景）
  ├── 删除任务时选择删除的关联文件
  └── 过期自动清理 → recycle_retention_days 配置保留天数，超期后真正删除
```

**关键设计原则**：

1. **临时区是工作区，不是存储区**：临时文件是处理过程中的副本，失败或忽略时直接删除，不进回收站
2. **源目录始终保留原始文件**：直到任务完成（cleanup_source_after_done=true 移入回收站）或用户主动操作（忽略/删除任务）；FAILED 状态源文件保留不动
3. **回收站是唯一的安全出口**：所有需要移除的源文件/入库文件都先进入回收站，不直接删除，确保可恢复
4. **高清替换是新任务**：用户新入同文件的高清版本时，系统创建新任务，入库时通过去重策略替换原文件
5. **删除任务保护文件**：删除任务时关联文件移入回收站而非直接删除，用户可选择保留文件仅删记录
6. **回收站有过期机制**：recycle_retention_days 配置保留天数，超期文件自动真正删除，避免回收站无限膨胀

### 3.3 核心业务流

**文件入库业务流**：

```
用户触发/文件监控 → 扫描源目录 → 源端去重检测 → 创建任务 → 复制到中转
→ AI+Provider刮削 → 置信度判定 → [自动入库 | 人工确认 | 失败处理]
→ 分类匹配路径 → 入库去重 → 移动入库 → 清理源文件 → 通知
```

**源端去重业务流**（六大场景）：

| 场景 | 检测方式 | 动作 | 处理 |
|------|---------|------|------|
| 新文件 | 路径+指纹均无历史 | CREATE | 正常创建任务 |
| 已处理无变化 | 路径匹配+指纹相同 | SKIP | 更新 last_seen_at |
| 仅 mtime 变 | 路径匹配+指纹不同+size不变 | UPDATE_MTIME | 更新指纹，跳过 |
| 内容变更 | 路径匹配+指纹不同+size变 | REPROCESS | 创建新任务 |
| 文件改名 | 路径无历史+指纹匹配 | RENAME_DETECTED | 更新路径引用 |
| 源文件删除 | 扫描不到 | — | 保留历史记录 |

**回收站业务流**：

```
文件删除/覆盖请求 → move_to_recycle() → 日期子目录 + 来源区域分离
  → .meta 侧车文件记录来源信息 → 文件可恢复

回收站浏览 → list_recycle_dir() → 解析 .meta/.dir.meta → 返回文件列表+分区统计
回收站恢复 → restore_from_recycle() → 读取 .meta 获取原位置 → 移回原位置（冲突处理）
回收站永久删除 → delete_from_recycle() → 直接删除文件/目录+元信息
```

**源目录清理器业务流**：

```
定时触发(cron)/手动触发 → 扫描源目录 → 排除已关联任务的文件
  → 规则分类（后缀名+黑名单+垃圾视频+清理模式）
  → AI 整体分析（以目录为单位，如启用）
  → 合并策略（交集/并集）→ 最终清理列表
  → 用户确认(如开启) → 执行清理(移入回收站[清理器-源目录]分区)
  → 写入清理记录(API可查)
```

→ 数据模型详见 [数据模型](架构/数据模型.md)

### 3.4 10 步流水线

| 步骤 | 名称 | 进度 | 说明 |
|------|------|------|------|
| 1 | scan | 0-5% | 扫描源目录，发现视频文件 |
| 2 | copy | 5-20% | 复制到中转目录（断点续传） |
| 3 | scrape | 20-50% | AI+Provider 刮削元数据 |
| 4 | validate | 50-55% | 校验刮削结果完整性 |
| 5 | dedup | 55-60% | 入库去重检查 |
| 6 | classify | 60-65% | 维度→路径规则匹配 |
| 7 | confirm | 65-70% | 置信度判定（自动/需确认/需审核） |
| 8 | import | 70-90% | 搬运到入库目录，按 cleanup_source_after_done 清理源文件 |
| 9 | notify | 90-95% | 发送通知 |
| 10 | cleanup | 95-100% | 清理临时文件 |

**4 业务状态模型**：流水线步骤中任务的状态对外呈现为 4 个业务状态，内部技术状态作为子状态：

| 业务状态 | 技术状态（子状态） | 含义 |
|---------|-------------------|------|
| 待处理 | PENDING | 等待流水线拾取 |
| 处理中 | PROCESSING | 流水线正在执行 |
| 处理中 | CONFIRMING（子状态） | 等待用户确认后继续 |
| 失败 | FAILED | 流程中断，源文件保留在源目录等用户决策 |
| 完成 | SUCCESS | 成功入库 |
| 完成 | SKIPPED（子状态） | 跳过/忽略不入库 |

→ 详见 [流水线处理](架构/流水线处理.md)

## 4. 功能模块文档

### 4.1 刮削引擎

Provider+AI 双引擎架构，支持 TMDB 结构化数据与 LLM 智能判断的融合刮削。

- **Provider 抽象层**：`MetadataProvider` 基类 + `@register_provider` 注册表，新增刮削源只需实现子类
- **文件名清洗**：16 步正则 + AI Fallback，从混乱文件名提取标题/年份/季集
- **标题匹配**：L1~L7 七级匹配体系，精确匹配优先，模糊匹配兜底
- **维度映射**：`provider_mappings` JSON 配置，支持 genre_ids/country_codes/certification 等映射类型

→ 详见 [刮削引擎](架构/刮削引擎.md) | [置信度引擎](架构/置信度引擎.md)

### 4.2 置信度计算

搜索置信度 × 数据门控的二元判定模型：

```
final = search_conf × data_gate
search_conf = T(标题匹配) × R_dynamic(结果数惩罚)
data_gate = 全部维度来源信任 ? 1.0 : 0
```

- **TMDB+AI 模式**：Provider 有结果且 T ≥ 阈值 → `final = search_conf × data_gate`
- **纯 AI 模式**：Provider 无结果 → `final = objective_cap × data_gate`
- **判定**：PASS(≥0.8) / CONFIRMING(≥0.5) / NEEDS_REVIEW(≥0.3) / FAILED(<0.3)

→ 详见 [置信度引擎](架构/置信度引擎.md) | [confidence-engine.md](架构/confidence-engine.md)

### 4.3 文件操作

从源目录到入库目录的完整文件流转链路，包含扫描、复制、搬运、去重、分类、源目录清理。

- **安全原则**：所有删除/覆盖操作通过 `move_to_recycle()` 移入回收站，受 `core/recycle/` 子包保护（路径校验/类型白名单/来源区域分离/.meta 侧车文件）
- **去重策略**：skip(跳过) / replace(替换) / rename(重命名) / quality(质量优先)
- **分类匹配**：维度条件 → 路径模板，支持 `{title_cn}`/`{year}`/`{season}` 等变量
- **源目录清理器**：独立于任务流的自动清理功能，规则+AI 双引擎分析，合并策略可选（交集/并集）
- **回收站管理**：浏览/恢复/永久删除，按来源分区（[源目录]/[入库目录]/[清理器-源目录]/[其他]），支持目录回收

→ 详见 [文件操作](架构/文件操作.md) | [回收站管理](架构/回收站管理.md)

### 4.4 任务管理

基于 SQLite 的任务持久化，4 业务状态 + 技术子状态：

```
待处理(PENDING) → 处理中(PROCESSING/CONFIRMING) → 完成(SUCCESS/SKIPPED) / 失败(FAILED)
                        ↑                                    │
                        └──────────── retry ─────────────────┘
```

业务状态映射：

| 业务状态 | 技术状态 | 含义 |
|---------|---------|------|
| 待处理 | PENDING | 等待流水线拾取 |
| 处理中 | PROCESSING | 流水线执行中 |
| 处理中 | CONFIRMING | 等待用户确认（子状态） |
| 失败 | FAILED | 流程中断，源文件保留在源目录 |
| 完成 | SUCCESS | 成功入库 |
| 完成 | SKIPPED | 跳过/忽略不入库（子状态） |

- **目录系统**：`file_location` 追踪文件当前位置（source/temp/import/recycle/deleted）
- **确认机制**：CONFIRMING 状态的任务需人工确认后才能入库
- **失败保护**：FAILED 状态源文件保留在源目录，不自动移入回收站

→ 详见 [任务管理](架构/任务管理.md)

## 7. 配置快速参考

```yaml
source_dir: "/vol1/downloads"          # 源目录
temp_dir: "/vol2/temp"                  # 中转目录

source_policy:
  recycle_dir: "/vol2/recycle"          # 回收站目录（旧配置 quarantine_dir 自动迁移）
  cleanup_source_after_done: true       # 任务完成后是否清理源文件（移入回收站）
                                        #   true  - 入库成功后自动清理源文件
                                        #   false - 入库后保留源文件（只读模式）
  recycle_retention_days: 30            # 回收站文件保留天数，超期自动清理（0=永不过期）
  # ⚠️ 旧字段已废弃：cleanup_mode, delete_source_after_import → 自动迁移为 cleanup_source_after_done

source_cleaner:                         # 源目录清理器（独立功能，与任务流无关）
  enabled: false                        # 是否启用源目录自动清理
  cleanup_mode: "media_only"            # media_only（仅保留影视+字幕）/ media_and_related（保留影视+字幕+关联文件）
  ai_enabled: false                     # 是否启用 AI 辅助判断
  merge_strategy: "intersection"        # AI与规则合并策略：intersection（交集，保守）/ union（并集，激进）
  junk_video_max_size_mb: 50            # 视频文件小于此大小视为垃圾视频
  delete_extensions: [".url", ".log", ".txt"]   # 指定后缀名直接删除
  protect_extensions: [".nfo", ".jpg", ".png"]  # 指定后缀名保护不删
  blacklist_patterns: ["RARBG*", "*/Sample/*", "*/sample/*"]  # 文件名/路径黑名单
  cleanup_empty_dirs: true              # 清理空目录
  confirm_before_cleanup: true          # 清理前需用户确认
  schedule: "0 3 * * *"                # 定时触发（cron 格式）
  # ⚠️ 旧字段已废弃：keep_media_only → media_only, keep_media_related → media_and_related

metadata:
  providers:
    - type: tmdb
      enabled: true
      api_key: "xxx"

llm:
  provider: "openai"
  api_key: "sk-xxx"
  base_url: "https://api.openai.com/v1"
  model: "gpt-4o"

confidence:
  pass_threshold: 0.8
  confirm_threshold: 0.5
  provider_match_threshold: 0.85

server:
  port: 9855
  auth_token: "your-secret-token"
```
