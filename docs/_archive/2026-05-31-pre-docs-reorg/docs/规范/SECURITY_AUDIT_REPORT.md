## 摘要

本次为第二次安全审计（v2），在首次审计修复了 2 个严重问题的基础上，进行了更深入全面的安全审查。本次审计共发现 **5 个严重漏洞**、**8 个中等风险问题** 和 **8 个低风险问题**。

最严重的问题是 **API 完全无认证** 与 **hooks 命令注入** 的组合攻击链：攻击者可以通过未认证的配置 API 修改 hooks，进而通过 subprocess 执行任意命令，实现完整的远程代码执行（RCE）。这意味着任何网络可达的攻击者可以完全控制 NAS 设备。

**风险评级变化**：首次审计发现 2 个 P0 问题（已修复），本次审计发现 5 个 P0 问题，反映出首次审计深度不足，本次审计覆盖了 API 层、认证、注入、SSRF 等更广泛的安全维度。

## 🔴 P0 严重问题

### 1. API 完全无认证

**位置**: `api_server.py` 所有端点

**问题描述**:
所有 API 端点无任何认证机制，任何网络可达的用户可以控制整个系统。受影响的端点包括但不限于：

| 端点 | 方法 | 危险操作 |
|------|------|----------|
| `/api/run` | POST | 触发批量处理 |
| `/api/run/file` | POST | 处理指定文件 |
| `/api/config` | PUT | 修改系统配置 |
| `/api/config` | GET | 查看配置（含密钥） |
| `/api/config/reload` | POST | 重载配置 |
| `/api/tasks/{id}/retry` | POST | 重试任务 |
| `/api/queue/pause` | POST | 暂停队列 |
| `/api/queue/resume` | POST | 恢复队列 |

**风险**:
- 触发批量处理消耗系统资源
- 修改配置导致系统行为异常
- 删除文件造成数据丢失
- 查看密钥泄露敏感信息
- 与 hooks 命令注入组合可实现 RCE

**建议**:
- 添加 API Key 或 Bearer Token 认证中间件
- 所有端点默认要求认证，仅健康检查端点可豁免
- 认证 Token 通过环境变量或独立配置文件加载，不存储在主配置文件中
- 考虑支持 IP 白名单作为辅助防护

---

### 2. hooks 命令注入

**位置**: `hooks.py`

**问题描述**:
hooks 配置的 `before_process`、`after_success`、`after_failure` 字段中的命令直接通过 `subprocess` 执行，无任何过滤或沙箱机制。

**攻击场景**:
1. 攻击者通过未认证的 `PUT /api/config` 修改 hooks 配置
2. 在 `before_process` 中注入恶意命令，如 `rm -rf /important/data`
3. 触发文件处理，hooks 自动执行恶意命令

**风险**: 远程代码执行（RCE），完全控制 NAS 设备

**建议**:
- 限制可执行命令的白名单（如仅允许特定目录下的脚本）
- 禁止通过 API 修改 hooks 配置
- 使用 shell=False 并限制可执行文件路径
- 添加 hooks 命令执行日志审计

---

### 3. 配置 API 可修改 hooks 导致 RCE

**位置**: `api_server.py` `_config_update`

**问题描述**:
`PUT /api/config` 允许修改任意配置项，包括 hooks。结合问题 #1（无认证）和问题 #2（hooks 命令注入），形成完整的 RCE 攻击链：

```
未认证 API → 修改 hooks 配置 → 触发处理 → subprocess 执行恶意命令
```

**攻击复杂度**: 低（仅需发送 HTTP 请求）
**攻击前提**: 网络可达
**影响**: 完全远程代码执行

**建议**:
- 配置更新时过滤掉 `hooks` 字段，禁止通过 API 修改
- 或要求二次确认（如输入管理员密码）才能修改敏感配置项
- 敏感配置项（hooks、credentials、URLs）应标记为不可通过 API 修改

---

### 4. 文件路径 API 未严格校验

**位置**: `api_server.py` `_run_file`

**问题描述**:
`POST /api/run/file` 接受用户提供的文件路径参数，虽然代码中有 `source_dir` 前缀检查，但可能被 `../` 路径穿越绕过。

**攻击示例**:
```
POST /api/run/file
{"file_path": "/media/../../../etc/passwd"}
```

如果前缀检查使用字符串匹配而非路径规范化比较，攻击者可以构造穿越路径绕过限制。

**建议**:
- 使用 `safety.py` 的 `validate_path_safety()` 做严格校验
- 对用户输入的路径先做 `os.path.realpath()` 规范化
- 规范化后的路径必须以 `source_dir` 的规范化路径为前缀
- 拒绝包含 `..` 的原始路径输入

---

### 5. 密钥通过 API 可读取

**位置**: `api_server.py` `_config_get`

**问题描述**:
`GET /api/config` 返回配置时虽然对密钥做了掩码处理，但掩码格式泄露了密钥的前缀和后缀字符。例如 `sk-c***pQf8` 泄露了：
- 前缀 `sk-c`：标识密钥类型和起始字符
- 后缀 `pQf8`：4 个已知字符

**风险**:
- 前缀泄露可用于推断密钥提供商和格式
- 前后缀组合大幅缩小了暴力破解的搜索空间
- 对于短密钥，已知前后缀可能直接还原

**建议**:
- 掩码应只显示 `sk-***`，不泄露前后缀字符
- 或统一显示为 `***REDACTED***`
- 敏感字段列表应覆盖所有 API Key、Secret、Token、Password 类配置

## 🟡 P1 中等问题

### 6. SSRF 风险 - LLM base_url 可修改

**位置**: `api_server.py` 配置更新

**问题描述**:
通过 `PUT /api/config` 可修改 `llm.base_url` 为内网地址（如 `http://192.168.1.1`、`http://169.254.169.254`），导致服务端发起请求到内网资源。

**风险**:
- 探测内网服务
- 访问云环境元数据接口（169.254.169.254）
- 攻击内网其他服务

**建议**:
- 验证 `base_url` 不指向私有 IP 地址段（RFC 1918）
- 阻止指向 `169.254.0.0/16`、`127.0.0.0/8`、`::1` 等特殊地址
- DNS 解析后再次验证 IP 地址

---

### 7. SSRF 风险 - Hermes base_url 可修改

**位置**: `api_server.py` 配置更新

**问题描述**:
同问题 #6，`hermes.webhook.base_url` 也可被修改为内网地址，导致 SSRF。

**建议**: 同问题 #6

### 8. 日志注入

**位置**: `pipeline.py` `_log`、`logger.py`

**问题描述**:
日志消息中包含 AI 返回的内容和文件名，这些内容可能包含控制字符或 ANSI 转义序列。攻击者可以通过构造特殊文件名或利用 AI 返回恶意内容来注入日志。

**攻击示例**:
- 文件名包含 ANSI 转义序列：`\033[31m FAKE ERROR \033[0m`
- 文件名包含换行符伪造日志条目：`file.txt\n[ERROR] System compromised`
- 控制字符干扰日志分析工具

**建议**:
- 过滤日志消息中的控制字符（ASCII 0-31, 127）
- 剥离 ANSI 转义序列
- 对文件名进行清洗后再写入日志

---

### 9. 任务 ID 可预测

**位置**: `task_manager.py`

**问题描述**:
任务 ID 使用短哈希生成，可能被暴力枚举。攻击者可以通过遍历任务 ID 查看其他任务的处理结果和文件信息。

**风险**:
- 信息泄露：查看其他用户的任务详情
- 竞争条件：对他人任务执行重试/取消操作

**建议**:
- 使用 UUID4 生成任务 ID（128 位随机数，不可预测）
- 或使用加密安全的随机数生成器

---

### 10. CORS 未配置

**位置**: `api_server.py`

**问题描述**:
未配置 CORS（跨域资源共享）策略，任何网站都可以通过浏览器向 API 发起跨域请求。

**攻击场景**:
1. 用户访问恶意网站
2. 恶意网站的 JavaScript 向 NAS API 发起请求
3. 由于无 CORS 限制，浏览器允许请求发送
4. 攻击者利用用户网络位置控制 NAS

**建议**:
- 添加 CORS 头，限制允许的来源
- 仅允许来自 NAS 本机或可信域名的请求
- 对于 API 端点，设置 `Access-Control-Allow-Origin` 为白名单域名

---

### 11. 配置文件权限

**位置**: `config_loader.py`

**问题描述**:
未检查配置文件的文件系统权限。API 密钥等敏感信息以明文存储在 `config.yaml` 中，如果文件权限过于宽松（如 644），同一 NAS 上的其他用户或服务可以读取密钥。

**建议**:
- 启动时检查配置文件权限，建议 600（仅所有者可读写）
- 如果权限过于宽松，输出警告日志
- 考虑在部署脚本中自动设置权限

---

### 12. 缺少速率限制

**位置**: `api_server.py`

**问题描述**:
无请求频率限制，API 可被高频访问导致：
- DoS 攻击：大量请求耗尽系统资源
- 暴力破解：遍历任务 ID 或尝试不同参数
- 资源滥用：频繁触发文件处理消耗 CPU/IO

**建议**:
- 添加简单的速率限制（如每 IP 每分钟 60 次请求）
- 对写操作（POST/PUT）设置更严格的限制
- 可使用令牌桶或滑动窗口算法

---

### 13. Webhook Secret 明文存储

**位置**: `config.yaml`

**问题描述**:
Hermes HMAC 密钥以明文存储在配置文件中。任何能读取配置文件的人都可以伪造 Webhook 请求。

**建议**:
- 支持从环境变量读取密钥（如 `HERMES_WEBHOOK_SECRET`）
- 配置文件中可使用 `${ENV_VAR}` 语法引用环境变量
- 优先使用环境变量值，配置文件值作为备选

## 🟢 P2 低风险

### 14. remove_empty_parent_dir 递归删除

**位置**: `file_mover.py`

**问题描述**:
`remove_empty_parent_dir` 递归向上删除空目录。虽然已有限制在 `source_dir` 内的基本安全检查，但应增加更多安全防护。

**当前状态**: ⚠️ 已有基本安全检查（限制在 source_dir 内）

**建议**:
- 增加最大递归深度限制
- 在每次删除前验证路径仍在允许范围内
- 记录每次目录删除操作到审计日志

---

### 15. LLM 响应验证不充分

**位置**: `llm_scraper.py`

**问题描述**:
AI 返回的元数据（标题、年份等）可能包含特殊字符，在后续文件操作中造成风险。例如：
- 标题包含路径分隔符 `/` 或 `\`
- 年份包含非数字字符
- 标题包含空字节或控制字符

**建议**:
- 对 AI 返回值进行更严格的清洗和验证
- 标题：移除路径分隔符和控制字符
- 年份：验证为 4 位数字
- 所有字段：限制最大长度

---

### 16. 临时文件清理

**位置**: `pipeline.py`

**问题描述**:
处理失败时临时文件可能残留在临时目录中，长期运行可能导致磁盘空间耗尽。

**建议**:
- 增加启动时清理临时目录的逻辑
- 使用 `tempfile` 模块创建临时文件，利用系统自动清理机制
- 添加定期清理任务

---

### 17. 错误信息泄露

**位置**: `api_server.py` 多个端点

**问题描述**:
错误响应中包含内部实现细节，如文件路径、异常堆栈、数据库错误等。这些信息可帮助攻击者了解系统内部结构。

**建议**:
- 生产环境返回通用错误信息（如 "Internal Server Error"）
- 详细错误信息仅写入服务端日志
- 区分开发模式和生产模式的错误详细程度

---

### 18. 前端 XSS 风险

**位置**: `webui/app.js`

**问题描述**:
`refreshLogs` 函数使用 `innerHTML` 拼接 HTML 内容。虽然已有 `escapeHtml` 函数进行转义，但 `innerHTML` 本身仍存在风险：
- 如果 `escapeHtml` 实现有缺陷，可能导致 XSS
- 未来维护者可能遗忘调用 `escapeHtml`
- 浏览器对 `innerHTML` 的解析可能触发意外行为

**建议**:
- 使用 `textContent` 或 DOM API 创建元素
- 或使用安全的模板库
- 添加 CSP（Content-Security-Policy）头作为纵深防御

---

### 19. 前端无 CSRF 防护

**位置**: `webui/`

**问题描述**:
前端请求无 CSRF Token 保护。虽然当前 API 无认证（因此 CSRF 意义有限），但在添加认证后 CSRF 防护将变得重要。

**建议**:
- 添加 CSRF Token（在添加认证后实施）
- 或使用 SameSite Cookie 属性
- 对状态修改操作（POST/PUT/DELETE）验证 CSRF Token

---

### 20. 日志缓冲区无大小限制的内存风险

**位置**: `logger.py`

**问题描述**:
内存日志缓冲区固定 500 条，大量日志时可能占用较多内存。

**当前状态**: ⚠️ 已有 `maxlen` 限制，风险较低

**建议**:
- 当前 `maxlen=500` 的限制已基本足够
- 如果单条日志很长，可考虑限制单条日志的最大长度

---

### 21. 文件附属文件删除逻辑

**位置**: `file_mover.py` `find_companion_files`

**问题描述**:
附属文件匹配基于文件名前缀，可能误删不相关的文件。例如，文件 `Movie.2024.mkv` 的附属文件匹配可能误匹配到 `Movie.2024.Part2.mkv` 等不相关文件。

**建议**:
- 增加更精确的匹配规则（如完全匹配文件名主体部分）
- 列出待删除的附属文件前进行确认
- 限制附属文件的扩展名范围

## 🔗 攻击链分析

### 攻击链 1：RCE 完整利用链

```
[攻击者] --HTTP--> [PUT /api/config] --修改hooks--> [触发文件处理]
    ↓                                                   ↓
  无认证                                          subprocess 执行
    ↓                                                   ↓
  任意配置修改                                    远程代码执行 (RCE)
```

**严重程度**: 🔴 Critical
**攻击复杂度**: 低
**所需权限**: 无
**用户交互**: 无

### 攻击链 2：信息泄露链

```
[攻击者] --HTTP--> [GET /api/config] --读取密钥--> [密钥前缀+后缀]
    ↓                                                   ↓
  无认证                                          缩小暴力破解空间
    ↓                                                   ↓
  CORS缺失                                        跨域攻击窃取配置
```

**严重程度**: 🔴 High
**攻击复杂度**: 低

### 攻击链 3：SSRF 探测链

```
[攻击者] --HTTP--> [PUT /api/config] --修改base_url--> [内网地址]
    ↓                                                     ↓
  无认证                                            服务端请求伪造
    ↓                                                     ↓
  修改LLM/Hermes URL                               探测内网/云元数据
```

**严重程度**: 🟡 Medium-High
