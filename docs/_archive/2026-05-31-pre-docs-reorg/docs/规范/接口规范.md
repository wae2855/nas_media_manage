# 接口规范

> 对应源码路径：`media_importer/api/`
> 关联文档：[API服务.md](../架构/API服务.md)

---

## 1. 概述

影音库AI智能整理的 API 层基于 Python 标准库 `http.server` 构建，采用 Mixin 组合模式将不同功能域的处理器解耦，通过 `ThreadingHTTPServer` 支持并发请求。

设计原则：

- **统一响应**：所有端点返回一致的 JSON 结构，前端无需针对不同端点适配响应格式
- **功能分组**：按 Mixin 拆分处理器（Task / Config / Dimension / Prompt / Provider），路由集中分发
- **安全优先**：敏感信息脱敏返回、路径安全校验、Bearer Token 认证
- **无构建依赖**：原生 Python 标准库实现，适配 NAS 轻量环境

## 2. 通用规范

### 2.1 URL 规则

- 所有 API 路径以 `/api/` 为前缀
- 路径参数使用 URL 段式：`/api/tasks/{id}/retry`，不使用查询字符串传递资源标识
- 集合资源用复数名词：`/api/tasks`、`/api/dimensions`、`/api/providers`
- 子资源用嵌套路径：`/api/tasks/{id}/subtitles`、`/api/providers/{type}/genres`
- 静态文件路径（`/`、`/css/*`、`/js/*`）不属于 API 范围，由 `StaticServerMixin` 单独处理

### 2.2 HTTP 方法语义

| 方法 | 语义 | 请求体 | 幂等性 |
|------|------|--------|--------|
| GET | 查询资源 | 无 | 幂等 |
| POST | 创建/触发操作/状态变更 | JSON | 非幂等 |
| PUT | 全量更新资源 | JSON | 幂等 |
| DELETE | 删除资源 | 无 | 幂等 |

> **注意**：本系统中部分 POST 端点用于触发操作（如 `/api/run`、`/api/tasks/{id}/retry`），属于命令式用法而非 RESTful 资源创建。同一 POST 端点根据路径段区分不同操作（如 `/api/tasks/{id}/retry` vs `/api/tasks/{id}/confirm`）。

### 2.3 认证机制

系统采用 Bearer Token 认证：

- 请求头：`Authorization: Bearer <api_key>`
- Token 值来自配置文件 `server.api_key`
- `/api/health` 免认证
- `server.api_key` 为空时跳过认证（所有请求放行）

认证流程：

```
请求到达 → 路径是否为 /api/health → 是 → 跳过认证
                                  → 否 → api_key 是否配置
                                          → 未配置 → 放行
                                          → 已配置 → 校验 Authorization 头
                                                    → 通过 → 继续处理
                                                    → 失败 → 返回 401
```

认证失败响应：

```json
{
  "code": 401,
  "status": "unauthorized",
  "message": "认证失败：请提供有效的 API Key",
  "data": null
}
```

### 2.4 统一响应格式

所有 API 端点返回统一的 JSON 结构：

```json
{
  "code": 200,
  "status": "success",
  "message": "操作描述",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | int | HTTP 状态码 |
| `status` | string | 状态标识 |
| `message` | string | 人类可读的操作结果描述 |
| `data` | object / null / array | 业务数据载荷 |

`status` 取值映射：

| HTTP 状态码 | status 值 | 说明 |
|-------------|-----------|------|
| 200 | `success` | 操作成功 |
| 201 | `created` | 资源创建成功 |
| 202 | `success` | 异步操作已接受 |
| 400 | `bad_request` | 请求参数错误 |
| 401 | `unauthorized` | 认证失败 |
| 403 | `bad_request` | 操作被禁止 |
| 404 | `not_found` | 资源不存在 |
| 500 | `internal_error` | 服务器内部错误 |
| 503 | `internal_error` | 外部服务不可用 |

> `status` 字段优先使用 `json_response` 的 `code_str` 参数显式指定；未指定时按状态码自动映射。

### 2.5 错误码定义

| 状态码 | 含义 | 典型场景 |
|--------|------|----------|
| 200 | 成功 | 查询、更新操作 |
| 202 | 已接受 | 异步操作（批量处理、单文件处理） |
| 400 | 请求错误 | 参数缺失、状态不允许操作 |
| 401 | 未认证 | API Key 缺失或错误 |
| 404 | 未找到 | 资源不存在、路径不匹配 |
| 500 | 服务器错误 | 内部异常 |
| 503 | 服务不可用 | 外部 API 调用失败 |

### 2.6 分页规范

`GET /api/tasks` 支持分页查询，参数如下：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `page` | int | 1 | 页码 |
| `limit` / `page_size` | int | 20 | 每页数量 |
| `offset` | int | 0 | 偏移量（与 page 二选一） |
| `status` | string | 全部 | 状态筛选 |
| `format` | string | json | 输出格式（json / text） |

分页响应结构：

```json
{
  "code": 200,
  "status": "success",
  "data": {
    "tasks": [],
    "total": 100,
    "page": 1,
    "page_size": 20,
    "active_count": 5
  }
}
```

### 2.7 请求体格式

POST / PUT 请求使用 JSON 格式，通过 `read_json_body` 解析。解析失败时返回空字典 `{}`，不抛出异常。

## 3. 任务管理接口

任务端点由 `TaskHandlersMixin` 实现，覆盖任务全生命周期。

### 3.1 任务查询

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/tasks` | 任务列表（分页 + 筛选） |
| GET | `/api/tasks/stats` | 任务统计 |
| GET | `/api/tasks/{id}` | 任务详情 |
| GET | `/api/tasks/{id}/subtitles` | 任务字幕列表 |

### 3.2 任务操作

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/tasks/{id}/retry` | 重试任务 |
| POST | `/api/tasks/{id}/confirm` | 确认入库（CONFIRMING → SUCCESS） |
| POST | `/api/tasks/{id}/reclassify` | 重新分类（携带 dimensions 参数） |
| POST | `/api/tasks/{id}/ignore` | 忽略任务 |
| POST | `/api/tasks/{id}/rename` | 重命名文件 |
| POST | `/api/tasks/{id}/delete` | 删除任务（可选删除文件，`delete_files: true`） |
| DELETE | `/api/tasks/{id}` | 删除任务（仅 DB 记录，不删文件） |

> **POST vs DELETE 删除**：POST `/api/tasks/{id}/delete` 支持通过 `delete_files` 参数同时删除文件；DELETE `/api/tasks/{id}` 仅移除数据库记录。

### 3.3 批量操作

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/tasks/clear` | 清空任务 |
| POST | `/api/tasks/confirm-all` | 批量确认所有待确认任务 |

### 3.4 处理触发

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/run` | 触发批量处理（异步，返回 202） |
| POST | `/api/run/file` | 处理指定文件（异步，返回 202） |

### 3.5 任务状态约束

任务操作受状态机约束，非法状态跳转返回 400：

- `retry`：仅 FAILED / SKIPPED 任务可重试
- `confirm`：仅 CONFIRMING 任务可确认
- `reclassify`：仅 CONFIRMING / NEEDS_REVIEW 任务可重新分类
- `ignore`：大部分状态可忽略，根据 `file_location` 决定是否移动/删除临时文件

## 4. 配置管理接口

配置端点由 `ConfigHandlersMixin` 和 `PromptHandlersMixin` 实现。

### 4.1 配置读取

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/config` | 获取当前配置（脱敏） |
| GET | `/api/config/validate` | 配置完整性验证 |
| GET | `/api/config/prompts` | 获取提示词内容 |

### 4.2 配置写入

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/config` | 保存完整配置 |
| POST | `/api/config/section` | 保存配置区块 |
| POST | `/api/config/reload` | 重载配置（从磁盘重新读取） |
| POST | `/api/config/prompts` | 保存提示词 |
| POST | `/api/config/prompts/reset` | 重置提示词为默认值 |

### 4.3 配置区块

`POST /api/config/section` 支持部分保存，请求体格式：

```json
{
  "section": "llm",
  "data": { "llm": { "provider": "openai", "model": "gpt-4" } }
}
```

支持的 section 值：`basic`、`path_rules`、`import_options`、`metadata.providers`、`llm`、`server`、`hermes`、`file_watcher`、`advanced`、`confidence`

### 4.4 连通性测试

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/config/test-llm` | 测试 LLM 连通性 |
| POST | `/api/config/test-hermes` | 测试 Hermes 通知 |
| POST | `/api/config/check-permission` | 检查路径权限 |
| POST | `/api/path/test` | 测试单个路径权限 |

### 4.5 配置热重载

配置保存后根据运行状态决定同步时机：

```
保存配置 → 有运行中任务 → 设置 _config_dirty=True → 写入文件 → 等待任务完成后自动同步
        → 无运行中任务 → 写入文件 → 立即更新内存配置 → 按需重启文件监控
```

### 4.6 YAML 保存策略

- 使用 `ruamel.yaml` 保持原始格式（注释、引号风格）
- 嵌套更新采用 `update_nested` 递归合并，不破坏未修改的配置结构
- 自动为 YAML 保留字（true/false/yes/no/null 等）和含特殊字符的值添加引号

## 5. 刮削与 Provider 接口

Provider 端点由 `ProviderHandlersMixin` 实现，刮削预览由 `ConfigHandlersMixin` 实现。

### 5.1 Provider 查询

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/providers` | Provider 列表 |
| GET | `/api/providers/{type}/genres` | Provider 类型列表 |
| GET | `/api/providers/{type}/prompts` | Provider 提示词 |

### 5.2 Provider 操作

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/providers/{type}/test` | 测试 Provider 连通性 |
| POST | `/api/providers/{type}/preview` | Provider 元数据预览 |
| POST | `/api/providers/{type}/search` | Provider 搜索 |
| POST | `/api/providers/{type}/details` | Provider 详情 |
| POST | `/api/providers/{type}/prompts` | 保存 Provider 提示词 |
| POST | `/api/providers/{type}/prompts/reset` | 重置 Provider 提示词 |

### 5.3 刮削预览

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/scrape/preview` | 刮削预览（AI + Provider 并行） |

刮削预览使用 `ThreadPoolExecutor` 并行执行两种刮削：

1. **纯 AI 刮削**：直接调用 `LLMScraper.scrape`
2. **Provider+AI 刮削**：调用 `MetadataScraper.scrape`（先查 Provider API，再用 AI 整理）

两者并行执行，超时时间 60 秒，结果合并返回供前端对比展示。

## 8. 安全规范

### 8.1 敏感信息处理

配置接口对敏感字段实施三层防护：

| 阶段 | 处理方式 | 实现函数 |
|------|----------|----------|
| 读取 | 将 `api_key`、`secret` 等字段替换为 `***` | `mask_sensitive` |
| 保存 | 值为 `***` 的字段不覆盖原始值 | `_update_config_safely` |
| 写入 | 写入 YAML 前移除脱敏字段，避免 `***` 写入配置文件 | `_filter_sensitive_fields` |

脱敏规则：

- `api_key` → `***`
- `llm.api_key` → `sk-***`（保留前缀便于识别类型）
- `secret` → `***`

连通性测试需要真实密钥时，通过 `_get_real_config_value` 从内存配置或磁盘文件中读取真实值。

### 8.2 路径安全校验

所有涉及文件路径的接口（配置保存、路径权限检查、任务操作）必须经过安全校验：

- 静态文件服务：通过 `os.path.realpath` 解析真实路径，校验是否在 `WEBUI_DIR` 内，防止 `../` 路径穿越
- 配置路径：通过 `core/safety` 模块校验路径合法性和写入权限
- 任务文件操作：校验文件路径在允许的目录范围内

### 8.3 认证失败处理

- 认证失败返回 401 状态码和 `unauthorized` 状态标识
- 不区分"Token 缺失"和"Token 错误"，统一返回相同错误信息，防止信息泄露
- 免认证端点仅 `/api/health` 一个

## 9. 新增端点规范

新增 API 端点时必须遵守以下规则：

### 9.1 代码层面

1. **路由注册**：在 `handler.py` 的 `do_GET` / `do_POST` / `do_PUT` / `do_DELETE` 方法中添加路径匹配
2. **处理逻辑**：在对应功能域的 Mixin 文件中实现处理方法
   - 任务相关 → `task_handlers.py`
   - 配置相关 → `config_handlers.py`
   - 维度相关 → `dimension_handlers.py`
   - 提示词相关 → `prompt_handlers.py`
   - Provider 相关 → `provider_handlers.py`
3. **响应格式**：统一使用 `json_response(handler, code, data, message, code_str)` 返回
4. **请求解析**：使用 `read_json_body(handler)` 解析请求体，不直接操作 `rfile`
5. **认证检查**：所有 `/api/` 路径自动经过认证（`/api/health` 除外），无需在 Mixin 中重复检查

### 9.2 文档层面

新增端点后必须同步更新：

1. **本规范文档**（`docs/规范/接口规范.md`）：在对应功能分组中添加端点条目
2. **架构文档**（`docs/架构/API服务.md`）：在路由表中添加路径、处理方法、所属 Mixin
3. **前端代码**：如涉及前端交互，需同步更新对应 JS 模块

### 9.3 命名约定

- 路由路径使用小写 + 连字符：`/api/config/test-llm`、`/api/tasks/confirm-all`
- Mixin 方法使用下划线前缀：`_task_confirm`、`_config_save_section`
- 路径参数使用花括号标记：`/api/tasks/{id}`、`/api/providers/{type}`
