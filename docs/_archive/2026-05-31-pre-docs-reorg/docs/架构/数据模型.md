# 数据模型

> 对应源码路径：
> - `media_importer/core/db/constants.py` — DDL 定义、默认维度、有效状态常量
> - `media_importer/core/db/connection.py` — 数据库初始化与 Schema 迁移
> - `media_importer/core/db/task_repo.py` — 任务 CRUD 数据访问层
> - `media_importer/core/db/subtitle_repo.py` — 字幕 CRUD 数据访问层
> - `media_importer/core/db/dimension_repo.py` — 维度 CRUD 数据访问层
> - `media_importer/core/safety.py` — 文件指纹计算（make_fingerprint）

---

## 1. 概述

影音库AI智能整理的数据模型围绕三个核心实体设计：**任务（tasks）**、**字幕（task_subtitles）**、**维度（dimensions）**。设计原则如下：

| 原则 | 说明 |
|------|------|
| 轻量存储 | SQLite 单文件数据库，零运维，适配 NAS 环境 |
| JSON 灵活字段 | 刮削结果、维度判定等非结构化数据使用 JSON TEXT 存储，避免频繁 Schema 变更 |
| 指纹去重 | 基于 size+mtime 的 SHA256 指纹，检测文件改名和内容变更 |
| 状态机约束 | 任务状态和文件位置严格按状态机流转，不允许非法跳转 |
| 向后兼容 | Schema 迁移自动执行，历史状态/字段自动合并修正 |

## 3. tasks 表

tasks 表是系统核心表，记录每个视频文件从扫描到入库的全生命周期数据。

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `id` | INTEGER | AUTOINCREMENT | 自增主键 |
| `task_id` | TEXT | - | 12 位 UUID hex，任务唯一标识，UNIQUE 约束 |

| 字段 | 类型 | 默认值 | 说明 |

| `source_path` | TEXT | - | 源文件完整路径 |

## 7. 枚举值定义

### 7.1 status 状态值及流转

**有效状态**：

```python
VALID_STATUSES = ["PENDING", "PROCESSING", "SUCCESS", "FAILED", "SKIPPED", "CONFIRMING"]
```

**状态含义**：

| 状态 | 含义 |
|------|------|
| PENDING | 待处理，任务已创建等待流水线执行 |
| PROCESSING | 处理中，流水线正在执行 |
| SUCCESS | 入库成功 |
| FAILED | 处理失败 |
| SKIPPED | 跳过（同名/质量优先保留） |
| CONFIRMING | 待确认，置信度不足需人工审核 |

**状态流转规则**：

| 当前状态 | 触发条件 | 目标状态 | 说明 |
|----------|----------|----------|------|
| - | 创建任务 | PENDING | 初始状态 |
| PENDING | process_one 开始 | PROCESSING | 开始处理 |
| PROCESSING | 流水线全部完成 | SUCCESS | 入库成功 |
| PROCESSING | PipelineError 异常 | FAILED | 处理失败 |
| PROCESSING | PipelineSkipError 异常 | SKIPPED | 跳过 |
| PROCESSING | _needs_confirm 标记 | CONFIRMING | 需人工确认 |
| PROCESSING | manual_review 启用 | CONFIRMING | 人工检查模式 |
| CONFIRMING | confirm_task | SUCCESS | 确认入库 |
| CONFIRMING | reclassify_task | PROCESSING → SUCCESS/FAILED/SKIPPED | 重新分类后继续 |
| FAILED | retry_task | PENDING | 重试（retry_count +1） |
| SKIPPED | retry_task | PENDING | 重试（retry_count +1） |

**历史状态合并**（Schema 迁移自动执行）：

| 旧状态 | 新状态 | 原因 |
|--------|--------|------|
| NEEDS_REVIEW | FAILED | 审核需求通过 CONFIRMING 处理 |
| ROLLBACK | FAILED | 回退视为失败，可重试 |
| DUPLICATE_REVIEW | SKIPPED | 重复审核跳过 |

### 7.2 file_location 值及流转

| 值 | 含义 |
|----|------|
| source | 文件在源目录 |
| temp | 文件在中转目录 |
| import | 文件已入库 |
| recycle | 文件在回收站 |
| deleted | 文件已删除（历史兼容） |

**流转路径**：

```
  source ──── copy步骤 ────→ temp ──── import步骤 ────→ import
    │                          │
    │                          │ 失败/跳过
    │                          ▼
    │                      (清理temp)
    │
    │ 失败/跳过(源目录文件)
    └──── move_to_recycle ──→ recycle

  source ──── 成功后清理 ────→ deleted
```

**file_location 与状态的对应关系**：

| file_location | 典型状态 | 说明 |
|---------------|----------|------|
| source | PENDING | 任务刚创建，文件在源目录 |
| temp | PROCESSING / CONFIRMING | 文件已复制到中转目录 |
| import | SUCCESS | 文件已入库到目标目录 |
| recycle | FAILED / SKIPPED | 文件被移入回收站 |
| deleted | SKIPPED | 源文件已清理 |

### 7.3 confirm_status 值

| 值 | 含义 |
|----|------|
| NONE | 无需确认或未进入确认流程 |
| PENDING | 待确认，任务进入 CONFIRMING 状态时设置 |
| CONFIRMED | 已确认，人工确认入库后设置 |

### 7.4 source_type 值

| 值 | 含义 | 说明 |
|----|------|------|
| ai | 仅 AI 判定 | 维度值由 LLM 刮削结果确定 |
| ai+provider | AI + 提供者 | 优先使用 TMDB 等提供者数据，AI 作为回退 |
| file | 文件信息 | 从文件本身提取（如分辨率从视频流获取） |

> 历史值 `tmdb`、`tmdb_ai`、`ai+tmdb` 在 Schema 迁移中自动合并为 `ai+provider`。

## 8. JSON 字段规范

### 8.1 序列化规则

| 字段 | 所属表 | 写入时 | 读取时 |
|------|--------|--------|--------|
| scrape_result | tasks | dict/list → json.dumps() | json.loads() → dict |
| scrape_dimensions | tasks | dict/list → json.dumps() | json.loads() → dict |
| dedup_result | tasks | dict/list → json.dumps() | json.loads() → dict |
| scrape_trace | tasks | dict/list → json.dumps() | json.loads() → dict |
| value_list | dimensions | dict/list → json.dumps() | json.loads() → list |
| default_value_list | dimensions | dict/list → json.dumps() | json.loads() → list |
| provider_mappings | dimensions | 直接存储 | 由 dimension_manager 解析 |

> task_repo.update_task() 中，`scrape_result`、`scrape_dimensions`、`dedup_result`、`scrape_trace` 四个字段在写入时自动检测类型：若为 dict/list 则自动 json.dumps()，若已是字符串则直接存储。

### 8.2 value_list 结构

value_list 存储维度的可选值列表，每个值项包含显示标签和匹配辅助字段：

```json
[
  {"value": "movie", "label": "电影"},
  {"value": "tv", "label": "剧集"}
]
```

布尔型维度（如 animation、documentary）：

```json
[
  {"value": "true", "label": "是", "tmdb_genre_ids": [16]},
  {"value": "false", "label": "否"}
]
```

枚举型维度（如 region、broad_genre）可包含 TMDB 匹配辅助字段：

```json
[
  {"value": "us", "label": "美国", "tmdb_codes": ["US"]},
  {"value": "cn", "label": "中国大陆", "tmdb_codes": ["CN"]}
]
```

分辨率维度（source_type=file）包含判定阈值：

```json
[
  {"value": "4k", "label": "4K", "min_width": 3840},
  {"value": "1080p", "label": "1080P", "min_width": 1920},
  {"value": "720p", "label": "720P", "min_width": 1280},
  {"value": "sd", "label": "标清", "min_width": 0}
]
```

### 8.3 provider_mappings 结构

provider_mappings 定义维度值与元数据提供者字段的映射规则：

```json
{
  "tmdb": {
    "field": "genres",
    "match_type": "genre_ids",
    "match_rules": {
      "true": {"ids": [16]},
      "horror_mystery": {"ids": [27, 9648, 53, 10758], "priority": 1}
    }
  }
}
```

| 字段 | 说明 |
|------|------|
| field | TMDB 数据字段名（genres / origin_country / original_language / release_dates） |
| match_type | 匹配方式（genre_ids / country_codes / direct_match / certification） |
| match_rules | 值到匹配规则的映射，ids 为 TMDB 对应 ID 列表，priority 为优先级 |

### 8.4 scrape_result 结构

scrape_result 存储 AI 刮削的完整结果：

```json
{
  "title_cn": "电影名称",
  "title_en": "Movie Title",
  "year": "2024",
  "type": "movie",
  "season": null,
  "episode": null,
  "media_type": "movie",
  "documentary": "false",
  "animation": "false",
  "restricted_level": "13-16",
  "region": "us",
  "origin_lang": "en",
  "resolution_tier": "1080p",
  "broad_genre": "action_adventure"
}
```

### 8.5 scrape_dimensions 结构

scrape_dimensions 存储维度判定结果（仅包含已启用维度）：

```json
{
  "media_type": "movie",
  "documentary": "false",
  "restricted_level": "13-16"
}
```

### 8.6 dedup_result 结构

dedup_result 存储同名检测结果：

```json
{
  "has_duplicate": true,
  "existing_file": "/path/to/existing/file.mkv",
  "action": "skip",
  "reason": "质量优先保留已有文件"
}
```

### 8.7 scrape_trace 结构

scrape_trace 存储刮削过程追踪信息，记录搜索和匹配的详细过程：

```json
{
  "search_query": "Movie Title 2024",
  "provider": "tmdb",
  "provider_id": 12345,
  "match_type": "exact",
  "search_confidence": 0.95,
  "data_confidence": 0.88
}
```

## 11. 文件指纹

文件指纹用于检测源文件的改名和内容变更，实现跨路径去重。

| 属性 | 说明 |
|------|------|
| 算法 | `sha256("{size_bytes}:{mtime_timestamp:.1f}")[:16]` |
| 输出 | 16 字符 hex 字符串 |
| 存储列 | `source_fingerprint` |
| 索引 | idx_tasks_fingerprint |
| 源码 | `media_importer/core/safety.py` → `make_fingerprint()` |

**计算过程**：

```python
def make_fingerprint(file_path: str) -> str:
    stat = os.stat(file_path)
    raw = f"{stat.st_size}:{stat.st_mtime:.1f}"
    return hashlib.sha256(raw.encode()).hexdigest()[:16]
```

**使用场景**：

- 源端去重：文件改名后 source_path 变化，但 fingerprint 不变，可识别为同一文件
- 变更检测：文件内容修改后 size 或 mtime 变化，fingerprint 随之变化，可触发重新处理
- 去重查询：`find_by_fingerprint()` 支持按指纹查找历史任务，可选按状态过滤
