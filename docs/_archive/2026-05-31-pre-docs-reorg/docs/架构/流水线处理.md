# 流水线处理

对应源码：
- `media_importer/pipeline/runner.py` — PipelineRunner 主类
- `media_importer/pipeline/steps.py` — StepsMixin（10 步实现）
- `media_importer/pipeline/confirm.py` — ConfirmMixin（确认/重分类）
- `media_importer/pipeline/utils.py` — 异常类 + 步骤常量 + 辅助函数

## 概述

流水线模块是 影音库AI智能整理的核心执行引擎，采用 **Mixin 组合** 模式：

```
PipelineRunner(StepsMixin, ConfirmMixin)
```

| Mixin | 职责 |
|-------|------|
| StepsMixin | 10 步流水线的逐步实现 |
| ConfirmMixin | 人工确认入库 + 重新分类 |
| PipelineRunner 自身 | 任务调度、暂停/恢复、错误处理、通知、清理 |

核心调度入口：

| 方法 | 说明 |
|------|------|
| `run_all()` | 批量扫描 + 逐任务处理 |
| `scan_and_create_tasks()` | 扫描源目录，创建 PENDING 任务 |
| `process_one(task)` | 单任务完整流水线 |
| `confirm_task(task_id)` | 确认入库（从 CONFIRMING 继续） |
| `reclassify_task(task_id, new_dimensions)` | 修改维度后重新分类入库 |

## 10 步流水线详解

```
PIPELINE_STEPS = [
    (1,  "scan",    "扫描源目录"),
    (2,  "copy",    "复制到临时目录"),
    (3,  "scrape",  "AI刮削元数据"),
    (4,  "validate","验证刮削结果"),
    (5,  "classify","分类匹配路径"),
    (6,  "dedup",   "同名文件检测"),
    (7,  "rename",  "生成目标文件名"),
    (8,  "import",  "入库移动文件"),
    (9,  "notify",  "发送通知"),
    (10, "record",  "记录处理结果"),
]
```

### 步骤 1：scan — 扫描源目录

由 `scan_and_create_tasks()` 执行，不在 `process_one()` 内。

```
source_dir
    │
    ▼
FileScanner.scan_and_filter() ─── dedup_enabled=True
FileScanner.scan_and_group()  ─── dedup_enabled=False
    │
    ▼
按组创建任务（video + subtitles → 1 task）
    │
    ▼
task_manager.create_task() → PENDING
```

- `dedup_enabled=True`：先去重过滤（跳过已存在任务），再分组
- `dedup_enabled=False`：直接扫描分组

### 步骤 2：copy — 复制到临时目录

| 项目 | 说明 |
|------|------|
| 方法 | `_step_copy()` |
| 进度 | 20% → 30% |
| 来源 | `file_location=source/recycle` 取 `source_path`，否则取 `video_path` |
| 目标 | `temp_dir` |
| 回调 | `progress_cb`（进度百分比）、`heartbeat_cb`（每 30s 更新任务心跳） |
| 异常 | `IOError` → `PipelineError("复制失败")` |

复制后更新 `task["video_path"]` 和 `task["subtitle_files"]` 为临时目录路径，同步更新 DB 中字幕的 `target_path`。

### 步骤 3：scrape — AI 刮削元数据

| 项目 | 说明 |
|------|------|
| 方法 | `_step_scrape()` |
| 进度 | 35% → 50% |
| 刮削器 | `MetadataScraper.scrape()` |

执行流程：

```
1. 文件维度分析（file_analyzer）
   └─ get_dimensions_for_file() → analyze_file()
   └─ 从视频文件物理属性推导维度值（如分辨率→quality）

2. AI 刮削
   └─ MetadataScraper.scrape(filename, subtitles)
   └─ 返回: title_cn, title_en, year, type, season, episode,
           confidence, dimensions, scrape_trace

3. 剧集维度覆盖（仅 TV 类型）
   └─ _find_cached_series_dims() → 查找同剧已成功任务的维度缓存
   └─ 未命中 → _extract_series_name() 提取剧名
   └─ scrape_series() 按剧名整体刮削维度
   └─ 整剧维度覆盖逐集维度（保持一致性）

4. 文件推导维度覆盖
   └─ file_dimensions 优先级高于 AI 刮削维度
   └─ 物理属性（分辨率等）以实际文件为准
```

写入 DB 字段：`scrape_result, scrape_dimensions, scrape_title_cn, scrape_title_en, scrape_year, scrape_media_type, scrape_season, scrape_episode, scrape_confidence, scrape_trace`

### 步骤 4：validate — 验证刮削结果

| 项目 | 说明 |
|------|------|
| 方法 | `_step_validate()` |
| 进度 | 52% → 55% |

验证逻辑：

```
刮削结果
    │
    ├─ 必填字段检查
    │   ├─ title_cn / title_en（至少一个）
    │   ├─ type（媒体类型）
    │   └─ year（年份，有标题时可缺）
    │
    ├─ 年份格式检查（1900~2030）
    │
    └─ 置信度分级（confidence_engine）
        ├─ FAILED        → _force_fail=True → 任务 FAILED
        ├─ NEEDS_REVIEW  → _needs_review=True → 任务 NEEDS_REVIEW
        │   └─ 数据门控拦截（来源不信任）也走此分支
        ├─ CONFIRMING    → _needs_confirm=True → 任务 CONFIRMING
        └─ OK            → 继续后续步骤
```

| 置信度级别 | 处理方式 |
|-----------|---------|
| FAILED | 直接标记失败 |
| NEEDS_REVIEW | 移入回收区，需人工审核 |
| CONFIRMING | 等待人工确认 |
| OK | 通过验证，继续流水线 |

### 步骤 5：classify — 分类匹配路径

| 项目 | 说明 |
|------|------|
| 方法 | `_step_classify()` |
| 进度 | 56% → 60% |

```
scrape_result + path_rules
    │
    ▼
classify(scraped, path_rules)
    │
    ├─ 匹配成功 → import_path
    ├─ 匹配失败 + fallback_dir → render_template(fallback_dir)
    └─ 匹配失败 + 无 fallback → PipelineError
```

- `path_rules` 按 `conditions` 匹配维度，命中则使用对应 `template`
- 相对路径自动拼接项目根目录
- 写入 DB：`import_path, classify_result`

### 步骤 6：dedup — 同名文件检测

| 项目 | 说明 |
|------|------|
| 方法 | `_step_dedup()` |
| 进度 | 65% → 70% |

```
import_roots（从 path_rules 提取根目录）
    │
    ▼
check_duplicate(search_dir, scraped, strategy, video_path)
    │
    ├─ 非重复 → 继续
    └─ 重复 → 按 strategy 处理
        ├─ skip     → PipelineSkipError（跳过，移入回收站）
        ├─ rename   → 修改 final_filename 为建议文件名
        ├─ replace  → safe_delete 删除已存在文件
        └─ quality  → 质量对比
            ├─ 新文件更优 → replace 逻辑
            └─ 已存在更优 → PipelineSkipError
```

### 步骤 7：rename — 生成目标文件名

| 项目 | 说明 |
|------|------|
| 方法 | `_step_rename()` |
| 进度 | 72% → 75% |

```
已有 final_filename？（dedup rename 可能已设置）
    │
    ├─ 是 → 跳过
    └─ 否 → apply_filename_template(scraped, template, ext)
              ├─ type=tv  → filename_templates.tv
              └─ type=movie → filename_templates.movie
```

### 步骤 8：import — 入库移动文件

| 项目 | 说明 |
|------|------|
| 方法 | `_step_import()` / `_step_import_from_confirm()` |
| 进度 | 80% → 90% |

```
1. move_to_import()
   └─ temp 视频 + 字幕 → import_path（按模板重命名）

2. 源文件清理（受 cleanup_source_after_done 布尔判断）
   └─ cleanup_source_after_done=true
   │   └─ move_to_recycle_with_companions()（源视频+附属文件移入回收站）
   │   └─ remove_empty_parent_dir()（删除空父目录）
   └─ cleanup_source_after_done=false
       └─ 保留源目录文件不动

3. 清理临时目录
   └─ delete_source_files()（删除 temp 中的视频副本，直接 rm 不入回收站）

4. 更新 DB
   └─ 任务: import_video_path, import_success=1
   └─ 字幕: status=SUCCESS, import_path, confirm_status=CONFIRMED
```

`_step_import_from_confirm()` 额外处理人工审核模式下的 `.temp/.tmp` 后缀恢复。

### 步骤 9：notify — 发送通知

| 项目 | 说明 |
|------|------|
| 方法 | `_step_notify()` |
| 进度 | 95% |

委托 `self.notifier` 发送入库成功通知。

### 步骤 10：record — 记录处理结果

| 项目 | 说明 |
|------|------|
| 方法 | `_step_record()` |
| 进度 | 100% |

调用 `task_manager.update_task(task)` 将最终状态写入 DB。

## 确认与重分类

### confirm_task — 确认入库

```
CONFIRMING 任务
    │
    ├─ 校验状态 = CONFIRMING
    │
    ├─ confirm_status → CONFIRMED
    ├─ 字幕 confirm_status → CONFIRMED
    │
    ▼
_step_import_from_confirm()
    ├─ 人工审核模式：恢复 .temp/.tmp 后缀
    ├─ _step_dedup()
    ├─ _step_rename()
    ├─ move_to_import()
    ├─ 清理源目录 + 临时目录
    └─ 更新 DB
    │
    ▼
_step_notify() → _step_record()
    │
    ▼
SUCCESS
```

### reclassify_task — 重新分类

```
任意任务 + new_dimensions
    │
    ├─ 合并维度：current_dims.update(new_dimensions)
    ├─ 更新 scrape_result.dimensions
    │
    ▼
classify(scrape_result, path_rules) → 新 import_path
    │
    ├─ 匹配失败 + fallback_dir → 使用兜底
    └─ 匹配失败 + 无兜底 → PipelineError
    │
    ▼
_step_dedup() → _step_rename() → _step_import()
→ _step_notify() → _step_record()
    │
    ▼
SUCCESS / SKIPPED / FAILED
```

重新分类跳过 copy/scrape/validate，从 classify 步骤重新开始。

## 任务状态流转

### process_one 主流程

```
PENDING
    │
    ▼
PROCESSING ──────────────────────────────────────────┐
    │                                                  │
    ├─ copy → scrape → validate                        │
    │       │                                          │
    │       ├─ _force_fail ────────────→ FAILED        │
    │       │                          (源文件保留在源目录)│
    │       ├─ _needs_confirm ────────→ CONFIRMING     │
    │       │                          (处理中·需确认)   │
    │       │                                          │
    │       ▼ (validate OK)                            │
    │   classify                                       │
    │       │                                          │
    │       ├─ manual_review=enabled ──→ CONFIRMING    │
    │       │                                          │
    │       ▼                                          │
    │   dedup → rename → import → notify → record      │
    │       │                                          │
    │       ├─ PipelineSkipError ────→ SKIPPED         │
    │       │                          (完成·跳过)      │
    │       ├─ Exception ───────────→ FAILED           │
    │       │                          (源文件保留在源目录)│
    │       └─ 正常完成 ────────────→ SUCCESS          │
    │                                  (完成)           │
    └──────────────────────────────────────────────────┘
```

### CONFIRMING 后续流转

```
CONFIRMING
    │
    ├─ confirm_task() ──────→ dedup → rename → import → SUCCESS
    │
    ├─ reclassify_task() ──→ classify → dedup → ... → SUCCESS/FAILED/SKIPPED
    │
    └─ rollback ───────────→ ROLLBACK（回退到源目录）
```

### 异常处理与清理

| 异常类型 | 业务状态 | 源文件处理 | 临时文件处理 |
|---------|---------|-----------|------------|
| `PipelineSkipError` | 完成(跳过) | 按 cleanup_source_after_done 配置处理 | 直接 rm 删除 temp 副本 |
| `Exception` | 失败 | 保留在源目录，等用户决策 | 直接 rm 删除 temp 副本 |
| 系统错误（API/网络/认证） | 失败 | 保留在源目录 | 直接 rm 删除 temp 副本 |

源文件清理规则：
- FAILED 状态：源文件保留在源目录（file_location=source），不自动移入回收站
- SUCCESS/SKIPPED 状态：按 cleanup_source_after_done 配置处理
  - true → 源文件+附属文件移入回收站（move_to_recycle_with_companions）
  - false → 保留源目录文件不动

系统错误通知有 300s 冷却去重机制，避免重复告警。

## 职责边界

### 负责

- 10 步流水线编排与调度
- 任务处理入口（run_all / process_one）
- 确认与重分类流程（confirm_task / reclassify_task）
- 异常处理与状态回退
- 暂停/恢复控制
- 源文件清理策略门控（cleanup_source_after_done: true/false）

### 不负责

- 具体文件 I/O（委托 storage 模块）
- 具体刮削逻辑（委托 scraper 模块）
- 任务数据持久化（委托 TaskManager / task_repo）
- 通知发送（委托 notify 模块）
- 配置管理（委托 config_loader）

## 配置项说明

| 配置键 | 流水线使用位置 | 说明 |
|--------|-------------|------|
| `source_dir` | scan, import, cleanup | 源目录路径 |
| `temp_dir` | copy, import, cleanup | 中转目录路径 |
| `source_policy.dedup_enabled` | scan | 扫描时是否去重过滤 |
| `source_policy.recycle_dir` | error handling | 回收站目录 |
| `source_policy.cleanup_source_after_done` | import | 任务完成后是否清理源文件 |
| `source_policy.recycle_retention_days` | cleanup | 回收站文件保留天数 |
| `manual_review.enabled` | validate 后 | 启用后所有任务进入 CONFIRMING |
| `duplicate_handling.strategy` | dedup | skip/rename/replace/quality |
| `path_rules` | classify | 入库路径匹配规则 |
| `fallback_dir` | classify | 无匹配规则时的兜底目录 |
| `filename_templates` | rename | 文件名模板（movie/tv/subtitle） |
| `video_extensions` | import, cleanup | 视频文件扩展名列表 |
| `subtitle_extensions` | import, cleanup | 字幕文件扩展名列表 |
| `llm.*` | scrape | AI 刮削配置（通过 MetadataScraper 间接使用） |

                                                                  scrape_title_cn/en, scrape_year
                                                                  scrape_media_type, scrape_confidence
                                                                  provider_type, provider_id
                                                                           │
                                              ┌────────────────────────────┤
                                              ▼                            ▼
                                       ┌──────────┐  import_path     ┌──────────┐  dedup_result
                                       │ validate │ ──────────────→ │ classify │ ──────────────→
                                       │          │  _needs_confirm  │          │  classify_result
                                       │          │  _force_fail     └──────────┘
                                       │          │  _needs_review         │
                                       └──────────┘                        │
                                                                           ▼
                                                                    ┌──────────┐  final_filename
                                                                    │  dedup   │ ──────────────→
                                                                    │          │  PipelineSkipError
                                                                    └──────────┘
                                                                           │
                                                                           ▼
                                                                    ┌──────────┐  import_video_path
                                                                    │  rename  │ ──────────────→
                                                                    │          │  file_location
                                                                    └──────────┘

### 各步骤输入/输出数据

#### 步骤 2：copy

| 方向 | 字段 | 类型 | 说明 |
|------|------|------|------|
| 输入 | `task.source_path` | str | 源文件路径 |
| 输入 | `task.subtitle_files` | list | 字幕文件路径列表 |
| 输入 | `task.file_location` | str | "source" 或 "recycle" |
| 输出 | `task.video_path` | str | 中转目录中的视频副本路径 |

### 数据流关键约束

1. **task dict 是核心数据载体**：所有步骤通过 task dict 传递数据，步骤间无直接依赖
2. **DB 写入时机**：scrape/classify/dedup/import 步骤有即时 DB 写入，其余步骤在 record 步骤统一写入
3. **文件系统副作用**：copy（创建临时文件）、dedup（可能移入回收站）、import（移动文件+按配置清理源文件）有文件系统副作用。临时文件(.tmp/.copying)直接 rm 删除，不入回收站
4. **异常中断安全**：PipelineError/PipelineSkipError 会被 runner 捕获，确保 task 状态和 file_location 正确更新
