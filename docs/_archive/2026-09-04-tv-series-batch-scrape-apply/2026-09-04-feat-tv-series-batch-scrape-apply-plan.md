# 同剧批量套用与待确认批量重新识别

- **Requirement**: [REQ-20260904-115624](../../tracking/requirements-board.md)
- **Proposal**: [同剧批量套用与待确认批量重新识别](2026-09-04-tv-series-batch-scrape-apply.md)
- **Status**: complete

## Problem Statement

电视剧的一组分集如果都进入“待人工确认”，当前必须逐集选择同一个 Provider 条目。以《北海鲸梦》5 集为例，用户需要重复完成 5 次相同的剧集身份确认，且已生成的待确认任务不会因为新版本识别能力提升而自动重新计算。

需要在不降低文件安全边界、不覆盖每集季集号、不自动入库的前提下，把一次人工选择安全地应用到同剧同批次的其他待确认分集；同时允许用户对选中的待确认任务批量重新识别。

## Target End State

1. 用户为某个电视剧任务选择 Provider 候选后，系统先预览同剧同批次的其他待确认任务。
2. 若发现 4 个可安全套用的任务，界面明确提示“发现同剧另外 4 个待确认任务，是否一起应用？”，展示文件名与 `SxxExx`，默认勾选且允许取消。
3. 后端对前端提交的任务 ID 再次校验，只向仍满足安全条件的任务应用同一剧集 Provider 身份。
4. 每个任务保留自己的季、集证据，并独立重算分类、目标文件名、字幕、缩略图和重复检测结果。
5. 操作仅更新刮削与待确认结果，不触发导入、移动、覆盖或删除文件。
6. 任务列表支持对选中的 `FAILED` 与 `AWAIT_REVIEW/PENDING` 任务执行批量重新识别，以便升级后重新运行旧任务。

## Scope

### In Scope

- 仅处理当前数据库中仍处于待确认或失败状态的任务。
- 同剧批量套用限定为电视剧、同一可信目录批次、标准化剧名一致、季集号有效且唯一的任务。
- 提供批量套用预览、逐项取消选择、后端二次校验和逐任务结果摘要。
- 扩展任务列表批量操作，支持待确认任务重新识别。
- 为《北海鲸梦》EP01–EP05 建立端到端回归样本，并覆盖排除、冲突及部分失败场景。

### Non-goals

- 不建立跨任务、跨目录、跨时间的永久剧集绑定或“改一次永远记住”。
- 不按标题模糊相似度在全库静默传播。
- 不跨松散源根目录聚合任务，不将整个下载根目录视为同一批次。
- 不修改运行中、已成功、已取消或存在未解决冲突的任务。
- 不自动确认导入，不移动、复制、覆盖或删除媒体文件。
- 本阶段不发布、不部署、不生成 fnOS 安装包。

## Proposed Solution

### 1. 安全同批次识别

新增任务域服务，根据锚点任务与候选 Provider 识别可套用任务。候选任务必须同时满足：

- 媒体类型为电视剧；
- 状态为 `PENDING` 或 `AWAIT_REVIEW`；
- 与锚点位于同一可信媒体目录批次，不能仅因同属 `loose_root` 而命中；
- 文件名清洗后的剧名一致；
- 季号、集号有效，并且批次内 `(season, episode)` 唯一；
- 不存在未解决重复冲突；
- 未人工绑定到另一个 Provider 条目。

预览结果同时返回排除原因，便于后端测试和后续问题诊断。前端只显示可选任务，不暴露内部策略细节。

### 2. 预览后批量应用

增加同剧任务预览接口，并在现有手动候选应用接口中支持可选的关联任务 ID。前端先预览，用户确认后再提交。

后端不信任前端任务列表：提交时重新加载任务和状态，重新执行同批次校验。Provider 详情只查询一次，各任务分别执行现有手动候选应用流程，保留各自季集号并重算派生结果。返回：

- 成功更新任务；
- 因状态变化或规则不符而跳过的任务及原因；
- 更新失败的任务及错误；
- 锚点任务的最新详情。

单个关联任务失败不回滚已成功任务，但必须在界面明确报告，不能伪装成全部成功。

### 3. 批量重新识别

任务列表对选中的 `FAILED`、`PENDING`、`AWAIT_REVIEW` 任务提供“批量重新识别”。复用现有单任务重试状态机与 API，逐项执行并汇总结果。其他状态不进入操作集合。

### 4. 交互预览

```text
选择《北海鲸梦》Provider 候选
        ↓
发现同剧另外 4 个待确认任务
┌────────────────────────────────────┐
│ ☑ 北海鲸梦...EP01.mkv   S01E01     │
│ ☑ 北海鲸梦...EP02.mkv   S01E02     │
│ ☑ 北海鲸梦...EP03.mkv   S01E03     │
│ ☑ 北海鲸梦...EP04.mkv   S01E04     │
│ ☑ 北海鲸梦...EP05.mkv   S01E05     │
│       [仅应用当前集] [应用所选 5 集] │
└────────────────────────────────────┘
        ↓
每集保留自己的 E01–E05，分别重算结果
        ↓
仍停留在待确认流程，由用户决定是否批量确认入库
```

## Acceptance Criteria

- 《北海鲸梦》同一目录中的 EP01–EP05 均处于待确认时，选择一次 TMDB 剧集条目可预览并默认选中全部 5 集。
- 应用后 5 个任务的 Provider ID 与剧名一致，季号均为 1，集号分别保持 1–5。
- 电影、其他剧名、不同可信目录、运行中/成功任务、冲突任务和已绑定不同 Provider 的任务不会被套用。
- 手工构造的任意关联任务 ID 会被后端拒绝或跳过，不能绕过分组规则。
- 套用过程不创建导入任务，不执行媒体文件复制、移动、覆盖或删除。
- 部分任务因并发状态变化失败时，响应和界面明确区分成功、跳过、失败。
- 选中待确认任务后可批量重新识别；不支持的状态不会被发送。
- 回归测试覆盖率目标为已收集电影/电视剧命名场景的至少 90%，本功能不得降低既有基线。

## Rejection Conditions

- 任一分集的季集号被锚点任务覆盖。
- 非电视剧、跨剧、跨不可信目录或冲突任务被静默纳入。
- 操作触发文件导入、移动、覆盖或删除。
- 前端任务 ID 可绕过后端校验。
- 部分失败只显示“全部成功”。
- 必须逐集重复选择同一 Provider 才能完成《北海鲸梦》5 集确认。

## Rationale and Tradeoffs

本阶段选择“同剧同批次”而非永久学习，是因为目录与文件名证据可审计、影响范围小，且足以消除同一下载包逐集确认的主要痛点。代价是跨季、跨目录或未来新增分集仍可能需要再次确认；待本阶段真实使用稳定后，再评估是否引入可撤销、可管理的剧集绑定。

## Constraints and Assumptions

- 现有单任务手动候选流程已经能保留每个任务的季集号，本实现以复用该事实源为原则。
- 现有重试状态机支持待确认任务重新运行，不新增任务状态。
- 同一批次内重复季集号视为冲突，不自动选择其中一个。
- 真实 fnOS 任务仍可能受“全局人工复核”配置影响，本功能只减少重复操作，不改变该产品策略。

## Risks and Mitigations

- **误分组**：使用同目录、标准化剧名、电视剧类型和唯一季集号多重约束，并由用户预览确认。
- **并发状态变化**：提交时重新校验状态与分组，使用现有 CAS 更新并报告跳过项。
- **Provider 请求放大**：同一次批量操作只加载一次 Provider 详情。
- **缩略图重复下载**：复用现有缓存路径或本次已下载资源，不为每集重复获取相同海报。
- **旧任务数据不完整**：无法可靠提取剧名或季集号时排除，并允许用户使用批量重新识别刷新。
