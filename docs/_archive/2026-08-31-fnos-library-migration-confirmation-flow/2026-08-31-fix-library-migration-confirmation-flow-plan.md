# fnOS 多片库暂存与确认闭环

- **Requirement**: [REQ-20260830-180954](../../tracking/requirements-board.md)
- **Status**: complete

## 目标与边界

用户通过 fnOS 目录选择器暂存任意数量的目标片库后，可以直接在“存储检查”完成旧规则关联；提交进行中、失败和成功都有当前上下文内的明确反馈。关联仍然只原子转换配置规则，不移动、覆盖或删除片库文件。

## 实施任务

- [x] 暂存区同时提供“继续添加片库”和“已选齐，确认关联”两个动作。
- [x] 弹窗与暂存区复用同一提交逻辑，提交期间禁用按钮并显示进行中状态。
- [x] 保存失败时在弹窗或暂存区内显示后端原始中文原因，不再只依赖被遮挡的 Toast。
- [x] 保存成功后关闭弹窗、刷新目录检查并清除迁移提示。
- [x] 增加真实 DOM 点击回归，覆盖暂存后直接确认、失败保持数据、成功刷新关闭。
- [x] 运行定向 UI、配置原子保存、JS 语法和文档检查。

- `FNOS_UAT NOT_RUN`：用户需要在真实 fnOS 上继续验证原生目录选择、失败反馈和成功关联。

## 验收标准

1. 已暂存 1、5 或更多片库时，不需要再次打开 fnOS 选择器即可确认关联。
2. 点击确认后立即看到“正在检查并关联”，按钮不可重复点击。
3. 后端拒绝时弹窗不关闭，当前区域直接显示具体原因；已暂存目录不丢失。
4. 成功后弹窗关闭、配置重新加载，旧规则迁移提示消失。
5. 任何失败均不产生部分配置写入，任何路径都不执行片库文件操作。

## 拒绝标准

- 暂存后仍只有“继续选择”。
- 失败提示仍位于弹窗遮罩之后，或只写控制台。
- 为完成关联要求用户重新选择已经暂存的目录。
- 前端修复改变服务端原子迁移或片库文件安全边界。
