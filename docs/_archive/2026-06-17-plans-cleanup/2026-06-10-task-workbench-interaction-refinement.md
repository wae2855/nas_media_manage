# 任务工作台交互与失败语义细化计划

> 日期: 2026-06-10 | 状态: complete

---

## 一、背景

任务工作台在 status + stage 重构后，仍存在几类交互和语义不一致：

1. 卡片点击仍会打开详情，不符合“点击任务默认选中”的工作台批处理模型；
2. 详情弹窗底部同时出现“保存新文件名”和“应用分类微调”，按钮位置和作用对象不够清晰；
3. 详情编辑权限过宽，FAILED、RUNNING、CANCELLED 等状态也会显示可编辑控件；
4. 启动清理孤儿 RUNNING 任务时当前会重置为 QUEUED，用户无法在 FAILED 视图中看到中断异常。

---

## 二、目标

1. 任务卡片点击默认只选中/取消选中；
2. 详情打开改为显式“详情”按钮；
3. 文件名编辑按钮放在文件名区域内，维度编辑按钮放在维度区域内；
4. 维度区域保留“预览入库规则”按钮；
5. 详情弹窗底部只保留“关闭”；
6. 仅 `PENDING/AWAIT_REVIEW` 允许编辑文件名和维度；
7. 孤儿 `PENDING/RUNNING` 任务在服务启动清理时标记为 `FAILED/DONE`；
8. 同步测试和文档。

---

## 三、非目标

1. 不合并文件名保存和维度保存；
2. 不新增“只保存维度但不继续流程”的后端接口；
3. 不支持强制中断正在运行的任务；
4. 不调整确认入库主流程。

---

## 四、设计决策

### D1：点击语义

```text
卡片主体点击 -> 选中
详情按钮 -> 打开详情
状态主按钮 -> 执行状态动作
```

### D2：详情编辑布局

文件名区域：

```text
新文件名 [修改/保存]
```

维度区域：

```text
分类维度 [修改/保存] [预览入库规则]
```

### D3：编辑权限

仅 `status=PENDING` 且 `stage=AWAIT_REVIEW` 时可编辑。其他状态详情均只读。

### D4：孤儿 RUNNING 处理

服务启动发现孤儿 `PENDING/RUNNING` 或旧 `PROCESSING` 时，清理 temp 文件并标记为：

```text
status=FAILED
stage=DONE
error_message=服务中断或重启导致任务未完成，请重试
```

## 六、验收标准

1. 点击任务卡片主体只切换选中，不打开详情；
2. 点击“详情”按钮才打开任务详情；
3. 详情底部只显示“关闭”；
4. `AWAIT_REVIEW` 详情中，文件名区域有修改/保存，维度区域有修改/保存和预览入库规则；
5. FAILED/RUNNING/CANCELLED/SUCCESS/SKIPPED 详情只读；
6. 服务启动清理孤儿 RUNNING 任务后进入 FAILED 筛选；
7. 相关测试通过。
