# 校验传输诊断与失败任务去重

准确区分来源变化与目标暂存校验失败，对同一来源的历史失败任务停止重复建档，并在不放宽 SHA-256 门禁的前提下提供一次干净重试。

- **Requirement**: [REQ-20260904-162232](../../tracking/requirements-board.md)
- **Related incident**: fnOS 0.3.28《北海鲸梦》EP04 两次 `目标临时文件 SHA-256 校验失败`
- **Proposal**: [校验传输诊断与失败任务去重方案](2026-09-04-verified-transfer-diagnostics-and-failed-task-dedup.md)
- **Status**: complete

## Problem Statement

当前 `verified_copy` 在来源哈希完成后，先比较来源与目标摘要，再检查来源快照。如果来源恰好在哈希期间变化，用户会先收到“目标临时文件 SHA-256 校验失败”，无法判断应等待上游稳定还是检查存储。同时，任务扫描对同一路径的历史 `FAILED` 记录返回 `CREATE`，每轮稳定扫描都可能新增一条相同失败任务，造成列表重复和重复 I/O。

## Target End State

- 来源在复制或来源哈希期间发生变化时，任务明确提示等待上游文件稳定后重试。
- 来源保持稳定但目标摘要不同，任务明确提示可能是目标存储或读取异常，不把原因武断归给上游。
- 第一次稳定来源下的目标摘要不一致时，只清理本任务拥有的临时文件并做一次从零复制；第二次仍失败则失败关闭。
- 同一路径最新任务为 `FAILED` 时，自动扫描不再创建新记录；用户仍可通过现有“重新识别/重试”显式重启原任务。
- SHA-256、no-replace、来源保留和目标片库不可覆盖边界不变。

## Scope and Non-Goals

### In Scope

- 调整来源快照与摘要检查顺序和面向用户的错误信息。
- 为稳定来源下的目标摘要不一致增加一次有界、干净的安全重试。
- 自动扫描对最新同路径失败任务执行跳过并刷新 `last_seen_at`。
- 增加来源在哈希期变化、瞬时目标摘要异常、持续异常和失败任务重复扫描测试。
- 同步任务、入库流程、存储架构、安全标准和回归矩阵文档。

### Non-Goals

- 不认定本次真机事故已经证明为上游文件变化。
- 不关闭、降低或跳过 SHA-256 校验。
- 不自动删除历史重复任务记录，不改变现有片库或来源文件。
- 不新增可配置的无限重试，不在后台持续读取故障大文件。
- 本轮不部署 fnOS；安装包与真机验证按用户后续发布指令执行。

## Proposed Solution

1. `verified_copy` 在比较摘要前先检查 `source_after_hash`，使复制期和来源校验期变化得到准确、可操作的提示。
2. 将单次校验复制保持为失败关闭的底层原语；在新作品文件包暂存层仅对“来源稳定且目标摘要不一致”执行一次重试。重试前只移除经路径和身份验证、属于当前任务的 `.copying` 文件，从零重新复制。
3. 第二次摘要仍不一致时返回存储/读取异常提示，并保留来源、禁止发布临时目标。
4. `TaskManager.check_source_duplicate` 对最新同路径 `FAILED` 返回 `SKIP`；继续使用原任务的显式重试入口，其他终态行为保持现状。

## Test Plan

- 底层复制：复制期间来源变化、来源哈希期间变化、正常复制、已有错误临时文件恢复均保持安全。
- 文件包暂存：首次目标摘要异常后第二次成功；连续两次异常后失败且来源保留、目标未发布；来源变化不触发目标重试。
- 任务去重：最新同路径 `FAILED` 自动扫描跳过并刷新发现时间；`PENDING`、`SUCCESS` 与重命名检测合同不回归；人工重试仍把原任务重新排队。
- 回归：目标冲突、文件包恢复、任务状态/CAS、来源处置、完整 pytest。

## Acceptance Criteria

- 来源哈希期间发生 size/mtime/inode 变化时，返回包含“完整性校验期间源文件发生变化”的提示，不返回目标 SHA 错误。
- 稳定来源下模拟一次目标摘要异常，系统只重试一次并成功；连续两次异常时不发布目标且不处理来源。
- 对同一路径已有 `FAILED` 任务连续扫描两次，数据库任务数量不增加。
- 用户点击现有失败任务“重新识别/重试”后，原任务仍可进入 `PENDING/QUEUED`。
- 所有现有文件安全与完整回归通过。

## Decision Rationale

错误分类必须先证明来源快照稳定，才能把摘要不一致归入目标读写异常；否则提示会误导用户。安全重试放在文件包业务层而非底层无限循环，可限定为当前任务、单个成员和一次尝试，也便于记录真实失败原因。失败任务自动去重只约束扫描建档，不影响用户显式重试，因此同时减少重复 I/O 并保留可恢复性。

## Constraints and Boundaries

- 临时文件清理必须证明属于当前任务和 `.copying` 边界。
- 任一重试都必须重新校验完整 SHA-256，不能复用失败摘要或直接发布。
- 来源发生变化时立即停止，不自动追赶正在写入的文件。
- 历史重复失败记录只保留，不在本轮执行数据清理。

## Assumptions

| Assumption | Status | Evidence |
|------------|--------|----------|
| 来源哈希后快照检查可以识别大多数写入期变化 | Verified | 快照包含 size、mtime_ns、device、inode；现有复制期检查使用同一合同 |
| 两条 EP04 记录由失败后再次扫描创建 | Strong inference | 最新同路径终态统一返回 `CREATE`，数据库按最新记录查找；未取得真机服务日志证明具体触发入口 |
| 单次干净重试不会突破安全边界 | Verified by design | 只对稳定来源下摘要不一致触发，重试仍执行完整校验并在失败时保留来源 |
| SHA 不一致一定由上游变化导致 | Rejected | 稳定来源下仍可能是挂载、磁盘或读取异常 |

## Risk Analysis

- **重复读取大文件增加 I/O**：仅对特定摘要错误重试一次；来源变化、空间不足和权限错误不重试。
- **误删其他任务临时文件**：复用现有任务绑定路径和安全清理函数，只清理当前调用生成的 `.copying`。
- **失败任务被永久忽略**：自动扫描跳过，但现有显式重试入口保留；提示用户处理原任务。
- **仅凭 stat 无法识别同大小同时间内容变化**：SHA 门禁仍会阻断发布；不声称 stat 能证明全部来源变化。

## Representative Proof Slice

用测试桩让第一次目标摘要比较失败、第二次成功：验证只执行两次复制、第一次临时文件被安全清理、最终目标与来源 SHA 相同。随后让来源在哈希阶段变化，验证不进行第二次复制并返回来源变化提示。

## Rejection Criteria

- 任何路径在摘要不一致时仍发布目标或处理来源。
- 错误信息把所有 SHA 不一致都确定描述为“上游文件变化”。
- 自动扫描继续为同一最新失败来源新增任务。
- 重试次数可无限增长或跨任务清理临时文件。
