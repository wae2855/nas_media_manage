# fnOS 动态目录清单与首次配置闭环

把首次安装、日常扩容和旧配置迁移拆成三个明确状态；目标片库由用户通过 fnOS 选择器动态创建，数量为 0～N，授权成功后立即校验并持久化。

## Target End State

- 全新安装不从规则或旧字段猜测目标片库；来源、回收为空，目标片库列表为空，中转和日志由安装包管理。
- “存储检查”只保留一份目录事实清单：来源 1 条、目标片库 N 条、回收 1 条、中转/日志系统条目；不再同时展示三张聚合授权卡和另一套检查卡。
- 每个外部目录都独立显示路径、fnOS 授权、挂载类型、读写、容量和修复动作。
- 目标片库支持动态添加、编辑、设默认、停用和移除；不存在 4 个、5 个等产品上限。
- fnOS 回调在弹窗、新标签和移动端无 `window.opener` 时都能回到原页面消费；一次性 state、来源应用和过期时间都要校验。
- 选择来源或本地回收后立即保存；一次选择多个目标目录时先形成待确认列表，命名/默认项确认后一次保存。
- 旧绝对路径规则只在用户明确选择片库根并点击“确认迁移”后转换为根 ID + 相对路径；无法覆盖的规则逐条提示，禁止静默猜测。

## Anti-goals

- 不在 fnOS 安装向导里恢复无法写 ACL 的路径文本框。
- 不从旧规则推断全新安装的片库根，也不预置固定数量的空片库槽位。
- 不因移除配置删除磁盘文件；规则仍引用目标片库时禁止移除。
- 不允许远程挂载作为回收、中转或日志目录；来源和目标片库的远程挂载只给警告并限制自动运行。
- 不修改导航胶卷形式，不引入前端框架，不在本任务中操作用户真机安装、推送或发布。

## 任务分解

### Phase 1 — 配置与迁移契约

- [x] 让 fnOS 全新初始化真正生成空的外部目录状态，并保留系统管理的中转/日志目录。
- [x] 增加显式旧规则迁移函数：按用户选择的多个根做最长安全包含匹配，转换规则与兜底目录；未匹配项整体拒绝。
- [x] 配置保存对本次触达角色执行独立 readiness 门禁：ACL、存在、读写、本地回收与容量错误拒绝；来源/目标远程警告允许保存。
- [x] 后端返回可直接渲染的目录记录，禁止 storage readiness 再从旧规则推断全新目标片库。

### Phase 2 — 动态目录清单与可靠回调

- [x] 将“存储检查”合并为单一目录清单；每个目标片库独立成行，空状态提供“添加第一个目标片库”。
- [x] 目标片库添加支持 fnOS 一次返回一个或多个目录，并进入命名、默认和启用确认；保存后刷新仍存在。
- [x] 来源和回收选择成功后立即保存并重新检查；失败在当前配置区域显示明确中文原因。
- [x] 使用同源 `localStorage` 结果桥接配合 message/focus/visibility 消费无 opener 回调，执行一次性 state 与过期校验。
- [x] 增加旧配置迁移面板；只有显式确认才提交转换，首次空白配置永不出现推断结果。

### Phase 3 — 安全、UI 与交付验证

- [x] 补充 0、1、5、10 个目标片库，重复路径、规则引用移除、远程回收、远程来源/目标和旧规则迁移测试。
- [x] Playwright 覆盖真实点击、弹窗回调、无 opener 新标签回调、保存后刷新及失败反馈，不再直接调用完成函数代替用户流程。
- [x] 在 1440×1000 与 390×844 验证目录清单层级、长路径换行、动态按钮和无横向溢出，保持现有影院主题。
- [x] 运行定向测试、架构护栏、非 UI 回归、UI 回归、Ruff、compileall、JS 语法和文档检查；同步当前事实文档并归档本计划。

## 验收标准

- 全新 fnOS 配置加载后目标片库为 0，页面只显示“添加第一个目标片库”，不会显示来自规则的猜测目录。
- 连续添加 1、5、10 个目标片库均可保存；每个目录各自有授权和存储状态，刷新后数量及默认项不变。
- 无 opener 回调能在返回应用后完成一次消费；错误 state、过期结果或其他应用结果不会写入配置。
- 回收目录选择本地可写目录后自动保存；远程、不可写、容量不足或未授权均拒绝且保留旧配置。
- 来源/目标为远程挂载时可保存并显示“仅适合人工任务”的警告，挂载失效明确显示目录不可达。
- 旧规则不会自动迁移；用户选择覆盖全部规则的根并确认后，所有规则转换为根 ID + 相对模板；任一规则未覆盖则配置原子不变。
- 移除片库只改配置，不删除文件；仍有规则/兜底引用时按钮明确阻止。
- 1440px 与 390px 页面均无横向滚动、按钮遮挡或第二套配置导航。

## Subjective Contract and Preview Gate

- 正向参考：现有深色影院、金色状态、胶卷配置轨；目录清单使用“角色—路径—状态—动作”的单层阅读顺序。
- 反向参考：三张授权汇总卡叠加五张检查卡、固定四个片库槽位、把高级迁移选项暴露给首次用户。
- Proof slice：先实现“空白配置 + 来源 + 两个目标 + 本地回收”的统一清单，并完成桌面/手机预览，再扩展旧配置迁移和十目标压力场景。
- Rejection：任一实际目录没有独立状态、选择后刷新丢失、移动端需复制路径、旧规则被静默推断或回收允许远程，均退回修改。

## 风险

- 旧绝对规则跨多个卷：必须由用户选择根后做最长安全包含匹配，不能用 `commonpath` 猜测跨卷共同根。
- 多目标保存可能触发现有规则校验：迁移和普通编辑必须区分，后端一次完成转换并原子写入。
- fnOS 不同宿主可能以弹窗或新标签打开：回调桥接不能只依赖 opener，且结果必须短时、一次性、同源。
- 远程挂载的存在性与容量会波动：保存时允许角色警告，但自动运行继续由完整 readiness 阻断。
