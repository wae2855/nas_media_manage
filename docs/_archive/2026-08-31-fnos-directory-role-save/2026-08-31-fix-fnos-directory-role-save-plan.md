# fnOS 存储目录按钮保存失败修复

## Problem Statement

真实 fnOS 0.3.7 中，目录选择和授权回调成功，但旧版绝对片库规则尚未迁移时，保存本地中转、本地回收等无关目录会被片库规范化提前拦截并返回 400。

## Target End State

- 来源、中转、回收、日志和资源目录只校验各自目录边界，不被未修改的旧片库规则阻塞。
- 修改片库根、入库规则或明确执行旧规则迁移时，继续严格执行片库规范化和安全边界。
- 存储检查六类按钮均有真实交互或保存证据，并生成 0.3.8 FPK 供 fnOS 验收。

## Scope and Safety

- 不自动迁移旧片库规则，不覆盖用户现有目录。
- 不在用户 fnOS 上写配置或安装包；仅读取既有诊断证据。
- 中转目录非空、存在活跃/可恢复任务、fnOS ACL 未授权、远程本地目录等门禁保持不变。

## Tasks

- [x] 仅在片库相关字段被修改时规范化片库配置。
- [x] 增加旧片库待迁移状态下五类非片库目录逐项保存测试。
- [x] 验证六类按钮的角色、选择器、回调和保存/迁移分支。
- [x] 运行全量测试、UI 回归、Ruff、compileall、架构与文档检查。
- [x] 构建并验证 0.3.8 FPK，记录 LOCAL_BUILD 与 FNOS_UAT 边界后归档。

## Acceptance Criteria

- 旧片库待迁移时，已授权且可用的来源、中转、回收、日志、资源目录均可独立保存。
- 片库变更仍会要求显式迁移旧绝对规则。
- 前端每个存储按钮都触发正确角色；保存失败必须显示后端中文原因。
- 0.3.8 归档验证、SHA256 和打包专项测试全部通过。

## Rejection Criteria

- 为让目录保存通过而绕过 ACL、权限、本地性、容量或中转安全门禁。
- 非片库目录保存时顺带改写旧片库规则。
- 仅做字符串断言，不验证实际 API 保存结果或按钮点击链路。
