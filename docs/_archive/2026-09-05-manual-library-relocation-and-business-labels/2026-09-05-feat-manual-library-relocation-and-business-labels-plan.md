# 已入库影片人工调整位置与季集业务化展示

在不破坏目标片库只新增、安全移动和任务审计边界的前提下，让用户能从已完成任务发起一次明确的片库内人工调整，并消除任务卡中的 `season` / `episode` 技术字段。

## Problem Statement

- 任务卡的维度名称兜底缺少 `season`、`episode`，导致技术字段直接暴露；卡片上方又已有季集标签，形成重复信息。
- 当前关联重新整理任务只允许 `SUCCESS/DONE + FALLBACK_PENDING`，正常按规则完成的电影不能再次由系统安全调整位置。用户只能绕过系统在文件管理器中移动，任务路径、字幕文件包和审计记录会失真。
- 正式上架前还需要核实公开项目信息、真实 fnOS 环境、端口/外部依赖失败提示和截图材料缺口。

## Target End State

1. 任务卡用“第 N 季 / 第 N 集”表达季集信息，维度区不再显示原始 `season` / `episode`。
2. 任意正常完成且文件仍位于已授权片库内的任务，可创建一条关联“人工调整位置”任务。
3. 用户可以选择启用的目标片库和安全相对子目录；确认前可看到原位置、目标位置与文件包信息。
4. 移动继续使用现有影片+字幕文件包、SHA-256、no-replace、冲突人工处理和重启恢复协议；原任务保持完成，新任务永久保留人工干预记录。
5. GitHub、fnOS 和发布材料形成可核对清单；不把本地检查冒充官方审核或跨架构真机验收。

## Scope and Non-Goals

### In scope

- 任务卡季集业务文案与重复字段收敛。
- 普通成功任务创建关联重新整理任务。
- 已授权片库根 + 相对子目录选择、服务端二次校验、任务详情预览与确认。
- 人工调整原因、原路径、目标路径和关联记录持久化。
- 正常完成、冲突、重复提交、路径穿越、符号链接、文件缺失、移动失败和恢复测试。
- 上架环境与不可用提示的只读检查。

### Non-goals

- 不扫描全片库猜测用户在 fnOS 文件管理器中进行的外部移动。
- 不允许移动到未授权目录、来源目录或应用私有目录。
- 不允许直接覆盖、删除目标片库已有影片。
- 不在本轮提交飞牛应用中心，也不对用户真实影片执行试移动。
- 不生成或发布新 FPK，除非用户后续明确要求。

## Proposed Solution

### 业务化季集展示

- 任务卡上方将 `S01/E01` 改为“第 1 季 / 第 1 集”。
- 维度渲染过滤 `season`、`episode`，避免重复。
- 详情编辑区域仍通过维度定义显示“季数 / 集数”，值使用“第 N 季 / 第 N 集”。

### 人工调整位置

- 复用 `task_kind=REORGANIZE` 和 `parent_task_id`，新增结构化 `reorganization_intent`，至少记录 `reason=user_requested`、原路径、目标 root ID、相对子目录、目标预览和发起时间。
- `POST /api/tasks/{id}/reorganize` 接受 `mode=rules|custom`。`custom` 必须提供启用片库 root ID 和相对子目录；服务端通过 `realpath/commonpath` 再次证明目标在所选根内。
- 普通成功任务使用 `custom` 创建关联任务；兜底任务继续支持 `rules` 流程，避免改变现有合同。
- 自定义位置默认保持当前影片文件名；字幕按当前影片主文件名重新形成一致计划。用户仍须在详情中确认后才开始移动。
- 同一原任务同一时间最多一条活动调整任务；历史成功/失败调整均保留，可再次创建新的关联任务。
- 完成后更新原任务的当前入库路径与最近调整任务 ID，但不改变原任务创建、完成时间和原始入库结果；详情展示调整历史入口。

## Representative UI Proof Slice

```text
已完成任务详情
  [调整存放位置]

调整存放位置
  当前位置：主片库/电影/北海鲸梦 (2021)
  目标片库：[主片库 v]
  目标子目录：[电视剧/英剧/北海鲸梦 (2021)]
  最终位置：主片库/电视剧/英剧/北海鲸梦 (2021)/原文件名.mkv
  将同时移动：影片 1、字幕 2
  [取消] [创建人工调整任务]
```

拒绝标准：允许绝对路径或 `..`、隐藏原/目标路径、直接移动不确认、覆盖同名文件、改写原任务为处理中、移动后历史不可追溯。

## Acceptance Criteria

- 列表中不再出现字面量 `season:`、`episode:`；电视剧显示“第 N 季 / 第 N 集”。
- 正常 `SUCCESS/DONE` 电影能创建人工调整任务，原任务仍为成功。
- 绝对路径、父目录穿越、停用/不存在 root、片库外源文件、符号链接和缺失文件均在零写入状态下拒绝。
- 调整任务列表明确显示“人工调整”，详情显示原位置、目标位置和关联原任务。
- 确认后影片和全部字幕整体移动；同名冲突不覆盖；失败或中断保留可恢复证据。
- 同一父任务并发重复提交只产生一条活动任务；结束后可再次调整且旧记录保留。
- 自动化测试及质量门禁全部通过，真实 fnOS 仅报告实际完成的只读检查和用户截图验收。

## Decision Rationale

- 复用现有重新整理文件包协议，比新增一套移动接口更安全，也天然保留任务状态和恢复能力。
- 目标位置使用“片库 root ID + 相对子目录”，既给用户自主权，又不恢复任意绝对路径。
- 原任务保持成功、另建关联任务，能够区分自动入库事实和后续人工干预事实。
- 外部文件管理器移动无法可靠关联字幕和历史，因此不作为第一版支持路径。

## Constraints and Boundaries

- 目标片库默认只新增；任何冲突必须人工决定且禁止静默覆盖。
- 目标和来源都必须是当前启用片库根下的普通文件，拒绝符号链接和挂载漂移。
- 任务状态仍以 transitions 为唯一事实源；API 只解析参数。
- 前端保持原生 HTML/CSS/JS，不新增框架或 CSS 文件。

## Risk Analysis

- 父任务路径不更新会导致下一次调整指向旧文件：成功提交和恢复完成必须同步父任务当前路径及字幕记录。
- 自定义目标绕过分类规则可能造成片库结构不一致：界面默认推荐按规则，自定义路径明确标记为人工选择。
- 并发创建或并发出现目标文件可能覆盖：沿用活动任务查询、no-replace 和目标复核。
- 任意相对路径输入可能穿越：服务端以 root ID 解析并执行绝对路径、`..`、`realpath/commonpath` 与根目录本身门禁。
