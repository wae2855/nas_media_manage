# 置信度引擎 — 技术文档

> 对应源码：
> - `media_importer/scraper/filename_cleaner.py` — 文件名正则/AI 清洗
> - `media_importer/scraper/title_matcher.py` — 标题匹配 T 值计算
> - `media_importer/scraper/trace_builder.py` — 刮削追踪构建
> - `media_importer/scraper/confidence_engine.py` — 置信度综合计算
> - `media_importer/scraper/confidence_models.py` — 数据模型定义

> 从 `scraper/confidence_engine.py` 拆分而来。刮削流程和 Provider 相关文档见 [刮削引擎](刮削引擎.md)，置信度计算完整细节见 [confidence-engine.md](confidence-engine.md)。

---

## 1. 概述

置信度引擎负责从文件名中提取结构化信息（标题、年份、季集），计算 Provider 搜索结果的标题匹配度（T 值），并综合搜索置信度和数据门控得出最终置信度。设计采用 **清洗 → 匹配 → 追踪 → 计算** 四阶段流水线：

```
文件名 ──→ FilenameCleaner ──→ TitleMatcher ──→ ScrapeTraceBuilder ──→ ConfidenceEngine
              清洗提取           T 值计算          追踪记录构建         综合置信度
```

核心类关系：

| 类 | 文件 | 职责 |
|---|---|---|
| `FilenameCleaner` | filename_cleaner.py | 文件名正则/AI 清洗 |
| `TitleMatcher` | title_matcher.py | 标题匹配分 T 计算 |
| `ScrapeTraceBuilder` | trace_builder.py | 刮削追踪记录构建 |
| `ConfidenceEngine` | confidence_engine.py | 置信度综合计算 |
| 数据模型 | confidence_models.py | CleanResult、ConfidenceResult 等数据类 |

## 2. 文件名清洗

**类**: `FilenameCleaner`（源码：`scraper/filename_cleaner.py`）

### 2.1 清洗流程

```
原始文件名
  │
  ▼
① 移除扩展名 (.mkv/.mp4/...)
② 移除制作组标签 [EPSiLON]
③ 提取尾部发布组 -FGT（防误判：排除编解码器前缀、广告后缀）
④ 移除多集标记 S01E01E02
⑤ 移除季集标记 S01E01（同时提取 season/episode）
⑥ 提取独立季号 S05
⑦ 提取括号年份 (1994)（优先于点号年份）
⑧ 提取点号年份 .1999.
⑨ 移除分辨率 1080p/4K/UHD/...
⑩ 移除源/编解码器 BluRay/x264/DTS-HD.MA.5.1/...
⑪ 移除版本标签 25th.Anniversary.Edition/...
⑫ 移除完整广告 www.xxx.com-加群123456
⑬ 移除广告标记 .com/.net/.org
⑭ 移除方括号内容 [...]
⑮ 移除尾部发布组大写缩写 EVOLVE
⑯ 整理空格 [.\s_-]+ → 空格
  │
  ▼
⑰ 中英分离：检测 "中文标题 英文标题" 模式
    cjk_title = 中文部分, clean_title = 英文部分
  │
  ▼
⑱ 年份可疑检测：year > 当前年+1 或标题中残留年份 → year_suspect=True
  │
  ▼
CleanResult(clean_title, year, season, episode, cjk_title, year_suspect, removed_items)
```

### 2.2 发布组提取的防误判

步骤 ③ 在步骤 ⑩ 之前执行，原因：编解码器正则的前缀 `[.\s_-]` 会吃掉 `-` 分隔符。

防误判规则：

| 规则 | 正则 | 防护场景 |
|------|------|----------|
| 编解码器前缀排除 | `_CODEC_PREFIX_RE` | `-DTS`, `-Atmos` 不被误判为发布组 |
| 广告后缀排除 | `_AD_FULL_PATTERN` | `www.xxx.com-加群123456` 中 `-加群123456` 不被误判 |

### 2.3 AI 清洗

当正则清洗结果可疑（`year_suspect=True`）或 Provider 搜索匹配不足时，触发 AI 清洗：

```
FilenameCleaner.ai_clean(filename, llm_scraper)
  │
  ├─ 构造提示词：从文件名提取标题和年份
  ├─ 调用 llm_scraper.extract_title()（使用 fast_model）
  ├─ 解析 JSON 响应：{"title": "...", "year": ...}
  │
  └─ 返回 CleanResult(method="ai")
      失败时回退到 regex 清洗
```

### 2.4 中英分离

当文件名包含中英双语标题时（如 `肖申克的救赎 The Shawshank Redemption`），分离出 `cjk_title` 和 `clean_title`，分别用于 Provider 搜索以提高命中率。

## 3. 标题匹配

**类**: `TitleMatcher`（源码：`scraper/title_matcher.py`）

### 3.1 匹配级别

| 级别 | 条件 | T 值 | 默认值 |
|------|------|------|--------|
| L1 | 精确匹配 + 年份一致 | 固定 | 1.0 |
| L2 | 精确匹配 + 有季号 | 固定 | 0.9 |
| L3 | 精确匹配 + 无年份/季号 | 固定 | 0.7 |
| L4 | 精确匹配 + 年份不匹配 | 固定 | 0.4 |
| L5 | 模糊匹配 + 年份一致 | best_sim | — |
| L6 | 模糊匹配 + 无年份/年份不匹配 | best_sim × 0.7 | — |
| L7 | 相似度 < 0.3 | 0.0 | — |

### 3.2 匹配流程

```
normalize(clean_title) vs normalize(provider_title/original_title)
  │
  ├─ 精确匹配 (normalized 相等)?
  │   ├─ 有年份 + 一致 → L1 (1.0)
  │   ├─ 有年份 + 不一致 → L4 (0.4)
  │   ├─ 有季号 → L2 (0.9)
  │   └─ 无年份无季号 → L3 (0.7)
  │
  └─ 模糊匹配 (SequenceMatcher)
      ├─ sim < 0.3 → L7 (0.0)
      ├─ 年份一致 → L5 (T=sim)
      └─ 无年份/不一致 → L6 (T=sim×0.7)
```

规范化：`lower().replace(' ','').replace('.','').replace('-','').replace('_','')`

相似度：`difflib.SequenceMatcher`，取与 `title` 和 `original_title` 中较高值。

### 3.3 两个匹配接口

| 方法 | 输入 | 使用场景 |
|------|------|----------|
| `match()` | `clean_title`, `tmdb_result: dict` | 旧接口，兼容 dict 格式 |
| `match_standard()` | `clean_title`, `search_item: SearchItem` | 新接口，Provider 抽象层使用 |

逻辑完全一致，仅输入类型不同。

## 4. 刮削追踪构建

**类**: `ScrapeTraceBuilder`（源码：`scraper/trace_builder.py`）

### 4.1 职责

构建刮削过程的追踪记录（`scrape_trace`），记录每一步的决策路径和中间结果，用于调试和置信度门控判定。

### 4.2 追踪内容

追踪记录包含以下信息：

| 字段 | 说明 |
|------|------|
| `clean_method` | 清洗方法：regex / ai |
| `clean_title` | 清洗后的标题 |
| `search_title` | 实际搜索使用的标题 |
| `provider_type` | 使用的 Provider 类型 |
| `match_T` | 标题匹配 T 值 |
| `match_level` | 匹配级别（L1~L7） |
| `search_conf` | 搜索置信度 |
| `data_gate` | 数据门控结果 |
| `final_confidence` | 最终置信度 |
| `gate_blocked` | 是否被门控阻断 |

## 5. 置信度计算

**类**: `ConfidenceEngine`（源码：`scraper/confidence_engine.py`）

### 5.1 计算模型

搜索置信度 × 数据门控的二元判定模型：

```
final = search_conf × data_gate
search_conf = T(标题匹配) × R_dynamic(结果数惩罚)
data_gate = 全部维度来源信任 ? 1.0 : 0
```

### 5.2 两个计算入口

| 方法 | 场景 | 说明 |
|------|------|------|
| `calculate()` | Provider+AI 模式 | `final = search_conf × data_gate` |
| `calculate_ai_only()` | 纯 AI 模式 | `final = objective_cap × data_gate` |

### 5.3 置信度与任务状态的映射

| 置信度判定 | 任务状态 | 说明 |
|-----------|----------|------|
| PASS (≥0.8) | SUCCESS | 自动入库 |
| CONFIRMING (0.5~0.8) | CONFIRMING | 需人工确认 |
| NEEDS_REVIEW (0.3~0.5 或 gate_blocked) | NEEDS_REVIEW | 需审核 |
| FAILED (<0.3) | FAILED | 失败 |

> 置信度计算的完整细节（R 公式、门控逻辑、AI 上限等）见 [confidence-engine.md](confidence-engine.md)

## 6. 数据模型

**源码**: `scraper/confidence_models.py`

### 6.1 CleanResult

| 字段 | 类型 | 说明 |
|------|------|------|
| `clean_title` | str | 清洗后的英文标题 |

| `confidence_search` | float | 搜索置信度 |

## 7. 职责边界

### 负责

- 文件名清洗（正则 16 步 + AI Fallback）
- 标题匹配（L1~L7 七级匹配体系）
- 刮削追踪记录构建
- 置信度综合计算（search_conf × data_gate）
- 数据模型定义（CleanResult、ConfidenceResult）

### 不负责

- Provider 搜索与详情获取（由 Provider 模块执行）
- AI 刮削提示词构建与 API 调用（由 LLMScraper 执行）
- 维度映射（由 dimension_manager 执行）
- 流水线编排（由 pipeline 模块执行）
