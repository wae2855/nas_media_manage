# 配置迁移模块技术文档

**对应源码路径**

| 模块 | 路径 |
|------|------|
| 配置键迁移 | `media_importer/core/config_migrations.py` |
| 数据库维度迁移 | `media_importer/core/db/migrations.py` |

> 从 `core/config_loader.py` 拆分而来。配置加载、校验、脱敏等功能文档见 [配置系统](配置系统.md)。

---

## 1. 概述

配置迁移模块负责将旧版配置键自动转换为新版格式，确保用户升级后无需手动修改配置文件即可正常运行。迁移逻辑在 `load_config()` 加载流程中自动执行，采用 `setdefault` 语义（仅当新键不存在时才从旧键迁移，不覆盖用户已配置的新值）。

---

## 2. 配置键迁移

**源码**: `core/config_migrations.py`

### 2.1 迁移规则

| 旧键 | 新键 | 迁移规则 |
|------|------|----------|
| `source_dedup.quarantine_dir` | `source_policy.quarantine_dir` | 取旧值，不覆盖已有 |
| `source_dir_scan.recursive` | `source_policy.scan_recursive` | 取旧值，不覆盖已有 |
| `source_dir_scan.max_depth` | `source_policy.scan_max_depth` | 取旧值，不覆盖已有 |
| `source_policy.cleanup_mode` = "read_only" | `source_policy.cleanup_source_after_done` = false | read_only 映射为不清理 |
| `source_policy.cleanup_mode` = "full_cleanup" | `source_policy.cleanup_source_after_done` = delete_source_after_import 的值或 true | full_cleanup 映射为清理 |
| `source_policy.cleanup_mode` = "smart_cleanup" | `source_policy.cleanup_source_after_done` = delete_source_after_import 的值或 true | smart_cleanup 映射为清理，同时启用 source_cleaner |
| `source_policy.delete_source_after_import` | `source_policy.cleanup_source_after_done` | 取旧值，不覆盖已有 |
| `source_policy.smart_cleanup` | `source_cleaner` | 整体迁移为顶层 source_cleaner 配置段 |
| `source_file_handling` | （删除） | 直接删除，删除后处理为默认行为 |
| `task_queue.persistence_path` | （删除） | 直接删除 |
| `source_cleaner.cleanup_mode` = "keep_media_only" | `source_cleaner.cleanup_mode` = "media_only" | 取旧值，自动迁移 |
| `source_cleaner.cleanup_mode` = "keep_media_related" | `source_cleaner.cleanup_mode` = "media_and_related" | 取旧值，自动迁移 |

### 2.2 迁移特点

- 使用 `setdefault` 语义：仅当新键不存在时才从旧键迁移，不覆盖用户已配置的新值
- 旧键通过 `config.pop()` 移除，迁移后不再保留
- 迁移逻辑在 `load_config()` 的第 5 步执行（路径解析之后、默认值填充之前）

### 2.3 cleanup_mode 迁移详解

`cleanup_mode` 是最复杂的迁移项，涉及三个旧值到布尔值的映射：

```
cleanup_mode = "read_only"
  → cleanup_source_after_done = false
  → 不清理源文件

cleanup_mode = "full_cleanup"
  → cleanup_source_after_done = delete_source_after_import 的值或 true
  → 入库后自动清理源文件

cleanup_mode = "smart_cleanup"
  → cleanup_source_after_done = delete_source_after_import 的值或 true
  → 同时启用 source_cleaner（独立清理器）
```

### 2.4 smart_cleanup 整体迁移

`source_policy.smart_cleanup` 不再是简单键值替换，而是整体迁移为 `source_cleaner` 顶层配置段：

```yaml
# 旧配置
source_policy:
  smart_cleanup:
    enabled: true
    keep_media_only: true

# 迁移后
source_cleaner:
  enabled: true
  cleanup_mode: "media_only"
```

## 3. confidence v1 → v2 迁移

**源码**: `core/config_migrations.py` 中的 `_migrate_confidence_v1_to_v2()`

### 3.1 移除的 v1 键

| 移除的 v1 键 | 说明 |
|--------------|------|
| `aggregation_method` | 聚合方法（v2 不再使用） |
| `tmdb_dim_confidence` | TMDB 维度置信度 |
| `file_dim_confidence` | 文件维度置信度 |
| `dim_missing_confidence` | 维度缺失置信度 |

### 3.2 维度级 v1 → v2 迁移

| 移除的 v1 维度键 | v2 替代 |
|------------------|---------|
| `weight` | 不再使用 |
| `veto_threshold` | 不再使用 |
| `source_confidence` | 不再使用 |
| `tmdb_confidence` | 不再使用 |
| `ai_confidence` | 不再使用 |
| `file_confidence` | 不再使用 |
| `missing_confidence` | 不再使用 |
| `trusted_sources` | 迁移为 `sources` 列表 |

### 3.3 trusted_sources → sources 迁移示例

```yaml
# v1
trusted_sources: ["tmdb", "ai"]

# v2
sources:
  - source: tmdb
    trusted: true
  - source: ai
    trusted: true
  - source: file
    trusted: false
```

迁移逻辑：遍历 `trusted_sources` 列表，每个源标记为 `trusted: true`；不在列表中的已知源（tmdb/ai/file）标记为 `trusted: false`。

## 4. 数据库维度迁移

**源码**: `core/db/migrations.py`

### 4.1 职责

数据库维度迁移负责在数据库 schema 或维度结构变更时自动升级数据。与配置键迁移不同，数据库迁移需要处理持久化存储的结构变更。

### 4.2 迁移触发

数据库迁移在服务启动时自动检测并执行，通过版本号判断是否需要迁移。

---

## 5. 迁移在加载流程中的位置

```
config.yaml (磁盘)
      │
      ▼
  yaml.safe_load()
      │
      ▼
  路径解析（相对→绝对）
      │
      ▼
  配置键迁移 ← 本模块负责（config_migrations.py）
      │
      ▼
  默认值填充
      │
      ▼
  confidence v1 → v2 迁移 ← 本模块负责（config_migrations.py）
      │
      ▼
  validate_config() 基础校验
      │
      ▼
  布尔字符串归一化
      │
      ▼
  运行时 config dict
```

---

## 6. 职责边界

### 负责

- 配置键自动迁移（旧键→新键，向后兼容）
- confidence v1 → v2 版本升级
- 数据库维度迁移
- 迁移语义保证（setdefault，不覆盖已有配置）

### 不负责

- 配置文件加载与解析（由 config_loader 执行）
- 默认值填充（由 config_loader 执行）
- 配置校验（由 config_validator 执行）
- 敏感信息脱敏（由 config_loader 执行）
