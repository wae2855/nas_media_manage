# 配置页面卡片化改造方案

> 将配置页从二级Tab导航改为卡片钻入式导航，提升配置引导性和层次感

---

## 一、背景与目标

### 1.1 当前问题

当前配置页面采用 **二级 Tab 导航**：

```
配置Tab → 子Tab栏(入库设置 | AI刮削 | 通知安全 | 高级设置) → Section 竖向堆叠
```

存在以下问题：

1. **缺乏配置引导**：用户不知道应该先配什么、后配什么，子Tab之间没有顺序关系
2. **配置项扁平堆叠**：每个子Tab下多个Section竖向排列，缺少层次感
3. **高级配置与基础配置平级**：置信度计算、安全配置等高级项与基础项混在一起，新手容易被干扰
4. **目录配置不够直观**：源目录→中转目录→回收站的数据流关系没有体现

### 1.2 改造目标

1. **卡片导航主页**：用卡片平铺代替Tab按钮，一目了然
2. **配置顺序引导**：基础配置4个卡片之间用箭头连接，引导用户按顺序配置
3. **层级分离**：基础配置与高级配置通过视觉分隔线区分
4. **数据流可视化**：目录配置子页面用箭头展示 源目录→中转目录→入库规则 的数据流
5. **面包屑导航**：提供清晰的导航上下文，用户随时知道自己在哪里

### 1.3 改造后架构

```
配置Tab → 卡片主页(Level 0) → 子卡片页(Level 1, 仅目录配置有) → 配置表单(Level 2)
```

---

## 二、导航层级设计

### Level 0：配置卡片主页

切换到"配置"Tab时，不再显示子Tab栏，而是直接展示卡片网格：

```
┌──────────┐  ➜  ┌──────────┐  ➜  ┌──────────┐  ➜  ┌──────────┐
│ 📁目录配置 │     │ 🎬影视刮削 │     │ 🤖 AI配置  │     │ ⏰定时任务 │
└──────────┘     └──────────┘     └──────────┘     └──────────┘

                        ⬇ 高级配置

┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐
│入库名称规范│  │影视分类维度│  │AI刮削提示词│  │置信度计算  │
└──────────┘  └──────────┘  └──────────┘  └──────────┘
┌──────────┐  ┌──────────┐  ┌──────────┐
│ 安全配置  │  │Hermes通知 │  │ 系统设置  │
└──────────┘  └──────────┘  └──────────┘
```

- 第一排4个卡片之间用 **➜ 箭头** 连接，提示用户按顺序配置
- 第一排下方是一个大的 **⬇ 高级配置** 视觉分隔线（含文字标识）
- 下方7个高级卡片无箭头，普通网格排列

### Level 1：目录配置子页面

点击"目录配置"卡片后，整个配置区域刷新为流程图式的子卡片布局：

```
← 返回    配置 > 目录配置

┌──────────┐  ➜  ┌──────────┐  ➜  ┌──────────┐
│  源目录   │     │  中转目录  │     │  入库规则  │
└──────────┘     └──────────┘     └──────────┘
                     ⬇
                 ┌──────────┐
                 │ 回收站目录 │
                 └──────────┘
```

- 4个子卡片用箭头连接，表示数据流方向
- 中转目录向下箭头指向回收站目录

### Level 2：具体配置表单

点击任一子卡片后，整个区域刷新为对应的配置表单内容。例如点击"源目录"：

```
← 返回    配置 > 目录配置 > 源目录

┌─────────────────────────────────────┐
│ 源目录 *                             │
│ [________________] [测试权限]         │
│                                     │
│ 递归扫描源目录                        │
│ [toggle]                            │
│                                     │
│ 最大递归深度                          │
│ [___5___]                           │
│                                     │
│ ┌───────────────────────────────┐   │
│ │ 🧹 源文件智能清理     [进入 →] │   │
│ └───────────────────────────────┘   │
│                                     │
│ [保存]                               │
└─────────────────────────────────────┘
```

- "源文件智能清理"是一个**入口按钮卡片**，点击后进入source_cleaner section完整配置
- 面包屑变为：`配置 > 目录配置 > 源目录 > 源文件智能清理`

### 3.2 高级配置区（7个卡片）

## 四、关键改动点

### 4.1 HTML 改动

#### 移除

- `config-sub-tabs` 导航栏（入库设置/AI刮削/通知安全/高级设置 4个子Tab按钮）

#### 新增

1. **卡片主页容器** `#config-cards-home`：包含11个导航卡片
2. **目录配置子卡片容器** `#config-dir-sub-cards`：包含4个子卡片 + 箭头连接器
3. **面包屑导航栏** `#config-breadcrumb`
4. **video_extensions、subtitle_extensions** 两个配置字段（添加到 advanced section）

#### 修改

1. `basic` section 的 form-group 添加 `data-view-group` 属性，用于按视图分组显示/隐藏：

   | data-view-group | 包含字段 |
   |----------------|---------|
   | `source` | source_dir, source_dir_scan-recursive, source_dir_scan-max_depth |
   | `temp` | temp_dir |
   | `recycle` | recycle_dir, recycle_retention_days, cleanup_source_after_done |

2. `llm` section 添加 `data-view-group` 属性：

   | data-view-group | 包含内容 |
   |----------------|---------|
   | `llm-config` | LLM配置字段（provider、api_key、base_url等） |
   | `llm-prompt` | 提示词编辑面板（prompt-system、provider tabs、编写指南） |

3. `import_options` section 中 `cfg-manual_review-enabled`：
   - 在"入库规则"视图中额外展示
   - 在"入库名称规范"视图中隐藏

### 4.2 JS 改动

#### 新增导航系统（config.js）

```javascript
var _navStack = ['home'];  // 导航栈

function navTo(viewId) { ... }      // 进入子页面，push到栈
function navBack() { ... }          // 返回上一级，pop栈
function renderView(viewId) { ... }  // 渲染当前视图
function updateBreadcrumb() { ... }  // 更新面包屑
```

#### 视图ID与渲染逻辑

| viewId | 渲染行为 |
|--------|---------|
| `home` | 显示卡片主页，隐藏所有 config-section |
| `dir-sub` | 显示目录配置子卡片页 |
| `source` | 显示 basic section 中 `data-view-group="source"` 的表单组 |
| `temp` | 显示 basic section 中 `data-view-group="temp"` 的表单组 |
| `recycle` | 显示 basic section 中 `data-view-group="recycle"` 的表单组 |
| `source-cleaner` | 显示 source_cleaner section |
| `path-rules` | 显示 path_rules section + cfg-manual_review-enabled |
| `metadata-providers` | 显示 metadata.providers section |
| `llm-config` | 显示 llm section 中 `data-view-group="llm-config"` 部分 |
| `llm-prompt` | 显示 llm section 中 `data-view-group="llm-prompt"` 部分 |
| `file-watcher` | 显示 file_watcher section |
| `import-options` | 显示 import_options section（不含 cfg-manual_review-enabled） |
| `dimensions` | 显示 dimensions section |
| `confidence` | 显示 confidence section |
| `server` | 显示 server section |
| `hermes` | 显示 hermes section |
| `advanced` | 显示 advanced section + video/subtitle extensions |

#### 修改

- `switchTab('config')` 不再调用 `applyConfigSubTab`，改为调用 `navTo('home')`
- 移除 `switchConfigSubTab` 和 `applyConfigSubTab` 函数
- `saveSection` 逻辑保持不变（表单字段仍在DOM中，只是部分隐藏）

#### 新增保存逻辑

- `_buildAdvancedData()` 增加 `video_extensions` 和 `subtitle_extensions` 字段收集
- 入库规则视图的保存需要同时保存 `path_rules` 和 `import_options`

### 4.3 CSS 改动

#### 新增样式

| 样式类 | 用途 |
|--------|------|
| `.config-card-grid` | 卡片网格布局（CSS Grid） |
| `.config-nav-card` | 导航卡片样式（cinema主题风格） |
| `.config-nav-card:hover` | 悬停效果（上浮 + 发光边框） |
| `.card-arrow` | 卡片间箭头连接器（CSS ::after 伪元素） |
| `.config-breadcrumb` | 面包屑导航栏 |
| `.config-advanced-divider` | 高级配置分隔指示器（⬇ 箭头 + 文字） |
| `.config-view-container` | 视图切换容器（含过渡动画） |

### 4.4 后端改动

#### 新增配置项

`advanced` section 的保存需要支持 `video_extensions` 和 `subtitle_extensions` 字段：

- 前端 `_buildAdvancedData()` 收集这两个字段
- 后端 config_validator.py 增加验证逻辑（后缀名格式校验）
- 后端保存时写入 config.yaml

## 五、目录配置特殊处理

### 5.1 basic section 的拆分展示

当前 `basic` section 包含7个字段，需要按视图拆分展示：

**关键决策：表单字段在HTML中保持原位，不物理拆分。** 通过 `data-view-group` 属性 + JS `show/hide` 控制可见性。保存时仍调用 `saveSection('basic')`，所有字段值都会被收集（包括隐藏的）。

每个子视图都有独立的 **保存** 按钮和 **验证权限** 按钮。

### 5.2 "启用入库前检查"的位置变更

- 该字段（`cfg-manual_review-enabled`）在HTML中仍属于 `import_options` section
- 在"入库规则"视图中通过JS额外显示该字段
- 在"入库名称规范"视图中隐藏该字段
- 保存时属于 `import_options` 的保存逻辑

### 5.3 源文件智能清理入口

在"源目录"视图底部，不直接展示source_cleaner的完整配置，而是放置一个**入口按钮卡片**：

```
┌─────────────────────────────────────┐
│ 🧹 源文件智能清理                     │
│ 配置源目录的自动清理策略              │
│                          [进入 →]   │
└─────────────────────────────────────┘
```

点击后导航到 source_cleaner section 的完整配置页面。

## 六、导航栈状态管理

### 6.1 导航栈数据结构

```javascript
_navStack = [
    { view: 'home', breadcrumb: '配置' }
]

// 用户点击"目录配置"后：
_navStack = [
    { view: 'home', breadcrumb: '配置' },
    { view: 'dir-sub', breadcrumb: '目录配置' }
]

// 用户点击"源目录"后：
_navStack = [
    { view: 'home', breadcrumb: '配置' },
    { view: 'dir-sub', breadcrumb: '目录配置' },
    { view: 'source', breadcrumb: '源目录' }
]

// 用户点击"源文件智能清理"后：
_navStack = [
    { view: 'home', breadcrumb: '配置' },
    { view: 'dir-sub', breadcrumb: '目录配置' },
    { view: 'source', breadcrumb: '源目录' },
    { view: 'source-cleaner', breadcrumb: '源文件智能清理' }
]
```

### 6.2 导航行为

- **点击卡片**：push 新视图到栈，渲染新视图
- **点击面包屑某一级**：截断栈到该级，渲染对应视图
- **点击返回按钮**：pop 栈顶，渲染上一级视图
- **切换到其他主Tab（概览/任务/回收站）再切回配置**：恢复栈状态（不清空）

## 八、风险评估

| 风险 | 影响 | 应对 |
|------|------|------|
| basic section 拆分后保存验证冲突 | 用户在"源目录"视图保存时，temp_dir可能为空导致验证失败 | 隐藏字段值仍在DOM中，已填的值不会丢失；仅首次配置时需要按顺序填写 |
| llm section 拆分展示提示词 | 保存时需确保提示词数据完整收集 | 不物理拆分HTML，仅通过CSS/JS控制可见区域，保存逻辑不变 |
| import_options 的"启用入库前检查"跨section展示 | 该字段在入库规则和入库名称规范两个视图中都有关系 | 通过JS在入库规则视图中动态插入该字段的引用展示 |
| 导航栈状态丢失 | 用户刷新页面后导航状态丢失 | 导航栈不持久化，刷新后回到卡片主页（可接受） |
