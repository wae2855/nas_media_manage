# 入库规则显式选择目标片库

- **Requirement**: [REQ-20260830-180954](../tracking/requirements-board.md)
- **Status**: complete

片库目录与入库规则是两类独立事实：存储检查只登记可用片库，片库整理必须由用户逐条决定规则写入哪个片库。

## 问题陈述

当前后端会把缺少 `library_root_id` 的规则回退到 `default_library_root_id`，前端也把未绑定规则显示并预选为默认片库。这会在多片库场景中替用户猜测业务分流。另一方面，要求每个片库至少被一条规则使用也不合理：用户可以先添加备用磁盘，或只让部分片库参与当前规则。

## 目标终态

- 每条启用的入库规则明确保存一个非空 `library_root_id`。
- 引用不存在或已停用片库的规则被明确拦截，并显示规则名称及问题片库。
- 允许任意片库暂时没有规则引用，不警告、不删除、不自动补规则。
- 存储检查可以先保存 0～N 个片库；规则尚未分配属于配置中的待完成状态，不阻止继续配置，但阻止后台运行和正式任务。
- 旧绝对路径只作为用户逐条设置时的参考；系统不得按添加顺序、默认片库或规则序号自动分配。

## 范围与非目标

### 范围

- 多片库规范化、运行时路径解析和规则保存校验。
- 旧规则待关联状态与存储检查到片库整理的引导。
- 规则卡片、规则编辑弹窗、兜底目录目标片库选择。
- 开场检查与自动运行门禁。
- 新装、旧版绝对规则、片库被移除/停用及未使用片库回归。

### 非目标

- 不要求所有片库都被规则覆盖。
- 不根据片库名称、添加顺序或磁盘编号推断业务分类。
- 不移动、复制、删除或重排已有影片。
- 不改变维度条件、命名模板和冲突确认规则。

## 方案

### 1. 配置的暂存态与完成态

`library_roots` 可以独立保存。规则缺少 `library_root_id` 时保持未绑定，不再写入默认片库；旧绝对模板也可在迁移待完成期间原样保留。只有“保存片库整理规则”和运行时解析要求全部规则完成显式绑定。

后端提供统一的规则引用检查：

- 未选择：`第 N 条规则“名称”尚未选择目标片库`。
- 不存在：`第 N 条规则“名称”引用的片库不存在`。
- 已停用：`第 N 条规则“名称”引用的片库已停用`。
- 不检查“某个片库是否被任何规则引用”。

兜底目录非空时同样必须显式选择 `fallback_library_root_id`。

### 2. 旧规则逐条人工关联

存储检查完成片库添加后，不再提供“一键按路径关联”。页面提示用户前往“片库整理”。规则卡显示旧路径和“尚未选择片库”；编辑弹窗先让用户选择目标片库，再填写未来使用的相对子目录。

若旧绝对路径确实位于用户刚选择的片库根下，界面可以在用户主动选择该片库后给出相对子目录建议；选择动作仍由用户完成。若不在该根下，子目录保持待填写，不做猜测。

### 3. 运行门禁

开场检查列出未绑定、失效或停用引用并指向“片库整理”。任何文件副作用入口继续由现有配置/存储门禁阻止，不允许运行时再回退默认片库。

## 决策理由

- 以规则引用为单向约束：`规则 → 片库` 必须有效；`片库 → 规则` 不要求被使用，符合用户可以准备备用片库的事实。
- 允许目录先保存、规则后完成，才能维持“存储检查 → 片库整理”的自然配置顺序。
- 旧路径只用于展示和相对路径建议，避免将物理路径关系误当成用户未来的业务分类决定。

## 设计合同

- **目标感受**：用户能清楚看到“哪些规则还没决定去哪里”，而不是发现系统已替自己选择第一个片库。
- **参考**：现有 `rule-inline-item` 和规则编辑弹窗；继续使用 cinema 黑金样式与胶卷轨道。
- **反例**：未绑定规则显示成默认片库；选择第一个片库后全部规则自动归属；为了消除提示强迫每个片库创建规则。
- **证明切片**：一条旧绝对规则在规则卡显示“尚未选择片库”，编辑后明确显示用户选中的片库与相对模板。
- **推广门禁**：证明切片通过桌面与 390px 真实浏览器验证后，再覆盖兜底目录和全部规则保存。
- **拒绝条件**：任何规则仍能在没有显式 `library_root_id` 时进入运行路径；任何未使用片库被当作错误。
- **预览产物**：未绑定规则卡与规则编辑弹窗的桌面/390px 截图、无横向溢出和 console error 证据。

## 验收标准

1. 新装添加两个片库后，预置规则均显示“尚未选择片库”，没有任何规则自动绑定第一个片库。
2. 用户逐条选择后，规则保存明确持久化所选 `library_root_id`。
3. 规则引用不存在或停用片库时，保存和开场检查都显示规则名称、问题原因和修复入口。
4. 三个片库中只有一个被规则使用时，配置保存和开场检查不因另外两个未使用而报错。
5. 旧绝对路径不会因根目录添加顺序自动映射；用户选择目标片库后才转换为相对模板。
6. 未绑定规则无法进入任何正式文件处理路径，片库文件无移动、覆盖或删除。
7. 1440px 与 390px 页面无横向溢出，动态文案转义，console error 为 0。

## 风险与缓解

- **兼容旧单片库配置**：已明确保存的旧 `library_root_id` 保持不变；缺失引用只进入待完成，不静默迁移。
- **运行时代码仍回退默认根**：路径解析层改为 fail closed，并补直接调用测试。
- **用户面对多条规则工作量增加**：保留现有预置规则和条件，只要求选择目标片库与必要的相对子目录，不新增第二套导航。
- **旧绝对路径转换丢失模板变量**：建议逻辑只截取根路径前缀，完整保留 `{title_cn}`、`{year}` 等模板后缀。
