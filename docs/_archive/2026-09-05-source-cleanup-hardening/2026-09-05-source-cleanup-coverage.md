# 来源清理按文件覆盖复核与链路补测

关联 [需求看板](../tracking/requirements-board.md) 与 [计划](../plans/2026-09-05-fix-source-cleanup-coverage-plan.md)。用户授权评审成立后实施、扩展场景测试并生成安装包。

## 证据与目标

当前协调器要求同一来源单元的每一条历史任务成功，重复失败/跳过记录会永久阻挡同一文件的成功结果。真机展示的两条北海鲸梦历史记录是否同一单元尚未取得数据库证据，不凭同名作清理决定。

另有直接收尾仅更新当前任务、重启恢复保留未成为清理门禁的问题。目标是解除可证明的重复历史阻挡、同步关联任务来源结果并尊重保留决定。

## 方案与边界

- 仅同一单元快照、同一真实来源路径、终态失败/跳过的非人工处置记录允许用成功文件包覆盖。必须复核提交清单、影片和全部字幕来源/目标 SHA-256、路径边界和来源快照；缺证据失败关闭。
- 待确认/排队/运行/取消、人工保留、重启恢复保留均不被覆盖；不把历史状态改成成功，不跨来源代际拼接。
- 只在实际待清理且存在历史重复时读取关联片库文件，不做空闲片库扫描；大文件校验发出进度事件。
- 所有关联任务及时得到来源结果，但人工处置结果保留；清理操作串行、重复调用幂等，异常逐单元隔离。
- 复用现有回收/永久删除隔离账本，不操作 fnOS 真机文件，不安装、不发布云端。

不采用“忽略全部跳过记录”或“只看文件名/大小”：两者都可能误清理尚未入库或明确保留的来源。
