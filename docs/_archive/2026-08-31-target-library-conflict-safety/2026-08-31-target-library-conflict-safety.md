# 目标片库冲突确认与安全替换

## 问题

现有重复策略会自动跳过、改名或将片库现有影片移入回收，最终同名路径又会直接失败。用户既看不到两份文件的对比，也没有独立的覆盖授权，无法形成“目标库默认只新增”的可信承诺。

## 目标

- 冲突检测只读，发现冲突时来源与目标均保持原样。
- 同作品候选和同名目标路径统一进入待确认。
- 用户逐项选择保留现有、保留两份或安全替换。
- 替换只走本地回收且可恢复，任何失败都不得永久删除。
- 多片库只处置本任务实际目标根内的文件。

## 方案

复用任务 `PENDING/AWAIT_REVIEW`，把结构化冲突快照持久化在 `dedup_result`。普通确认和批量确认禁止绕过未决冲突；冲突动作携带受限决策值和现有文件指纹，服务端重检后执行。替换先验证新文件和回收边界，再回收旧文件、发布新文件；发布失败自动尝试恢复。

任务详情显示两份文件的路径、大小、清晰度和冲突原因，并明确“现有文件未发生任何改动”。旧自动策略只做配置兼容，运行时统一转为人工确认。

## 影响面

- `features/import_flow`：只读检测、冲突决策、安全替换。
- `features/tasks` / API：冲突确认合同和批量隔离。
- `webui`：任务列表、详情对比与二次确认。
- configuration：重复策略默认值与旧配置兼容。
- docs/tests：任务生命周期、存储安全、API、双端 UI 和真实文件场景。

## 备选

- 保留质量优先自动替换：无法满足用户授权边界，否决。
- 仅在前端增加确认：API 和后台运行仍可绕过，否决。
- 新增冲突状态枚举：会扩大现有状态机；结构化原因配合 `AWAIT_REVIEW` 足够，暂不采用。
