# 本地真实前端文件全流程矩阵验收

## 问题

取消中心中转后的既有回归覆盖了大量后端文件组合和真实浏览器页面状态，但部分浏览器用例通过直接创建任务或预置中断状态开始，不能证明普通用户从前端点击扫描后，识别、确认、目标侧暂存、字幕发布、来源处置和最终任务展示能够在同一场景内闭环。

## 目标

- 在本地隔离开发目录生成电影、电视剧、字幕、重复目标和故障注入文件。
- 每个场景都由真实 Chromium 从产品前端入口操作，不以直接写任务数据库代替业务入口。
- 外部 TMDB 以确定性测试 Provider 隔离网络波动，但扫描、任务、分类、冲突、复制、回收、来源处置和页面刷新使用真实代码。
- 每个场景保存源目录、目标片库、回收区文件树、文件 SHA-256、任务状态 JSON、关键浏览器截图和控制台/HTTP 错误摘要。

## 方案概述

新增一套自启动本地 HTTP 服务的 Playwright 验收矩阵。测试基座为每个场景创建独立配置、SQLite 和文件根，通过浏览器点击扫描、任务详情及确认按钮推进流程。Provider 边界使用固定电影/电视剧候选，避免真实账号、网络和 TMDB 数据变化影响文件流结论。

首轮覆盖：电影正常入库并保留来源、电视剧和字幕整包入库、兜底确认、重复保留、重复另存、单视频替换并回收旧片、来源整组本地回收、来源整组永久删除、提交前中断清理及重试、完整提交后恢复、歧义恢复人工检查，以及父测试进程在真实复制中途对服务进程发送外部 SIGKILL 后的重启与前端重试。

## 影响面

- 测试：新增真实前端矩阵、可复核证据生成器和场景清单。
- 文档：更新文件流矩阵、回归矩阵、需求和验收台账。
- 业务代码：原则上不改；只有真实验收暴露缺陷时才做最小修复，并补对应回归。

## 备选方案

- 继续组合后端测试与页面状态测试：速度快，但仍不能证明用户路径闭环，因此不采用。
- 直接访问真实 TMDB：无法稳定复现，且依赖用户密钥和网络；保留为独立外部烟测，不作为本轮文件安全结论。
- 使用多 GB 真影片：更接近真机但耗时和空间成本过高；本轮使用真实文件 I/O、可控大小与故障注入，fnOS 大文件和断电仍单独验收。
