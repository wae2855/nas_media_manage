# 真实任务阶段与大文件传输进度计划

- **Requirement**: [REQ-20260901-010051](../../tracking/requirements-board.md)
- **Proposal**: [真实任务阶段与大文件传输进度](2026-09-01-truthful-task-progress.md)
- **Status**: complete

让大文件从来源、中转、识别、分类、片库写入到来源处理的每个长耗时阶段都可见、可刷新且不降低安全校验。

## Problem Statement

任务后端已有基础步骤和来源复制字节进度，但列表 API 与前端没有消费；完整性校验、跨盘入库和整组来源回收没有进度通道。用户只能看到“处理中”，而总体百分比又是固定步骤权重，不代表真实耗时。

## Target End State

- 任务卡显示当前阶段、阶段进度、容量和流程位置；详情显示已完成/当前/后续步骤。
- 文件写满后明确进入“校验完整性”，不继续伪装为复制。
- `/vol3` 中转到其他卷的跨盘入库显示真实字节进度。
- 来源整组回收有明确状态，任务不会在来源处理尚未结束时无说明地显示整体完成。
- 任务页运行时每 2～3 秒轻量更新；无运行任务或页面不可见时停止刷新。
- SQLite 进度写入有节流，17 GB 文件不再产生约 1.7 万次 commit。

## Scope and Non-Goals

### Scope

- 安全复制/移动的阶段回调与进度节流。
- 来源→中转、中转→片库、来源→回收的任务进度接入。
- 任务列表 API、任务卡、详情进度、自动刷新和移动适配。
- 对应单元、集成、静态 UI、真实浏览器验收和事实文档。

### Non-Goals

- 不删除或弱化 SHA-256、断点前缀检查、no-replace 发布和片库保护。
- 第一版不承诺准确 ETA；只展示可验证的字节进度、阶段与已运行时间。
- 不引入 WebSocket/SSE、前端框架或新依赖。
- 不把固定步骤百分比描述成剩余时间比例。

## Proposed Solution

### 1. 统一进度事件

文件系统层使用轻量结构化事件：`phase`、`completed_bytes`、`total_bytes`。阶段覆盖恢复检查、传输、源/目标校验和发布。`verified_copy` 保持兼容旧 `(copied,total)` 回调，新的 pipeline 使用结构化回调；`safe_move` 只在跨盘回退时产生字节进度，同盘原子移动直接完成。

### 2. Pipeline 映射与节流

import-flow 把底层 phase 映射到任务 `step_name`，同时维护整体流程位置和阶段字节。进度落库满足以下任一条件时执行：阶段变化、完成、至少 1 秒、至少 1% 或至少 64 MB；心跳最长 30 秒。阶段开始/结束永远立即写入。

### 3. 诚实的任务 UI

卡片只对 `PENDING/RUNNING` 展示进度组件：中文阶段、文件阶段百分比、容量和五段流程位置。非字节阶段只展示当前活动和流程位置。详情使用紧凑五段时间线：准备中转、识别资料、整理规则、写入片库、处理来源。

任务页只在当前视图可见、无弹窗交互阻塞且存在运行任务时轮询；更新现有记录而不是显示全页加载骨架。首页继续使用业务摘要，但活动文案改为当前真实阶段。

### 4. 来源处理生命周期

入库文件发布成功后进入 `source_cleanup`，完成来源策略后再落 `SUCCESS/DONE`。若“片库已写入但来源处理失败”，必须保留 `import_success=1` 和 `import_video_path`，错误文案明确片库文件已安全写入，重启恢复不得重复写入或删除片库文件。

## Subjective Contract

- **目标感受**：像可靠的 NAS 文件任务，而不是不透明的加载动画；用户随时知道“在哪里、还在做什么、文件是否已经写完”。
- **反目标**：不堆技术英文；不显示跳动或倒退的假百分比；不因自动刷新让卡片闪烁、滚动位置丢失或弹窗关闭。
- **正向参考**：现有影院金色状态条、任务卡信息层级、首页真实运行进度。
- **反向参考**：只显示“处理中”、把步骤权重当耗时百分比、每次轮询重建加载骨架。
- **语气**：`正在复制到中转`、`正在校验中转文件`、`正在写入「电影」片库`、`入库完成，正在处理来源文件`。

## Test Plan

- `verified_copy`：新复制、满/部分 `.copying` 恢复、源变化、目标竞争、校验失败，各阶段顺序与字节单调。
- `safe_move`：同盘无复制进度；模拟 EXDEV 时进度透传且源仅在校验发布后删除。
- pipeline：17 GB 等价模拟确保落库次数受节流上限控制；视频+字幕总体进度不倒退。
- import：跨盘写入进度、冲突替换、片库发布后来源处理成功/失败、重启恢复不重复入库。
- API：列表和详情均返回 `current_step/total_steps/step_name/percentage/bytes_copied/total_bytes/started_at`。
- UI：运行卡中文阶段、字节格式、确定/不确定进度；轮询只在任务页且有运行项时启动，弹窗不被重建。
- 浏览器：1280/390/320px 无横向溢出，进度条和文案不挤压状态/操作。

## Acceptance Criteria

- 17 GB 模拟任务可依次观察“复制→校验来源→校验中转→写入片库→校验片库→处理来源”，无超过 30 秒的无阶段心跳。
- 文件传输阶段显示真实 `完成字节/总字节`，同一阶段百分比单调；非字节阶段不显示伪百分比。
- 跨盘入库和整组回收均有状态；来源处理完成前不无说明地宣告整体结束。
- 每 1 MB 回调不会对应一次 SQLite commit；测试证明节流生效且阶段完成不丢失。
- 任务页 2～3 秒内看到进度变化，切换页面后停止轮询，选择状态和滚动位置保持。
- 1280/390/320px 任务卡和详情无横向溢出、无遮挡，减少动态效果时无循环动画。
- 文件安全、片库不可删除、重启恢复和现有任务状态回归全部通过。

## Assumptions

| Assumption | Status | Evidence |
|---|---|---|
| 现有任务表足以承载第一版阶段进度 | Verified | 已有 step/current/total/percentage/bytes 字段，详情 API 可读 |
| 跨盘入库走 `safe_move -> verified_copy` | Verified | EXDEV 分支当前直接调用 verified_copy，fnOS 中转与片库位于不同卷 |
| 云盘来源需要保留完整性校验 | Verified | 来源为 `fuse.rclone`，项目安全规范禁止弱化校验 |
| 轮询足以满足体验 | Verified | 任务处理以秒/分钟计，2～3 秒刷新无需新协议 |
| 来源回收可纳入当前任务进度 | Partially verified | 文件任务可关联 source_unit；多任务共享单元需要聚合并避免进度归属误导 |

## Risk Analysis

- **安全回归**：进度回调只能观察，不改变发布/删除顺序；现有目标竞争、源变化和片库保护测试必须全过。
- **SQLite 压力**：引入节流并用调用次数断言，阶段完成强制 flush。
- **多任务共享来源单元**：只在最后一个完成任务上显示“处理来源”，其余显示“等待同组任务”；单元状态仍是事实源。
- **自动刷新干扰操作**：弹窗打开、批量选择或页面隐藏时暂停；无加载骨架刷新。
- **步骤语义兼容**：旧任务和未知 step_name 回退为“处理中”，不阻断页面。

## Rollout and Rejection Rules

- 来源→中转证明切片的进度顺序、节流和三视口通过后，才接入入库与来源回收。
- 任一改动导致 SHA-256 减少、目标文件可覆盖、片库文件被删除、百分比倒退、页面闪烁或任务终态错误，拒绝交付。
- 不生成安装包、不提交或推送，除非用户后续明确要求。
