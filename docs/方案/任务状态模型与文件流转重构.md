# 任务状态模型与文件流转重构方案

> 状态：待审核
> 日期：2026-05-30
> 类型：架构重构

---

## 一、问题陈述

当前系统存在三组问题：

### 1.1 状态模型问题

6 个技术状态（PENDING / PROCESSING / SUCCESS / FAILED / SKIPPED / CONFIRMING）直接暴露给用户，语义不清晰：
- CONFIRMING 是"处理中等待用户输入"还是"异常"？
- FAILED 是"临时中断"还是"终局"？

### 1.2 文件流转问题

- **FAILED 时源文件被自动移入回收站**：用户还没决定如何处理，源文件就被移走了
- **临时文件处理不一致**：CONFIRMING+忽略时临时文件移入回收站，FAILED 时临时文件直接删除
- **删除任务直接 rm 文件**：没有安全网，误删不可恢复
- **回收站无过期机制**：文件无限积压

### 1.3 配置设计问题

当前 `source_policy` 混合了两个独立关注点：

| 配置项 | 实际作用 | 问题 |
|--------|---------|------|
| `cleanup_mode` (full_cleanup/smart_cleanup/read_only) | 混合了"任务完成后源文件处理"和"源目录垃圾文件清理" | 两个独立关注点耦合 |
| `delete_source_after_import` (true/false) | 仅在 full_cleanup 下生效 | 与 cleanup_mode 语义重叠 |
| `smart_cleanup` (子对象) | AI+规则清理源目录非媒体文件 | 与任务流无关，却嵌在 source_policy 里 |

## 二、目标终态

### 2.1 四状态业务模型

```
业务状态          技术状态               含义
─────────────────────────────────────────────────────────────
待处理(PENDING)   PENDING               等待流水线拾取
处理中(RUNNING)   PROCESSING            流水线正在执行
                 CONFIRMING            等待用户确认后继续（子状态）
失败(FAILED)      FAILED                流程中断，等用户决策
完成(DONE)        SUCCESS               成功入库
                 SKIPPED               用户忽略/跳过不入库
```

### 2.2 源文件处理：二选一

任务完成后，源文件处理本质只有两种选择：

| 选项 | 行为 | 说明 |
|------|------|------|
| 清理源文件 | 源文件+附属文件移入回收站 | 入库成功后源文件不再需要 |
| 保留源文件 | 源文件保留在源目录不动 | 用户希望保留原始文件 |

**简化配置**：废弃 `cleanup_mode` 和 `delete_source_after_import`，替换为单一布尔值 `cleanup_source_after_done`。

### 2.3 源目录清理器：独立功能

将 `smart_cleanup` 从 `source_policy` 中剥离，作为独立功能模块。目的是通过 AI 和规则，自动清理源目录中不属于任何任务关联的垃圾文件（如 .url、Sample 目录、RARBG 标记文件等）。

### 2.4 回收站过期机制

新增 `recycle_retention_days` 配置项，超期文件自动真正删除。

## 三、详细设计

### 3.1 状态流转

```
                    ┌──────────────────────────────────────────┐
                    │                                          │
                    ▼                                          │
  ┌──────┐    ┌──────┐    ┌──────┐                           │
  │待处理│───→│处理中│───→│ 失败 │───重试──→ 回退到待处理 ─────┘
  └──────┘    └──┬───┘    └──┬───┘
                 │           │
                 │           └──忽略──→ 完成(跳过)
                 │                       源文件按配置处理
                 │
                 ├─验证通过──→入库──→ 完成(成功)
                 │                    源文件按配置处理
                 │
                 └─需确认──→ 等用户操作
                              ├── 确认入库──→ 完成(成功)
                              ├── 重分类──→ 继续(处理中)
                              ├── 重命名源文件──→ 重新刮削(处理中)
                              └── 忽略──→ 完成(跳过)
                                           临时文件rm删除
                                           源文件按配置处理
```

### 3.2 每个状态下的文件位置

| 业务状态 | 临时文件 | 源文件 | 说明 |
|---------|---------|--------|------|
| 待处理 | 无 | 在源目录 | 尚未开始处理 |
| 处理中-执行中 | 存在(副本) | 在源目录 | 流水线正在跑 |
| 处理中-需确认 | 存在(副本) | 在源目录 | 等用户确认/重分类后继续 |
| 失败 | **已删除(rm)** | **在源目录** | 临时文件直接删，源文件等用户决策 |
| 完成-成功 | **已删除(rm)** | 按 cleanup_source_after_done | 入库成功 |
| 完成-跳过 | **已删除(rm)** | 按 cleanup_source_after_done | 用户忽略不入库 |

### 3.3 文件流转路径

```
源目录(source)                     中转目录(temp)                  入库目录(import)
    │                                   │                              │
    │  ┌── 待处理: 源文件在此           │                              │
    │  │                                │                              │
    │  │  复制到中转                     │                              │
    │  └───────────────────────────→    │                              │
    │                                   │                              │
    │                            ┌──────┴──────┐                       │
    │                            │  处理中      │                       │
    │                            │  临时文件存在 │                       │
    │                            └──────┬──────┘                       │
    │                                   │                              │
    │                    ┌──────────────┼──────────────┐               │
    │                    ▼              ▼              ▼               │
    │              ┌──────────┐  ┌──────────┐  ┌──────────────┐       │
    │              │ 验证通过  │  │ 需确认   │  │    失败      │       │
    │              │          │  │(处理中)  │  │              │       │
    │              └────┬─────┘  └────┬─────┘  └──────┬───────┘       │
    │                   │            │               │                │
    │                   │      ┌─────┼─────┐    ┌────┼────┐          │
    │                   │      ▼     ▼     ▼    ▼         ▼          │
    │                   │   确认  重分类  忽略  重试      忽略         │
    │                   │   入库  (继续) (跳过) (→待处理) (→跳过)     │
    │                   │    │      │      │              │           │
    │                   ▼    ▼      ▼      ▼              ▼           │
    │              ┌─────────────────────────────────────────┐        │
    │              │              完成                        │        │
    │              │    临时文件: rm删除(不入回收站)           │        │
    │              │    源文件: 按 cleanup_source_after_done  │        │
    │              └──────────────────────┬──────────────────┘        │
    │                                     │                           │
    │              ┌──────────────────────┼──────────────┐            │
    │              ▼                      ▼              ▼            │
    │     cleanup_source_           cleanup_source_  ──────────→ 入库文件在此
    │     after_done=true           after_done=false             (SUCCESS时)
    │        ┌─────────┐              ┌─────────┐
    │        │移入回收站│              │保留源目录│
    │        └─────────┘              └─────────┘
    │
    └── 入库去重替换(高清场景):
        新任务入库时 quality策略判定新文件更优
        → 原入库文件移入回收站
        → 新文件替换入库

回收站(recycle):
  ├── 完成后移入的源文件 (cleanup_source_after_done=true)
  ├── 被去重替换的旧版本入库文件 (高清替换)
  ├── 删除任务时选择删除的关联文件
  └── 过期自动清理 (recycle_retention_days)
```

### 3.4 删除任务规则

- **前提**：任务不在 PROCESSING 状态均可删除
- **删除时提示**：是否删除任务关联文件？
  - **选择删除文件**：关联文件移入回收站（不直接删除）
    - file_location=source → 源文件移入回收站
    - file_location=temp → 临时文件直接 rm 删除（不入回收站）
    - file_location=import → 入库文件移入回收站
    - file_location=recycle → 回收站文件保留不动
  - **选择保留文件**：仅删除任务记录，文件不动

### 3.5 配置重构设计

#### 3.5.1 废弃配置 → 新配置映射

| 废弃配置 | 新配置 | 迁移逻辑 |
|---------|--------|---------|
| `cleanup_mode: "full_cleanup"` + `delete_source_after_import: true` | `cleanup_source_after_done: true` | 默认值 |
| `cleanup_mode: "full_cleanup"` + `delete_source_after_import: false` | `cleanup_source_after_done: false` | 保留 |
| `cleanup_mode: "read_only"` | `cleanup_source_after_done: false` | 语义等价 |
| `cleanup_mode: "smart_cleanup"` | `cleanup_source_after_done: true` + `source_cleaner.enabled: true` | 拆分为两个独立配置 |
| `source_policy.smart_cleanup` | `source_cleaner` (顶层配置段) | 剥离为独立功能 |

#### 3.5.2 新配置结构

```yaml
source_policy:
  dedup_enabled: true
  recycle_dir: "/vol1/@appdata/nas-media-importer/data/recycle"
  recycle_retention_days: 30         # 新增：回收站保留天数，0=永不过期
  cleanup_source_after_done: true    # 新增：任务完成后是否清理源文件(移入回收站)
                                      #   仅清理创建任务的视频和字幕文件
                                      #   其他附属文件(nfo/jpg等)由源目录清理器处理
  max_auto_retries: 3
  scan_recursive: true
  scan_max_depth: 5

# 新增：源目录清理器（独立功能，与任务流无关）
source_cleaner:
  enabled: false                     # 是否启用源目录自动清理

  # ── 清理模式（二选一）──
  # 模式1: 仅保留影视+字幕，删除其他所有文件
  #   保留: .mkv/.mp4/.avi/.ts/.mov/.wmv + .srt/.ass/.ssa/.sub/.sup
  #   删除: .url/.txt/.nfo/.jpg/.png/.torrent 等所有其他文件
  #
  # 模式2: 保留影视+字幕+相关文件，仅删除垃圾文件
  #   保留: 影视+字幕 + .nfo/.jpg/.png/.info/.torrent 等影视相关文件
  #   删除: .url/Sample目录/RARBG标记等明确垃圾文件
  cleanup_mode: "keep_media_only"    # keep_media_only | keep_media_related

  ai_enabled: false                  # 是否启用 AI 辅助判断
                                      #   勾选后 = 规则 + AI 联合判断
                                      #   AI 可识别规则无法覆盖的垃圾文件

  # ── 高级配置 ──
  junk_video_max_size_mb: 50         # 视频文件小于此大小视为垃圾视频(如Sample)
                                      #   0=不检测，仅按后缀名规则判断
  delete_extensions:                  # 指定后缀名直接删除（前台可配置）
    - ".url"
    - ".txt"
  protect_extensions:                 # 指定后缀名保护不删（前台可配置）
    - ".nfo"                          #   仅在 keep_media_related 模式下生效
    - ".jpg"
    - ".png"
  blacklist_patterns:                 # 文件名/路径黑名单（优先删除）
    - "RARBG*"
    - "*/Sample/*"
    - "*/sample/*"
  cleanup_empty_dirs: true            # 是否清理空目录
  confirm_before_cleanup: true        # 清理前是否需用户确认
  schedule: "0 3 * * *"              # 清理执行时间(cron)，默认每天凌晨3点
```

#### 3.5.3 源目录清理器设计

**定位**：独立于任务流的源目录维护功能。清理源目录中不属于任务关联的垃圾文件（广告、Sample、标记文件等）。

**与任务流的边界**：
- `cleanup_source_after_done`：仅处理创建任务的视频和字幕文件，任务完成后移入回收站
- `source_cleaner`：处理源目录中其他所有文件（nfo/jpg/url/txt/Sample等），与任务无关

**清理模式（核心选项，前端需明确说明）**：

| 模式 | 保留 | 删除 | 适用场景 |
|------|------|------|---------|
| `keep_media_only` | 影视文件+字幕 | 其他所有文件 | 源目录只保留纯净的影视文件 |
| `keep_media_related` | 影视文件+字幕+影视相关文件(nfo/jpg/info/torrent等) | 明确垃圾文件(url/Sample/RARBG等) | 保留影视资料库完整性 |

**规则引擎优先级**：

```
1. 视频文件判定:
   - 后缀名在 video_extensions 中 → 保留
   - 后缀名在 video_extensions 中 但 size < junk_video_max_size_mb → 标记为垃圾视频
   - 其他后缀名 → 按非视频文件规则处理

2. 非视频文件判定:
   - 后缀名在 delete_extensions → 直接删除
   - 后缀名在 protect_extensions → 保留(仅keep_media_related模式)
   - 路径/文件名匹配 blacklist_patterns → 直接删除
   - 其他 → AI判断(如启用) / 按cleanup_mode默认行为

3. AI辅助(如启用):
   - 对规则无法判定的文件，调用LLM判断是否为垃圾文件
   - AI判断结果与规则冲突时，规则优先
```

**工作流程**：
```
定时触发(cron) → 扫描源目录 → 排除已关联任务的文件
  → 视频文件判定(含垃圾视频检测)
  → 非视频文件规则判定(后缀名+黑名单)
  → AI辅助判断(如启用，处理规则未覆盖的文件)
  → 生成清理列表(含详细分类原因)
  → 写入清理记录(API可查)
  → 用户确认(如开启confirm_before_cleanup)
  → 执行清理(移入回收站，不直接删除)
  → 消息通知+日志打印
```

**清理记录API**：

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/source-cleaner/preview` | GET | 预览本次清理列表（不执行，仅展示） |
| `/api/source-cleaner/records` | GET | 查询历史清理记录（路径+分类+原因+时间） |
| `/api/source-cleaner/execute` | POST | 执行清理（需confirm_before_cleanup=true时手动触发） |
| `/api/source-cleaner/status` | GET | 清理器状态（上次执行时间/下次计划时间/统计） |

**消息通知与日志**：
- 清理执行完成后，通过 Hermes Webhook 发送通知（含清理文件数/总大小）
- 清理记录写入日志（info级别，含每个文件的路径和原因）
- 清理预览时输出日志（debug级别）

### 3.6 回收站过期机制

- 每次轮询扫描时检查回收站中超过 `recycle_retention_days` 天的文件
- 读取 .meta 侧车文件确认文件移入时间，超期则真正删除（文件+.meta）
- `recycle_retention_days: 0` 表示永不过期
