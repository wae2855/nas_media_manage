# 通知与监控

> 对应源码路径：`media_importer/notify/`、`media_importer/monitor/`

## 概述

通知与监控模块负责系统运行时的外部通信和文件系统监控，包含四个核心组件：

- **HermesNotifier**：通过 Hermes 平台的 Webhook 机制发送任务状态通知
- **HookRunner**：在流水线关键节点执行用户自定义钩子脚本
- **FileWatcher**：轮询监控源目录，检测新文件并自动触发处理
- **PermissionChecker**：检查路径读写权限，为配置校验提供支持

## Hermes 通知集成

> 源码：`media_importer/notify/hermes_hook.py`

### 类概述

`HermesNotifier` 是与 Hermes 通知平台集成的核心类，通过 HTTP Webhook 将系统事件推送到外部。支持多种事件类型、自动重试和 HMAC 签名验证。

### 初始化

从配置的 `hermes` 区块读取参数：

| 参数 | 配置路径 | 默认值 | 说明 |
|------|----------|--------|------|
| `enabled` | `hermes.enabled` | False | 是否启用通知 |
| `base_url` | `hermes.webhook.base_url` | "" | Hermes 服务地址 |
| `route_name` | `hermes.webhook.route_name` | "media-normalize" | Webhook 路由名称 |
| `secret` | `hermes.webhook.secret` | "" | 签名密钥 |
| `timeout` | `hermes.webhook.timeout` | 30 | 请求超时（秒） |
| `max_retries` | `hermes.webhook.max_retries` | 3 | 最大重试次数 |
| `retry_delay` | `hermes.webhook.retry_delay` | 5 | 重试间隔（秒） |
| `verify_ssl` | `hermes.webhook.verify_ssl` | True | 是否验证 SSL 证书 |
| `enabled_events` | `hermes.webhook.events` | 默认四种事件 | 启用的事件类型列表 |

Webhook URL 拼接规则：`{base_url}/webhooks/{route_name}`

### 事件类型

| 事件类型 | 显示名称 | 触发场景 | 附加信息 |
|----------|----------|----------|----------|
| `task_complete` | - | 单个任务入库成功 | 入库路径、最终文件名 |
| `task_failed` | - | 单个任务处理失败 | 错误信息、重试次数 |
| `task_skipped` | - | 单个任务被跳过 | 跳过原因 |
| `batch_start` | 📥 批量处理开始 | 批量扫描启动 | 源目录、文件数量统计 |
| `batch_complete` | 📦 批量处理完成 | 批量处理结束 | 各状态任务数量汇总 |
| `program_error` | ⚠️ 程序错误 | 程序级异常 | 错误类型、错误信息 |

默认启用的事件：`task_complete`、`task_failed`、`task_skipped`、`batch_complete`

### 通知方法

| 方法 | 说明 |
|------|------|
| `notify(event_type, task, extra_data)` | 通用通知发送，根据事件类型构建载荷 |
| `notify_batch_complete(tasks, summary)` | 批量完成通知，自动统计各状态数量 |
| `notify_batch_start(source_dir, video_count, subtitle_count)` | 批量开始通知 |
| `notify_program_error(error_type, error_message, extra_data)` | 程序错误通知 |
| `should_notify(event_type)` | 判断是否应发送通知（检查启用状态和事件过滤） |

### 发送流程

```
构建载荷 → JSON 序列化 → HMAC-SHA256 签名 → HTTP POST → 成功返回
                                                     ↓ 失败
                                              重试（最多 max_retries 次，间隔 retry_delay 秒）
```

## Webhook 签名机制

### 签名算法

使用 HMAC-SHA256 对请求体进行签名，确保消息完整性和来源验证：

1. 将载荷 JSON 序列化为字节流（`ensure_ascii=False`）
2. 使用配置的 `secret` 作为密钥
3. 计算 `HMAC-SHA256(secret, payload_bytes)` 的十六进制摘要
4. 将签名放入请求头 `X-Webhook-Signature`

### 签名验证流程（接收端）

```
接收请求 → 读取 X-Webhook-Signature 头 → 用相同 secret 计算请求体的 HMAC
        → 比对签名 → 一致 → 处理请求
                   → 不一致 → 拒绝请求
```

### 安全配置

| 配置项 | 说明 |
|--------|------|
| `secret` 为空 | 不生成签名，`X-Webhook-Signature` 头为空字符串 |
| `verify_ssl=True` | 使用系统默认 SSL 证书验证 |
| `verify_ssl=False` | 禁用 SSL 证书验证（适用于自签名证书环境） |

### 异常处理

- HTTP 状态码 ≥ 400 时抛出 `HermesNotifyError`
- 重试耗尽后静默失败，不影响主流程
- SSL 验证失败、网络超时等异常均在重试范围内

## 钩子系统

> 源码：`media_importer/notify/hooks.py`

### 类概述

`HookRunner` 在流水线的关键节点执行用户自定义脚本，支持前置和后置钩子。所有钩子脚本在独立子进程中执行，具有超时保护和路径安全校验。

### 钩子类型

| 钩子名称 | 配置路径 | 触发时机 | 环境变量 |
|----------|----------|----------|----------|
| `before_process` | `hooks.before_process` | 任务处理前 | HOOK_NAME, TASK_ID, VIDEO_FILE, VIDEO_PATH |
| `after_success` | `hooks.after_success` | 任务成功后 | HOOK_NAME, TASK_ID, VIDEO_FILE, IMPORT_PATH, FINAL_FILENAME |
| `after_failure` | `hooks.after_failure` | 任务失败后 | HOOK_NAME, TASK_ID, VIDEO_FILE, ERROR_MESSAGE |

### 安全校验

钩子执行前进行严格的安全校验：

| 校验项 | 规则 | 失败处理 |
|--------|------|----------|
| 路径为空 | 空路径视为未配置，跳过执行 | 正常返回 True |
| 绝对路径 | 必须是绝对路径 | 拒绝执行，返回 False |
| 目录穿越 | 路径中不允许包含 `..` | 拒绝执行，返回 False |
| 允许目录 | 脚本必须在 `hooks.allowed_dir` 目录内 | 拒绝执行，返回 False |
| 文件存在 | 脚本文件必须存在 | 跳过执行，返回 True |
| 执行权限 | 脚本必须有可执行权限 | 跳过执行，返回 True |

### 执行参数

| 参数 | 值 | 说明 |
|------|----|------|
| 执行方式 | `subprocess.run` | 独立子进程 |
| 超时时间 | 60 秒 | 超时后终止 |
| 环境变量 | 系统环境 + 钩子专属变量 | 任务信息通过环境变量传递 |
| 输出捕获 | `capture_output=True` | stdout/stderr 被捕获 |
| 退出码 | 非零退出码记录警告日志 | 不影响主流程 |

### 执行流程

```
读取钩子路径 → 安全校验 → 检查文件存在性 → 检查执行权限
  → 构建环境变量 → subprocess.run 执行 → 处理结果
    ├─ 成功（退出码 0）→ 记录 info 日志
    ├─ 非零退出码 → 记录 warn 日志（含 stderr 前 200 字符）
    ├─ 超时 → 记录 warn 日志
    └─ 异常 → 记录 warn 日志
```

所有钩子执行结果不会阻断主流程，即使钩子失败也返回 True。

## 文件监控

> 源码：`media_importer/monitor/file_watcher.py`

### 类概述

`FileWatcher` 通过轮询方式监控源目录中的文件变化，检测到新文件后自动触发流水线处理。基于后台线程运行，支持启停控制和状态查询。

### 工作原理

采用快照对比法检测文件变化：

1. 启动时扫描源目录，建立已知文件集合（`_known_files`）
2. 每隔 `poll_interval` 秒重新扫描
3. 对比当前文件集合与已知集合，差集即为新文件
4. 检测到新文件后调用回调函数 `on_new_files`
5. 更新已知文件集合

### 初始化参数

| 参数 | 配置路径 | 默认值 | 说明 |
|------|----------|--------|------|
| `enabled` | `file_watcher.enabled` | False | 是否启用监控 |
| `poll_interval` | `file_watcher.poll_interval` | 10 | 轮询间隔（秒） |
| `ignore_patterns` | `file_watcher.ignore_patterns` | [] | 忽略的文件模式 |
| `source_dir` | `source_dir` | "" | 监控的源目录 |

### 线程模型

```
主线程 → start() → 创建守护线程 → _watch_loop()
                                      ↓
                                  等待 poll_interval
                                      ↓
                                  _check_changes()
                                      ↓
                                  发现新文件 → on_new_files 回调
                                      ↓
                                  继续循环...
                                  
主线程 → stop() → 设置 _stop_event → 线程退出
```

- 使用 `threading.Event` 实现可中断的等待（`_stop_event.wait(poll_interval)`）
- 守护线程（`daemon=True`），主进程退出时自动终止
- `stop()` 最多等待 5 秒让线程优雅退出

### 文件扫描

通过 `scan_source_dir` 函数扫描源目录，返回视频+字幕分组：

- 每个分组包含一个视频路径和关联的字幕路径列表
- 将所有视频和字幕路径加入已知文件集合
- 扫描失败时记录警告日志，不中断监控循环

### 回调机制

`on_new_files` 回调在 `start_server` 中定义，执行以下逻辑：

1. 检查流水线是否暂停，未暂停则调用 `pipeline.run_all()`
2. 检查配置脏标记，若有待同步的配置变更且无运行中任务，则自动重载配置
3. 异常通过 `notify_error` 发送程序错误通知

### 状态属性

`status` 属性返回监控器状态字典：

| 字段 | 类型 | 说明 |
|------|------|------|
| `enabled` | bool | 是否启用 |
| `running` | bool | 线程是否在运行 |
| `source_dir` | str | 监控目录 |
| `poll_interval` | int | 轮询间隔 |
| `known_files` | int | 已知文件数量 |
| `scan_count` | int | 累计扫描次数 |

### API 控制

通过 `/api/watcher/control` 端点控制监控器：

| action | 效果 |
|--------|------|
| `pause` | 调用 `watcher.stop()` 停止轮询 |
| `resume` | 调用 `watcher.start()` 恢复轮询 |
| `status` | 返回当前监控状态 |

### 配置热更新

当配置中 `file_watcher` 区块变更时，`_reload_watcher` 方法执行：

1. 停止当前监控器（如果存在）
2. 读取新配置
3. 如果 `enabled=True`，创建新的 `FileWatcher` 实例并启动
4. 如果 `enabled=False`，仅停止，不创建新实例

## 权限检查

> 源码：`media_importer/monitor/permission_checker.py`

### 功能概述

权限检查模块为系统提供路径读写权限验证能力，支持清理器启用时的动态权限升级，用于配置保存前的校验和运行时健康检查。特别针对飞牛 NAS (fnOS) 的应用目录权限模型进行了适配。

### 核心函数

#### `check_path_permission(path, need_write=True)`

检查指定路径的读写权限，返回详细的结果字典：

| 返回字段 | 类型 | 说明 |
|----------|------|------|
| `path` | str | 检查的路径 |
| `ok` | bool | 权限是否正常 |
| `level` | str | 级别：ok / error |
| `message` | str | 检查结果描述 |
| `hint` | str | 修复建议 |
| `exists` | bool | 路径是否存在 |
| `readable` | bool | 是否可读 |
| `writable` | bool | 是否可写 |

#### 检查逻辑

```
路径为空 → 返回错误
路径非绝对路径 → 返回错误
路径存在
  ├─ 非目录 → 返回错误
  ├─ 不可读 → 返回错误 + 授权提示
  ├─ 需要写入但不可写 → 返回错误 + 授权提示
  └─ 需要写入 → 创建临时文件测试实际写入能力
      ├─ 成功 → 权限正常
      └─ 失败 → 返回错误 + 授权提示
路径不存在
  ├─ 查找最近的已存在父目录
  ├─ 父目录不存在 → 返回错误
  ├─ 父目录不可写 → 返回错误 + 授权提示
  └─ 父目录可写 → 尝试自动创建目录
      ├─ 成功 → 权限正常
      └─ 失败 → 返回错误 + 授权提示
```

#### `check_config_permissions(config)`

批量检查配置中所有路径的权限，返回问题列表：

| 检查项 | 路径来源 | 写入要求 | 跳过条件 |
|--------|----------|----------|----------|
| 源目录 | `source_dir` | 只读 | 路径在应用管理目录下 |
| 中转目录 | `temp_dir` | 读写 | 路径在应用管理目录下 |
| 日志目录 | `log_dir` | 读写 | 路径在应用管理目录下 |
| 入库规则根目录 | `path_rules[*].template` | 读写 | 根目录在应用管理目录下 |
| 回收站目录 | `source_policy.recycle_dir` | 读写 | 路径在应用管理目录下 |
| 清理器启用时的源目录 | `source_dir`（当 `source_cleaner.enabled=true`） | 读写 | 清理器启用时源目录需写权限才能移入回收站 |

返回结构：

```json
{
  "all_ok": true,
  "user": "当前系统用户",
  "issues": [
    {
      "field": "source_dir",
      "path": "/vol1/video",
      "level": "error",
      "message": "应用用户 xxx 无权读取此目录",
      "hint": "请在 fnOS 应用中心 → nas-media-importer → 设置 → 授权目录 → 添加目录\n路径: /vol1/video\n权限: 勾选 【读】\n保存授权后，回到此页面重新点击保存或测试"
    }
  ]
}
```

### 应用管理目录

fnOS 中以下目录由系统管理，应用默认具有访问权限，检查时自动跳过：

| 目录前缀 | 说明 |
|----------|------|
| `/vol*/@appdata/` | 应用数据目录 |
| `/vol*/@appcenter/` | 应用中心目录 |
| `/vol*/@appconf/` | 应用配置目录 |
| `/vol*/@apptemp/` | 应用临时目录 |
| `/vol*/@appshare/` | 应用共享目录 |

### 授权提示生成

`_build_auth_hint` 函数生成面向用户的操作指引，引导用户在 fnOS 应用中心中添加目录授权：

- 只读需求：提示勾选【读】权限
- 读写需求：提示勾选【读】+【写】权限

### 辅助函数

#### `extract_root_from_template(template)`

从入库规则模板中提取根目录路径。例如：

| 模板 | 提取根目录 |
|------|-----------|
| `/vol1/video/{type}/{genre}/{title}` | `/vol1/video` |
| `/vol1/media/movie/{title}` | `/vol1/media` |
| `/vol1/video` | `/vol1/video` |

#### `get_current_user()`

获取当前运行用户名称，依次尝试 `getpass.getuser` 和 `pwd.getpwuid`。

## 职责边界

### 负责

- Hermes Webhook 通知发送（含 HMAC 签名）
- 钩子脚本执行（before/after_success/after_failure）
- 源目录文件监控（轮询快照对比）
- 路径权限检查（fnOS 适配）

### 不负责

- 通知内容生成（由 pipeline 构建载荷）
- 钩子脚本内容（用户自定义）
- 文件处理触发决策（由 pipeline 控制）
- 配置变更检测（由 api 层控制）
