# 刮削引擎 — 技术文档

> 对应源码：
> - `media_importer/scraper/metadata_scraper.py` — 元数据刮削主入口
> - `media_importer/scraper/llm_scraper.py` — AI 刮削与提示词
> - `media_importer/scraper/confidence_engine.py` — 文件名清洗、标题匹配、置信度计算
> - `media_importer/scraper/dimension_manager.py` — 维度映射
> - `media_importer/scraper/providers/base.py` — Provider 抽象基类
> - `media_importer/scraper/providers/tmdb_provider.py` — TMDb Provider
> - `media_importer/scraper/providers/__init__.py` — Provider 注册与工厂
> - `media_importer/scraper/tmdb_client.py` — TMDb API 客户端

---

## 1. 概述

刮削引擎负责从视频文件名中提取影视元数据（标题、年份、类型、维度等），是流水线 `scrape` 步骤的核心。

设计采用 **Provider + AI 双引擎**架构：

```
文件名 ──→ 清洗 ──→ Provider 搜索 ──→ 匹配判定 ──→ 详情获取 ──→ AI 整理 ──→ 置信度计算 ──→ 结果
              │           │              │             │            │            │
              │           └── 无结果/低匹配 ──→ AI 清洗 ──→ 重搜 ──┘            │
              │                                                        │
              └── 全部失败 ──→ 纯 AI 刮削 ──────────────────────────────┘
```

核心类关系：

| 类 | 文件 | 职责 |
|---|---|---|
| `MetadataScraper` | metadata_scraper.py | 刮削主入口，编排整个流程 |
| `MetadataProvider` | providers/base.py | 元数据源抽象基类 |
| `TMDbProvider` | providers/tmdb_provider.py | TMDb 实现 |
| `TMDbClient` | tmdb_client.py | TMDb API 底层通信 |
| `LLMScraper` | llm_scraper.py | AI 刮削、提示词构建、API 调用 |
| `FilenameCleaner` | confidence_engine.py | 文件名正则/AI 清洗 |
| `TitleMatcher` | confidence_engine.py | 标题匹配分 T 计算 |
| `ConfidenceEngine` | confidence_engine.py | 置信度综合计算 |

## 2. Provider 抽象层

### 2.1 类图

```
MetadataProvider (ABC)          providers/__init__.py
├── provider_type: str          _PROVIDER_REGISTRY: Dict[str, Type]
├── display_name: str           ├── register_provider(cls)    ← 装饰器
├── search() → SearchResult     ├── create_providers(config)  ← 工厂
├── get_details() → MediaDetails├── get_provider_class(type)
├── get_genres() → list         └── get_all_registered_providers()
├── test_connection() → bool
├── map_dimensions() → List[DimensionMapping]
├── get_config_schema() → dict
├── get_context_template() → str
└── get_prompt_file_name() → str
    │
    └── TMDbProvider (@register_provider)
        ├── provider_type = "tmdb"
        ├── display_name = "TMDb"
        └── 内部持有 TMDbClient
```

### 2.2 核心数据类

| 数据类 | 字段 | 用途 |
|--------|------|------|
| `SearchItem` | provider_type, item_id, title, original_title, year, media_type, poster_url, vote_average, raw_data | 搜索结果条目 |
| `SearchResult` | items: List[SearchItem], total_results: int | 搜索结果集 |
| `MediaDetails` | provider_type, item_id, media_type, title, original_title, year, genres, overview, vote_average, origin_country, original_language, adult, tagline, poster_url, raw_data, rating_info | 详情数据 |
| `Genre` | id, name | 类型标签 |
| `DimensionMapping` | name, value, confidence, source | 维度映射结果 |

### 2.3 注册机制

使用装饰器 + 全局注册表实现 Provider 插件化：

```
@register_provider          →  _PROVIDER_REGISTRY["tmdb"] = TMDbProvider
class TMDbProvider: ...

create_providers(config)    →  遍历 config.metadata.providers
                               跳过 enabled=false
                               通过 _PROVIDER_REGISTRY[type] 实例化
```

配置结构（config.yaml）：

```yaml
metadata:
  providers:
    - type: tmdb
      enabled: true
      api_key: "xxx"
      language: "zh-CN"
      fallback_language: "en-US"
```

### 2.4 TMDbProvider 关键实现

**搜索策略**：同时搜索 movie 和 tv，合并结果：

```
search(query, year, media_type)
  │
  ├─ media_type == "tv" or None ──→ search_tv_list(query, year)
  ├─ media_type == "movie" or None ──→ search_movie_list(query, year)
  │
  └─ 合并 results，累加 total_results
```

**维度映射**：调用 `dimension_manager.map_provider_to_dimension()`，并额外获取 `release_dates` 用于分级映射：

```
map_dimensions(dim_configs, details)
  │
  ├─ _get_release_dates(item_id, media_type)
  │   ├─ movie → get_movie_release_dates
  │   └─ tv    → get_tv_content_ratings
  │
  └─ for each dim_config:
      └─ map_provider_to_dimension(dim_config, raw_data, release_dates, "tmdb")
```

### 2.5 TMDbClient

| 方法 | API 端点 | 说明 |
|------|----------|------|
| `search_movie_list` | `/search/movie` | 电影搜索，支持 `primary_release_year` |
| `search_tv_list` | `/search/tv` | 电视剧搜索，支持 `first_air_date_year` |
| `search_movie` | `/search/movie` → `/movie/{id}` | 搜索+取详情（旧接口） |
| `search_tv` | `/search/tv` → `/tv/{id}` | 搜索+取详情（旧接口） |
| `get_movie_details` | `/movie/{id}` | 电影详情 |
| `get_tv_details` | `/tv/{id}` | 电视剧详情 |
| `get_tv_season` | `/tv/{id}/season/{num}` | 季详情 |
| `get_movie_release_dates` | `/movie/{id}/release_dates` | 电影分级 |
| `get_tv_release_dates` | `/tv/{id}/content_ratings` | 电视剧分级 |
| `test_connection` | `/authentication` | 连通性测试 |
| `get_genre_list` | `/genre/movie/list` + `/genre/tv/list` | 类型列表 |

请求特性：内置重试（max_retries）、SSL 验证关闭（fnOS 环境）、语言回退（language → fallback_language）。

## 3. 文件名清洗

> 源码位于 `confidence_engine.py` 中的 `FilenameCleaner` 类，非独立文件。

### 3.1 清洗流程

```
原始文件名
  │
  ▼
① 移除扩展名 (.mkv/.mp4/...)
② 移除制作组标签 [EPSiLON]
③ 提取尾部发布组 -FGT（防误判：排除编解码器前缀、广告后缀）
④ 移除多集标记 S01E01E02
⑤ 移除季集标记 S01E01（同时提取 season/episode）
⑥ 提取独立季号 S05
⑦ 提取括号年份 (1994)（优先于点号年份）
⑧ 提取点号年份 .1999.
⑨ 移除分辨率 1080p/4K/UHD/...
⑩ 移除源/编解码器 BluRay/x264/DTS-HD.MA.5.1/...
⑪ 移除版本标签 25th.Anniversary.Edition/...
⑫ 移除完整广告 www.xxx.com-加群123456
⑬ 移除广告标记 .com/.net/.org
⑭ 移除方括号内容 [...]
⑮ 移除尾部发布组大写缩写 EVOLVE
⑯ 整理空格 [.\s_-]+ → 空格
  │
  ▼
⑰ 中英分离：检测 "中文标题 英文标题" 模式
    cjk_title = 中文部分, clean_title = 英文部分
  │
  ▼
⑱ 年份可疑检测：year > 当前年+1 或标题中残留年份 → year_suspect=True
  │
  ▼
CleanResult(clean_title, year, season, episode, cjk_title, year_suspect, removed_items)
```

### 3.2 发布组提取的防误判

步骤 ③ 在步骤 ⑩ 之前执行，原因：编解码器正则的前缀 `[.\s_-]` 会吃掉 `-` 分隔符。

防误判规则：

| 规则 | 正则 | 防护场景 |
|------|------|----------|
| 编解码器前缀排除 | `_CODEC_PREFIX_RE` | `-DTS`, `-Atmos` 不被误判为发布组 |
| 广告后缀排除 | `_AD_FULL_PATTERN` | `www.xxx.com-加群123456` 中 `-加群123456` 不被误判 |

### 3.3 AI 清洗

当正则清洗结果可疑（`year_suspect=True`）或 Provider 搜索匹配不足时，触发 AI 清洗：

```
FilenameCleaner.ai_clean(filename, llm_scraper)
  │
  ├─ 构造提示词：从文件名提取标题和年份
  ├─ 调用 llm_scraper.extract_title()（使用 fast_model）
  ├─ 解析 JSON 响应：{"title": "...", "year": ...}
  │
  └─ 返回 CleanResult(method="ai")
      失败时回退到 regex 清洗
```

### 3.4 中英分离

当文件名包含中英双语标题时（如 `肖申克的救赎 The Shawshank Redemption`），分离出 `cjk_title` 和 `clean_title`，分别用于 Provider 搜索以提高命中率。

## 4. 标题匹配

> 源码位于 `confidence_engine.py` 中的 `TitleMatcher` 类，非独立文件。

### 4.1 匹配级别

| 级别 | 条件 | T 值 | 默认值 |
|------|------|------|--------|
| L1 | 精确匹配 + 年份一致 | 固定 | 1.0 |
| L2 | 精确匹配 + 有季号 | 固定 | 0.9 |
| L3 | 精确匹配 + 无年份/季号 | 固定 | 0.7 |
| L4 | 精确匹配 + 年份不匹配 | 固定 | 0.4 |
| L5 | 模糊匹配 + 年份一致 | best_sim | — |
| L6 | 模糊匹配 + 无年份/年份不匹配 | best_sim × 0.7 | — |
| L7 | 相似度 < 0.3 | 0.0 | — |

### 4.2 匹配流程

```
normalize(clean_title) vs normalize(provider_title/original_title)
  │
  ├─ 精确匹配 (normalized 相等)?
  │   ├─ 有年份 + 一致 → L1 (1.0)
  │   ├─ 有年份 + 不一致 → L4 (0.4)
  │   ├─ 有季号 → L2 (0.9)
  │   └─ 无年份无季号 → L3 (0.7)
  │
  └─ 模糊匹配 (SequenceMatcher)
      ├─ sim < 0.3 → L7 (0.0)
      ├─ 年份一致 → L5 (T=sim)
      └─ 无年份/不一致 → L6 (T=sim×0.7)
```

规范化：`lower().replace(' ','').replace('.','').replace('-','').replace('_','')`

相似度：`difflib.SequenceMatcher`，取与 `title` 和 `original_title` 中较高值。

### 4.3 两个匹配接口

| 方法 | 输入 | 使用场景 |
|------|------|----------|
| `match()` | `clean_title`, `tmdb_result: dict` | 旧接口，兼容 dict 格式 |
| `match_standard()` | `clean_title`, `search_item: SearchItem` | 新接口，Provider 抽象层使用 |

逻辑完全一致，仅输入类型不同。

## 5. 元数据刮削流程

### 5.1 主流程

`MetadataScraper.scrape(video_filename, subtitle_filenames, conn)` 是刮削入口：

```
视频文件名
  │
  ▼
① FilenameCleaner.clean() → CleanResult
  │  clean_title, year, season, episode, cjk_title, year_suspect
  │
  ▼
② year_suspect? ──Yes──→ AI 清洗 → Provider 搜索(ai_clean_result)
  │                         │
  │                         └──→ 跳到 ④
  │
  No
  ▼
③ cjk_title 存在?
  │
  ├─ Yes → 先用 cjk_title 搜索 Provider
  │        │
  │        ├─ 有结果但 T < threshold → 再用 clean_title 搜索，取 T 更高者
  │        └─ 无结果 → 用 clean_title 搜索
  │
  └─ No → 用 clean_title 搜索 Provider
  │
  ▼
④ Provider 搜索结果判定
  │
  ├─ T ≥ provider_match_threshold (0.85) ──→ ⑤
  │
  ├─ 0 < T < 0.85 ──→ AI 清洗 → 用 AI 标题重搜
  │                    │
  │                    ├─ 新 T > 旧 T → 用新结果 → ⑤
  │                    └─ 新 T ≤ 旧 T → ⑥ 纯 AI
  │
  └─ 无结果 ──→ AI 清洗 → 用 AI 标题重搜
                │
                ├─ 有结果且 T ≥ ai_research_threshold (0.5) → ⑤
                └─ 无结果或 T < 0.5 → ⑥ 纯 AI
  │
  ▼
⑤ Provider+AI 模式
  │
  ├─ provider.get_details(item_id, media_type) → MediaDetails
  │   失败 → 回退到 ⑥ 纯 AI
  │
  ├─ _map_provider_dimensions() → provider_dimensions
  ├─ _extract_context() → provider_context（结构化参考文本）
  ├─ llm_scraper.scrape_with_context() → AI 整理结果
  │   失败 → llm_scraper.scrape() 兜底
  │
  └─ confidence_engine.calculate() → ConfidenceResult
     │
     └─ 返回 result（含 confidence, scrape_trace, confidence_gate_blocked 等）
  │
  ▼
⑥ 纯 AI 模式
  │
  ├─ llm_scraper.scrape() → AI 刮削结果
  └─ confidence_engine.calculate_ai_only() → ConfidenceResult
     │
     └─ 返回 result
```

### 5.2 Provider 搜索策略

`_search_with_match()` 对单个 Provider 的搜索策略：

```
_search_with_match(provider, clean_title, year, season)
  │
  ├─ 1. 用 clean_title + year + media_type_hint 搜索
  │     media_type_hint = "tv" if season else None
  │
  │  T ≥ threshold? ──Yes──→ 返回
  │
  ├─ 2. 去掉 year 重搜（年份可能误提取）
  │
  │  T ≥ threshold? ──Yes──→ 返回
  │
  ├─ 3. 回退语言重搜（如 zh-CN → en-US）
  │     临时切换 provider._client.language
  │
  │  T ≥ threshold? ──Yes──→ 返回
  │
  └─ 全部失败 → 返回 (None, status)
     status 包含: provider_type, status(error/no_results/below_threshold), best_T
```

`_search_all_providers()` 遍历所有已启用 Provider，取 T 值最高的结果。

### 5.3 Provider 上下文提取

`_extract_context()` 将 Provider 详情转为结构化参考文本，注入 AI 提示词：

```
【TMDb 元数据参考】
中文标题: 银翼杀手2049
原始标题: Blade Runner 2049
年份: 2017
类型: movie
类型标签(genres): 科幻, 剧情, 冒险
简介: ...（截取前300字）
评分: 7.5
制片国家: 美国, 英国
标语: ...
总季数: ...（仅 tv）

请基于以上 TMDb 权威数据，整理为系统所需格式。
```

### 5.4 剧集系列刮削

`scrape_series(series_name)` 用于整季刮削，跳过文件名清洗，直接用剧名搜索 Provider：

```
scrape_series(series_name)
  │
  ├─ 遍历 providers:
  │   ├─ search(series_name, media_type="tv")
  │   ├─ get_details(item_id, "tv")
  │   ├─ _extract_context()
  │   └─ llm_scraper.scrape_series_with_context()
  │       失败 → llm_scraper.scrape_series()
  │
  └─ 所有 Provider 失败 → llm_scraper.scrape_series()
```

## 6. 维度映射

### 6.1 维度来源类型

| source_type | 说明 | 数据来源 |
|-------------|------|----------|
| `ai` | 纯 AI 判断 | LLM 返回的 dimensions 字段 |
| `ai+provider` | AI + Provider 映射 | Provider 结构化字段映射 + AI 补充 |
| `ai+tmdb` | AI + TMDb 映射（旧，兼容） | 同 ai+provider，provider_type=tmdb |
| `file` | 文件分析 | 视频文件元数据（分辨率等） |

### 6.2 维度查询函数

| 函数 | 筛选条件 | 返回 |
|------|----------|------|
| `get_dimensions_for_scrape(conn)` | source_type=ai 或 (ai+provider 且有 ai_prompt) | AI 刮削用维度列表 |
| `get_dimensions_for_provider(conn, provider_type)` | source_type=ai+provider 且 provider_mappings 包含该 provider_type | Provider 映射用维度列表 |
| `get_dimensions_for_tmdb(conn)` | 兼容别名，= get_dimensions_for_provider(conn, "tmdb") | — |
| `get_dimensions_for_file(conn)` | source_type=file | 文件分析用维度列表 |

### 6.3 Provider 维度映射

`map_provider_to_dimension()` 根据 `provider_mappings` 中的 `match_type` 分派：

| match_type | 映射逻辑 | 适用维度 |
|------------|----------|----------|
| `genre_ids` | 按 TMDB genre ID 匹配 | documentary, animation → `_map_bool_genre`；其他 → `_map_genre_by_rules` |
| `country_codes` | 按国家代码匹配 | region → `_map_region_v2` |
| `direct_match` | 直接匹配语言代码 | origin_lang → `_map_origin_lang_v2` |
| `certification` | 按分级证书匹配 | restricted_level → `_map_restricted_level` |
| `genre_names` | 按类型名称匹配（预留） | — |

### 6.4 映射规则示例

**布尔型 genre 映射**（如 animation）：

```
provider_mappings.tmdb:
  match_type: genre_ids
  match_rules:
    true:
      ids: [16]         ← Animation genre ID
```

genre_ids ∩ {16} 非空 → value="true", confidence=1.0
genre_ids 存在但不含 16 → value="false", confidence=0.9

**分级映射**（restricted_level）：

```
国家优先级: US > GB > DE > FR > CN > JP > KR > AU > CA
只取 US/GB 的分级证书

CERTIFICATION_TO_LEVEL:
  G/U → "0-6"
  PG/TV-Y7/TV-G/TV-PG → "7-12"
  12A/12/PG-13/TV-14 → "13-16"
  R/NC-17/15/18/TV-MA → "17+"
```

US 分级 confidence=1.0，GB 分级 confidence=0.95。

### 6.5 维度映射在刮削流程中的位置

```
Provider+AI 模式:
  │
  ├─ _map_provider_dimensions(provider, details, conn)
  │   ├─ get_dimensions_for_provider(conn, provider_type) → dim_configs
  │   └─ provider.map_dimensions(dim_configs, details) → List[DimensionMapping]
  │       └─ 内部调用 map_provider_to_dimension()
  │
  ├─ provider_dimensions = {name: {value, confidence, source}}
  │   media_type 由 Provider 直接提供 (confidence=1.0)
  │
  ├─ llm_scraper.scrape_with_context(..., provider_dimensions=provider_dimensions)
  │   └─ AI 返回的 dimensions 中，provider 已映射的维度被覆盖
  │
  └─ 最终 result.dimensions = AI维度 ∪ Provider维度（Provider 优先）
```

## 7. AI 刮削与提示词

### 7.1 LLMScraper 核心方法

| 方法 | 场景 | system_prompt | model |
|------|------|---------------|-------|
| `scrape()` | 纯 AI 刮削 | 默认/自定义提示词 | model → fallback_model |
| `scrape_with_context()` | Provider+AI | Provider 专属提示词 | fast_model |
| `scrape_series()` | 纯 AI 剧集 | 剧集提示词 | model → fallback_model |
| `scrape_series_with_context()` | Provider+AI 剧集 | Provider 剧集提示词 | fast_model |
| `extract_title()` | AI 清洗文件名 | 简短提取提示词 | fast_model |

### 7.2 提示词加载优先级

```
scraper_prompts.md（用户自定义）
  ↓ 不存在
scraper_prompts.example.md（模板）
  ↓ 不存在
代码内置 DEFAULT_SYSTEM_PROMPT
```

Provider 专属提示词：

```
{provider_type}_prompts.md（如 tmdb_prompts.md）
  ↓ 不存在
Provider.get_context_template()（类方法）
  ↓ 不存在
MetadataProvider.get_context_template()（基类默认）
```

搜索路径：`config/` 目录 → `../config/` → `/vol3/@appdata/nas-media-importer/config/`

### 7.3 提示词结构

```
┌─────────────────────────────────────┐
│ 上半部：角色定义 + 数据源优先级 +     │
│         正确/错误示例 + 翻译规则      │
│         （来自 custom_system_prompt   │
│          或 DEFAULT_SYSTEM_PROMPT）  │
├─────────────────────────────────────┤
│ 【维度判断】                         │
│ 当前需要判断的维度：                  │
│ 1. 影视类型(media_type): [movie|tv]  │
│    — ai_prompt 描述                  │
│ 2. 是否纪录片(documentary): [...]    │
│    — ai_prompt 描述                  │
│ ...                                 │
├─────────────────────────────────────┤
│ 请严格按以下JSON格式返回：            │
│ {                                   │
│   "title_cn": "string|null",        │
│   "title_en": "string|null",        │
│   "year": "int|null",               │
│   "type": "movie|tv",               │
│   "dimensions": {                   │
│     "media_type": "movie|tv|null",  │
│     "documentary": "true|false|null"│
│   },                                │
│   "confidence": "float"             │
│ }                                   │
└─────────────────────────────────────┘
```

### 7.4 Provider+AI 模式的提示词差异

| 项目 | 纯 AI | Provider+AI |
|------|-------|-------------|
| 上半部 | 默认/自定义提示词 | Provider 专属提示词（如 TMDb 提示词） |
| 维度排除 | 无 | 排除 Provider 已映射的维度（exclude_dims） |
| user_content | 文件名 + 字幕名 | 文件名 + 字幕名 + provider_context |
| model | model → fallback_model | fast_model |
| 维度合并 | 无 | AI 维度 ∪ Provider 维度（Provider 覆盖） |

### 7.5 API 调用与重试

```
_retry_with_fallback(system_prompt, user_content, use_fast)
  │
  ├─ use_fast=True:
  │   models = [fast_model]
  │   call_fn = _call_fast_api
  │
  └─ use_fast=False:
      models = [model, fallback_model]（去重）
      call_fn = _call_api
  │
  ▼
  for model in models:
      for attempt in range(max_retries):
          ├─ 成功 → _parse_response() → 返回
          └─ 失败 → sleep(retry_delay) → 重试
  │
  ▼
  全部失败 → 抛出 LLMScrapeError
```

### 7.6 响应解析

`_parse_response()` 处理 LLM 返回的各种格式：

```
原始响应
  │
  ├─ 移除 <think...</think > 标签（DeepSeek 等推理模型）
  ├─ 移除 ```json ``` 代码块标记
  ├─ 提取第一个 {...} JSON 对象
  ├─ json.loads()
  ├─ 补全缺失字段（title_cn/title_en/year/type/confidence）
  ├─ 过滤 dimensions：只保留已知维度名
  ├─ confidence 类型检查（非数字 → 0.5）
  └─ 计算 low_confidence = confidence < confidence_threshold
```

### 7.7 维度从数据库动态加载

`load_dimensions_from_db(conn)` 在每次刮削前调用，从数据库读取已启用维度的 `name`、`label`、`values`、`ai_prompt`，替换内置维度列表。这使提示词中的维度部分始终与数据库配置同步。

## 8. 职责边界

### 负责

- 文件名清洗（正则 16 步 + AI Fallback）
- Provider 搜索与匹配（多 Provider 遍历，取最高 T 值）
- Provider 详情获取与维度映射
- AI 刮削（纯 AI / Provider+AI 双模式）
- 置信度计算（search_conf × data_gate）
- 维度映射（provider_mappings → 维度值）
- Provider 注册表管理

### 不负责

- 文件 I/O 操作（由 storage 模块执行）
- 任务状态管理（由 TaskManager 执行）
- 流水线编排（由 pipeline 模块执行）
- 配置管理（由 config_loader 执行）
- LLM API 底层通信（由 LLMScraper 内部处理，但 API Key/URL 由配置提供）

### 8.3 置信度与任务状态的映射

> 置信度计算的完整细节见 [confidence-engine.md](confidence-engine.md)

| 置信度判定 | 任务状态 | 说明 |
|-----------|----------|------|
| PASS (≥0.8) | SUCCESS | 自动入库 |
| CONFIRMING (0.5~0.8) | CONFIRMING | 需人工确认 |
| NEEDS_REVIEW (0.3~0.5 或 gate_blocked) | NEEDS_REVIEW | 需审核 |
| FAILED (<0.3) | FAILED | 失败 |
