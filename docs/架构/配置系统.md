# 配置系统模块技术文档

> 对应源码路径：
> - `media_importer/core/config_loader.py` — 配置加载、迁移、脱敏、布尔归一化
> - `media_importer/core/config_validator.py` — 配置完整性校验、连通性测试
> - `config.yaml.example` — 配置模板（首次安装自动复制）
> - `config/config.yaml` — 本地开发配置文件
> - `config/scraper_prompts.md` — 用户自定义刮削提示词

---

## 1. 概述

配置系统负责管理 影音库AI智能整理的全部运行参数，涵盖目录路径、LLM 连接、入库规则、通知集成等。系统采用 YAML 格式存储配置，支持自动迁移旧版配置键、运行时校验、敏感信息脱敏和布尔字符串归一化。

配置加载流程：

```
config.yaml (磁盘)
      │
      ▼
  yaml.safe_load()
      │
      ▼
  路径解析（相对→绝对）
      │
      ▼
  配置迁移（旧键→新键）
      │
      ▼
  默认值填充
      │
      ▼
  布尔字符串归一化
      │
      ▼
  validate_config() 基础校验
      │
      ▼
  运行时 config dict
```

## 2. 配置文件结构

### 2.1 config.yaml 段落总览

| 段落 | 顶级键 | 必需 | 说明 |
|------|--------|------|------|
| 1. 轮询监控 | `file_watcher` | 否 | 源目录文件监控配置 |
| 2. API 服务 | `server` | 否 | HTTP API 监听地址与认证 |
| 目录配置 | `source_dir` / `temp_dir` / `log_dir` | 是 | 核心目录路径 |
| 源文件策略 | `source_policy` | 是 | 去重、回收、源文件清理、扫描深度 |
| 源目录清理器 | `source_cleaner` | 否 | 独立功能，自动清理源目录垃圾文件 |
| 视频格式 | `video_extensions` | 否 | 支持的视频后缀列表 |
| 字幕格式 | `subtitle_extensions` | 否 | 支持的字幕后缀列表 |
| 3. 入库规则 | `path_rules` | 否 | 维度条件→路径模板映射 |
| 兜底目录 | `fallback_dir` | 否 | 无规则匹配时的入库目录 |
| 特殊规则 | `rules` | 否 | 电视剧/电影特殊处理动作 |
| 4. 文件名模板 | `filename_templates` | 否 | movie/tv/subtitle 文件名模板 |
| 5. 同名处理 | `duplicate_handling` | 否 | 入库同名文件策略 |
| 6.5 人工检查 | `manual_review` | 否 | 入库前人工确认开关 |
| 6.8 元数据 | `metadata` | 否 | TMDB 等元数据源配置 |
| 7. LLM | `llm` | 是 | AI 刮削模型配置 |
| 8. 通知 | `hermes` | 否 | Hermes Webhook 通知 |
| 9. 任务队列 | `task_queue` | 否 | 并发控制 |
| 10. 钩子 | `hooks` | 否 | 处理前后脚本 |
| 11. 日志 | `logging` | 否 | 日志级别与格式 |
| 置信度 | `confidence` | 否 | 刮削置信度参数（内部填充默认值） |

### 2.2 file_watcher — 轮询监控

| 键 | 类型 | 默认值 | 说明 |
|----|------|--------|------|
| `enabled` | bool | true | 是否启用文件监控 |
| `poll_interval` | int | 60 | 轮询间隔（秒），建议不低于 30 |
| `ignore_patterns` | list | ["*.tmp", ".DS_Store", "*partial*"] | 忽略的文件名模式 |

### 2.3 server — API 服务

| 键 | 类型 | 默认值 | 说明 |
|----|------|--------|------|
| `host` | string | "0.0.0.0" | 监听地址 |
| `port` | int | 9855 | 监听端口 |
| `api_key` | string | "" | API 认证密钥，空则不启用认证 |

### 2.4 核心目录

| 键 | 必需 | 说明 |
|----|------|------|
| `source_dir` | 是 | 影视文件来源目录 |
| `temp_dir` | 是 | 处理过程中的中转目录 |
| `log_dir` | 是 | 日志目录 |

> 三个目录不能互相相同，否则校验报错。

### 2.5 source_policy — 源文件策略

| 键 | 类型 | 默认值 | 说明 |
|----|------|--------|------|
| `recycle_dir` | string | - | 回收站路径（不能与 source_dir/temp_dir 相同，旧配置 quarantine_dir 自动迁移） |
| `cleanup_source_after_done` | bool | true | 任务完成后是否清理源文件（移入回收站）。true=入库后自动清理源文件，false=保留源文件（只读模式） |
| `recycle_retention_days` | int | 30 | 回收站文件保留天数，超期自动清理（0=永不过期） |
| `max_auto_retries` | int | 3 | 同一文件失败超过此次数后不再自动重试 |
| `scan_recursive` | bool | true | 递归扫描源目录子目录 |
| `scan_max_depth` | int | 5 | 递归扫描最大深度 |

> **废弃配置**：`cleanup_mode`（full_cleanup/smart_cleanup/read_only）和 `delete_source_after_import` 已废弃，自动迁移为 `cleanup_source_after_done`。详见 3.2 迁移说明。

#### 2.5.1 source_cleaner — 源目录清理器

源目录清理器是独立功能，与任务流无关。用于通过规则和 AI 自动清理源目录中不属于任何任务关联的垃圾文件。

| 键 | 类型 | 默认值 | 说明 |
|----|------|--------|------|
| `enabled` | bool | false | 是否启用源目录自动清理 |
| `cleanup_mode` | string | "media_only" | 清理模式：media_only（仅保留影视+字幕）/ media_and_related（保留影视+字幕+关联文件） |
| `ai_enabled` | bool | false | 是否启用 AI 辅助判断（规则+AI 联合判断） |
| `merge_strategy` | string | "intersection" | AI与规则合并策略：intersection（交集，保守）/ union（并集，激进） |
| `junk_video_max_size_mb` | int | 50 | 视频文件小于此大小视为垃圾视频（如 Sample），0=不检测 |
| `delete_extensions` | list | [".url", ".log", ".txt"] | 指定后缀名直接删除 |
| `protect_extensions` | list | [".nfo", ".jpg", ".png"] | 指定后缀名保护不删 |
| `blacklist_patterns` | list | ["RARBG*", "*/Sample/*", "*/sample/*"] | 文件名/路径黑名单（优先删除） |
| `cleanup_empty_dirs` | bool | true | 清理空目录 |
| `confirm_before_cleanup` | bool | true | 清理前需用户确认 |
| `schedule` | string | "0 3 * * *" | 定时触发（cron 格式，默认每天凌晨3点） |

> **后缀名统一**：清理器不再硬编码视频/字幕后缀，改为从全局 `video_extensions`/`subtitle_extensions` 配置读取。`delete_extensions` 指定额外删除的后缀，`protect_extensions` 指定额外保护的后缀（优先级最高）。

> **废弃配置**：`keep_media_only` → `media_only`，`keep_media_related` → `media_and_related`，加载时自动迁移。

清理器工作流程：

```
定时触发(cron)/手动触发 → 扫描源目录 → 排除已关联任务的文件
  → 规则分类（后缀名+黑名单+垃圾视频+清理模式）
  → AI 整体分析（以目录为单位，如启用）
  → 合并策略（交集/并集）→ 最终清理列表
  → 用户确认(如开启 confirm_before_cleanup)
  → 执行清理(移入回收站[清理器-源目录]分区，不直接删除)
  → 写入清理记录(API可查)
  → 消息通知+日志打印
```

### 2.6 video_extensions / subtitle_extensions

列表类型，定义系统处理的文件后缀：

```yaml
video_extensions: [".mkv", ".mp4", ".avi", ".ts", ".mov", ".wmv", ".m2ts", ".flv"]
subtitle_extensions: [".srt", ".ass", ".ssa", ".vtt", ".sub"]
```

### 2.7 path_rules — 入库规则

列表类型，按顺序匹配，第一个命中的规则生效。每条规则包含：

| 键 | 类型 | 说明 |
|----|------|------|
| `conditions` | dict | 维度条件，如 `{media_type: tv, animation: "true"}` |
| `template` | string | 路径模板，支持变量 `{title_cn}` `{title_en}` `{year}` `{season}` `{episode}` `{resolution}` `{quality}` `{ext}` |

匹配规则：
- `conditions` 为空 `{}` 时作为默认兜底规则
- `restricted_level` 支持多选，用 `|` 分隔（如 `"0-6|7-12"`）
- 精确规则放前面，通用规则放后面

### 2.8 fallback_dir — 兜底入库目录

所有 `path_rules` 都不匹配时的入库目录。不设置时，无匹配的文件在分类阶段报错中断。

### 2.9 rules — 特殊处理规则

列表类型，定义按条件触发的动作：

| 键 | 说明 |
|----|------|
| `name` | 规则名称 |
| `conditions` | 触发条件 |
| `actions` | 动作列表（如 `create_series_folder`、`organize_by_season`、`create_year_folder`） |

### 2.10 filename_templates — 文件名模板

| 键 | 说明 | 支持变量 |
|----|------|----------|
| `movie` | 电影文件名模板 | `{title_cn}` `{title_en}` `{year}` `{resolution}` `{quality}` `{ext}` |
| `tv` | 电视剧文件名模板 | 同上 + `{season:02d}` `{episode:02d}` |
| `subtitle` | 字幕文件名模板 | `{video_filename}` `{lang}` `{ext}` |

### 2.11 duplicate_handling — 同名文件处理

| 键 | 类型 | 默认值 | 说明 |
|----|------|--------|------|
| `enabled` | bool | true | 启用智能同名检测 |
| `strategy` | string | "quality" | 处理策略 |

策略选项：

| 策略 | 说明 |
|------|------|
| `skip` | 同名文件已存在则跳过 |
| `replace` | 用新文件替换已存在的文件 |
| `rename` | 两者都保留，新文件添加编号后缀 |
| `quality` | 质量优先：高分辨率优先，同分辨率保留较小文件 |

### 2.12 manual_review — 人工检查

| 键 | 类型 | 默认值 | 说明 |
|----|------|--------|------|
| `enabled` | bool | false | 启用后刮削完成不自动入库，进入 CONFIRMING 状态 |

## 3. 配置加载与迁移

### 3.1 加载流程

`load_config(config_path)` 执行以下步骤：

```
1. 确定配置文件路径
   ├─ 传入 config_path → 使用指定路径
   ├─ 环境变量 TRIM_PKGVAR → {TRIM_PKGVAR}/config/config.yaml
   └─ 默认 → {project_root}/config/config.yaml

2. 文件不存在 → 从 config.yaml.example 复制模板

3. yaml.safe_load() 解析 YAML
   └─ 格式错误 → sys.exit(1001)

4. 相对路径转绝对路径
   └─ source_dir / temp_dir / log_dir / recycle_dir

5. 配置迁移（见 3.2）

6. 默认值填充
   ├─ source_policy 默认值
   ├─ metadata 默认提供者
   ├─ manual_review 默认关闭
   ├─ confidence 全量默认值
   └─ fallback_dir 默认空

7. confidence v1 → v2 迁移

8. validate_config() 基础校验（仅警告，不阻止启动）

9. 记录 _config_path

10. 布尔字符串归一化

11. 返回 config dict
```

### 3.2 配置键迁移

`load_config()` 内置以下自动迁移逻辑：

| 旧键 | 新键 | 迁移规则 |
|------|------|----------|
| `source_dedup.quarantine_dir` | `source_policy.quarantine_dir` | 取旧值，不覆盖已有 |
| `source_dir_scan.recursive` | `source_policy.scan_recursive` | 取旧值，不覆盖已有 |
| `source_dir_scan.max_depth` | `source_policy.scan_max_depth` | 取旧值，不覆盖已有 |
| `source_policy.cleanup_mode` = "read_only" | `source_policy.cleanup_source_after_done` = false | read_only 映射为不清理 |
| `source_policy.cleanup_mode` = "full_cleanup" | `source_policy.cleanup_source_after_done` = delete_source_after_import 的值或 true | full_cleanup 映射为清理 |
| `source_policy.cleanup_mode` = "smart_cleanup" | `source_policy.cleanup_source_after_done` = delete_source_after_import 的值或 true | smart_cleanup 映射为清理，同时启用 source_cleaner |
| `source_policy.delete_source_after_import` | `source_policy.cleanup_source_after_done` | 取旧值，不覆盖已有 |
| `source_policy.smart_cleanup` | `source_cleaner` | 整体迁移为顶层 source_cleaner 配置段 |
| `source_file_handling` | （删除） | 直接删除，删除后处理为默认行为 |
| `task_queue.persistence_path` | （删除） | 直接删除 |
| `source_cleaner.cleanup_mode` = "keep_media_only" | `source_cleaner.cleanup_mode` = "media_only" | 取旧值，自动迁移 |
| `source_cleaner.cleanup_mode` = "keep_media_related" | `source_cleaner.cleanup_mode` = "media_and_related" | 取旧值，自动迁移 |

迁移特点：
- 使用 `setdefault` 语义：仅当新键不存在时才从旧键迁移，不覆盖用户已配置的新值
- 旧键通过 `config.pop()` 移除，迁移后不再保留

### 3.3 confidence v1 → v2 迁移

`_migrate_confidence_v1_to_v2()` 处理置信度配置的版本升级：

| 移除的 v1 键 | 说明 |
|--------------|------|
| `aggregation_method` | 聚合方法（v2 不再使用） |
| `tmdb_dim_confidence` | TMDB 维度置信度 |
| `file_dim_confidence` | 文件维度置信度 |
| `dim_missing_confidence` | 维度缺失置信度 |

维度级 v1 → v2 迁移：

| 移除的 v1 维度键 | v2 替代 |
|------------------|---------|
| `weight` | 不再使用 |
| `veto_threshold` | 不再使用 |
| `source_confidence` | 不再使用 |
| `tmdb_confidence` | 不再使用 |
| `ai_confidence` | 不再使用 |
| `file_confidence` | 不再使用 |
| `missing_confidence` | 不再使用 |
| `trusted_sources` | 迁移为 `sources` 列表 |

`trusted_sources` → `sources` 迁移示例：

```yaml
# v1
trusted_sources: ["tmdb", "ai"]

# v2
sources:
  - source: tmdb
    trusted: true
  - source: ai
    trusted: true
  - source: file
    trusted: false
```

## 4. 配置校验

### 4.1 基础校验（config_loader.validate_config）

在 `load_config()` 末尾调用，仅产生警告，不阻止服务启动：

| 校验项 | 条件 | 错误信息 |
|--------|------|----------|
| LLM API Key | 缺失或为占位符 | "缺少有效的 llm.api_key 配置" |
| 目录存在性 | source_dir/temp_dir/log_dir 不存在 | "{key} 不存在: {path}" |
| 目录未配置 | source_dir/temp_dir/log_dir 为空 | "{key} 未配置" |
| 回收站目录 | 未配置或不存在 | "source_policy.recycle_dir 未配置/不存在" |

### 4.2 完整校验（config_validator.validate_config）

由 API 端点 `GET /api/config/validate` 调用，返回结构化校验结果：

```json
{
  "overall": "ok" | "degraded",
  "details": [
    {"item": "source_dir", "status": "ok"|"error"|"warning", "message": "..."}
  ],
  "timestamp": "2025-01-01T00:00:00"
}
```

校验项分类：

**目录类校验**

| 校验项 | 级别 | 说明 |
|--------|------|------|
| source_dir | error | 存在性检查（只读） |
| temp_dir | error | 存在性 + 可写检查 |
| recycle_dir | error | 存在性 + 可写检查 |
| log_dir | error/warning | 存在性 + 可写检查，未配置时 warning |
| dir_conflict | error | 三个目录不能互相相同 |

**LLM 类校验**

| 校验项 | 级别 | 说明 |
|--------|------|------|
| llm_api_key | error/warning | 缺失→error，掩码值→warning |
| llm_base_url | error | 未配置或格式错误（需 http:// 或 https:// 开头） |
| llm_model | error | 未配置 |
| llm_api | error | 连通性测试（需显式触发） |

**Hermes 类校验**

| 校验项 | 级别 | 说明 |
|--------|------|------|
| hermes_webhook | error | 已启用但地址未配置或格式错误 |
| hermes_route | error | 已启用但路由名称未配置 |
| hermes_webhook_test | error | 连通性测试（需显式触发） |

**入库规则校验**

| 校验项 | 级别 | 说明 |
|--------|------|------|
| path_rules | warning | 未配置、缺少 template、缺少 conditions |

**置信度校验**

| 校验项 | 级别 | 说明 |
|--------|------|------|
| confidence.R_formula | error | 必须为 inverse/log/sqrt/flat 之一 |
| confidence.aggregation_method | error | 必须为 product/geometric_mean/min 之一 |
| confidence 阈值键 | error | 0-1 之间的数值 |
| pass vs confirm | error | pass_threshold 必须大于 confirm_threshold |
| confirm vs review | error | confirm_threshold 必须大于 review_threshold |
| R_max_results_cap | error | 正整数 |
| ai_cap_* 键 | error | 0-1 之间的数值 |
| dimensions 权重 | error | weight 必须为正数 |
| dimensions veto | error | veto_threshold 必须 0-1 |
| dimensions source_confidence | error/warning | 数值 0-1 / 格式应为字典 |

**磁盘空间校验**

| 级别 | 条件 |
|------|------|
| ok | > 1 GB |
| warning | 0.1 - 1 GB |
| error | < 0.1 GB |

### 4.3 连通性测试

**LLM API 测试**（`test_llm_api`）：

| 步骤 | 说明 |
|------|------|
| 1 | 构造 `{base_url}/chat/completions` 请求 |
| 2 | 发送 `{"model": model, "messages": [{"role": "user", "content": "test"}], "max_tokens": 5}` |
| 3 | 检查响应状态码：200=成功，401=认证失败，404=端点不存在 |

**Hermes Webhook 测试**（`test_hermes_webhook`）：

| 步骤 | 说明 |
|------|------|
| 1 | 构造 `{base_url}/webhooks/{route_name}` 请求 |
| 2 | 发送测试消息（event_type: "test_notification"） |
| 3 | 如有 secret，计算 HMAC-SHA256 签名附加到 `X-Webhook-Signature` 头 |
| 4 | 检查响应：200 + success/ok=成功，401=认证失败，404=路由不存在 |

### 4.4 路径权限检查

`check_path(path, require_write)` 用于检查目录是否存在及可写：

| 检查 | 方法 |
|------|------|
| 存在性 | `os.path.exists(path)` |
| 是目录 | `os.path.isdir(path)` |
| 可写性 | 创建并删除临时测试文件 `.test_write_{timestamp}` |

## 5. 敏感信息脱敏

`mask_sensitive(config)` 在 API 返回配置时调用，防止密钥泄露：

| 配置键 | 脱敏规则 | 示例 |
|--------|----------|------|
| `server.api_key` | 全部替换为 `***` | "my-secret-key" → "***" |
| `llm.api_key` | 保留前缀（到第一个 `-`），其余替换为 `***` | "sk-abc123" → "sk-***" |
| `metadata.providers[].api_key` | 全部替换为 `***` | "tmdb-key" → "***" |
| `hermes.webhook.secret` | 全部替换为 `***` | "hmac-secret" → "***" |

LLM API Key 的前缀保留逻辑：遍历字符串找到第一个 `-` 的位置，保留到该位置（含），其余替换。如果 API Key 中不含 `-`，则全部替换为 `***`。

## 6. 配置热重载

### 6.1 当前机制

系统当前**不支持**配置热重载。修改 `config.yaml` 后需要重启服务才能生效。

### 6.2 配置保存流程

通过 API 端点 `POST /api/config` 保存配置：

```
1. 接收前端提交的配置 JSON
2. 写入 config.yaml 文件
3. 更新内存中的 _config 引用
4. 部分配置项立即生效（如 path_rules、filename_templates）
5. 部分配置项需重启生效（如 server.port、llm.base_url）
```

### 6.3 提示词热更新

刮削提示词存储在独立文件 `config/scraper_prompts.md` 中，通过 API 端点 `POST /api/config/save-prompts` 保存。提示词变更在下次刮削调用时自动生效，无需重启。

## 7. 职责边界

### 负责

- 配置文件加载与解析（YAML）
- 配置键自动迁移（旧键→新键，向后兼容）
- 默认值填充
- 敏感信息脱敏（mask_sensitive）
- 布尔字符串归一化
- 配置完整性校验（基础校验 + 完整校验）
- 连通性测试（LLM / Hermes）
- 路径权限检查

### 不负责

- 配置保存到磁盘的 YAML 格式化（由 api/config_handlers 中的 ruamel.yaml 处理）
- 运行时配置热重载触发（由 api 层控制）
- 业务逻辑使用配置（由各业务模块自行读取）

### 7.8 布尔字符串归一化

配置文件中某些键可能以字符串形式写入布尔值（如 `"true"`、`"yes"`、`"on"`）。`_normalize_bool_strings()` 在加载时自动将这些值转换为 Python 原生布尔类型。

需要归一化的键名集合（`BOOL_KEYS`）：

| 键名 | 说明 |
|------|------|
| `enabled` | 各种启用开关 |
| `verify_ssl` | SSL 验证开关 |
| `delete_after_process` | 处理后删除 |
| `cleanup_source_after_done` | 任务完成后清理源文件 |
| `ai_enabled` | AI 辅助判断（源目录清理器） |
| `cleanup_empty_dirs` | 清理空目录 |
| `confirm_before_cleanup` | 清理前确认 |
| `recursive` | 递归扫描 |
| `create_series_folder` | 创建剧集文件夹 |
| `organize_by_season` | 按季组织 |
| `create_year_folder` | 创建年份文件夹 |
| `auto_delete_success` | 成功后自动删除 |
| `scan_source` | 扫描源目录 |

字符串到布尔映射：

| True 值 | False 值 |
|---------|----------|
| `"true"`, `"yes"`, `"on"` | `"false"`, `"no"`, `"off"` |

归一化递归遍历整个配置字典（包括嵌套 dict 和 list 中的 dict），对所有匹配 `BOOL_KEYS` 的键执行转换。
