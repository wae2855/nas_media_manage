Config Reading Demo

说明内容从“功能卡片”回归“阅读内容”

这个 demo 只聚焦一个问题：当前配置页里很多说明内容被设计得太像可点击功能块，尤其是“开始”“刮削配置”“AI 配置”这类页面。下面左边模拟当前的嵌套感，右边展示统一改造后的阅读型方案。

当前视觉感觉

说明内容和功能入口长得太像，层级感重，阅读负担大。

AI 刮削 可选。不配置则走纯刮削器；配置后刮削器 + AI 结合，取置信度更高的结果。
AI 刮削说明 这里本来是帮助阅读的说明，但视觉上仍然像一个功能容器。
不配置 AI 刮削 系统使用 TMDB 等 Provider 独立完成元数据获取。
配置 AI 刮削 同一字段取置信度更高的值，适合冷门影片。
联网搜索增强 开启后 AI 可以获取最新影视信息，提高刮削准确率。
模型要求 轻量模型 + 搜索能力通常就够用。
联网搜索增强 作为子手风琴继续嵌套，看起来又像一个新功能入口。

可选能力
AI 刮削说明

说明区不再像功能卡，而像设置页里的帮助文档

AI 刮削是可选能力，用于补齐 Provider 覆盖不到的影片信息。这里不再用额外容器把说明切碎，而是直接用标题、段落、留白和细分隔线组织阅读节奏。

不开启时
仅使用 Provider 刮削 适合已有稳定元数据来源、希望流程更简单的场景。
开启后
Provider + AI 联合判断 更适合冷门影片、别名复杂或刮削结果经常不完整的情况。
模型要求
轻量模型即可 不需要高端模型，优先速度快、成本低、兼容 OpenAI API 的服务。
重要提醒 只有真正可操作的内容才保留表单容器。说明型内容尽量不画边框，只保留一条很轻的视觉提示，让用户知道这是一段需要阅读的信息。

配置项

说明读完后，下面才进入可操作表单。这样用户对“哪里是信息、哪里是动作”会一眼分清。

高级选项：联网搜索增强 保留折叠，但作为与表单同级的高级项，不再嵌套在说明卡内部。
默认收起
这个 demo 对应的真实落地方式： 配置页里像“开始 / 刮削配置 / AI 配置 / 入库规则”这些页面，说明区统一改成这套阅读型结构；原来的 `config-guide-card`、`start-step-card`、`start-directory-card`、嵌套说明卡会大幅减少，只保留给真正的功能表单和交互区域。
