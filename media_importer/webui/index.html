配置顺序

三步完成基础配置

按照目录→识别能力→落库方式的顺序完成，可以减少反复调整。

第 1 步
先把目录边界定清楚先完成授权，再配置源目录、中转目录和回收目录。
第 2 步
再打开识别能力配置刮削 Provider 和 AI，让系统开始识别、补全和判断。
第 3 步
最后决定落库方式设置入库规则、命名方式和兜底目录，确认最终落点。
首次使用先记住这几点 所有目录都要在 fnOS 应用中心授权读写权限；AI 配置未完成时主流程无法完整工作；完成基础配置后先用【运行模拟】检查规则是否符合预期。

刮削模式说明

控制 AI 与 Provider 刮削的协作方式

刮削模式决定系统如何选择 AI 和元数据源（Provider）来完成影视元数据获取。不同模式在准确性、成本和速度上有不同的侧重。

重要提示 选择「纯 AI 刮削」模式时，必须在「AI 配置」页签中配置「AI 搜索增强」，填写支持联网搜索的模型接口地址、模型ID 和 API Key，并确认 API Key 已开通联网搜索（MCP）功能。未配置 AI 搜索增强时，纯 AI 模式将无法工作。
Provider 优先（推荐）
省成本、Provider 为主先使用元数据源（TMDB）获取数据，AI 仅在元数据源数据不完整时补充缺失维度。Provider 数据完整时不会调用 AI，节省 API 调用成本。即使未启用 AI 刮削也可正常工作（仅在 Provider 缺失时降级到 AI）。
纯 AI 刮削
完全依赖 AI、必须配置 AI 搜索增强不使用元数据源 API，所有信息均由 AI 联网搜索后推断。必须在 AI 配置中启用「AI 搜索增强」，填写支持联网搜索的模型接口地址、模型ID 和 API Key，并确认 API Key 已开通联网搜索（MCP）功能，否则将无法完成刮削。

AI 辅助说明

标题清洗、结果整理、目录清理都依赖此项

AI 辅助承担标题清洗、Provider 数据整理、源目录智能清理等轻量任务。推荐速度快、成本低的模型，不需要联网搜索。

必须配置
多个核心功能依赖标题清洗、刮削结果整理、源目录智能清理都需要此项。未配置时相关功能不可用。
不用联网
基于已有数据判断辅助任务基于文件名解析、格式转换、分类识别等已有数据，不需要联网搜索能力。
模型要求
速度快、成本低推荐 MiniMax-M2.7-highspeed、DeepSeek-V3、GLM-4-flash 等。
推荐模型
MiniMax-M2.7-highspeed速度快、成本低，推荐首选
DeepSeek-V3通用能力强
GLM-4-flash智谱免费额度
gpt-4o-miniOpenAI 轻量模型
使用场景
以下功能使用 AI 辅助模型 ① 标题清洗（从文件名提取影视标题） ② 源目录智能清理 · AI 辅助判断 ③ Provider 优先模式 · 维度补缺（当 AI 搜索增强未配置时降级使用）

AI 搜索增强说明

配置支持联网搜索的模型，用于 AI 刮削和维度补缺

AI 搜索增强利用大模型厂商自带的联网搜索能力获取最新影视信息，提高刮削准确率。必须填写支持联网搜索的模型。适合冷门影片、别名复杂的场景。Provider 优先模式下维度补缺也优先使用此模型。

已配置时
Provider 优先 + AI 搜索增强补缺Provider 数据完整时不调用 AI，缺失维度由 AI 搜索增强补充。纯 AI 模式下全量使用此模型刮削。
未配置时
只使用 Provider 刮削系统使用 TMDB 等 Provider 独立获取元数据，AI 补缺降级为辅助模型（无联网搜索）。
模型要求
必须支持联网搜索请确认你的 API Key 已开通 MCP 网络搜索功能，否则联网搜索不会生效。
支持联网搜索的厂商
智谱 GLM接口含 bigmodel.cn，使用 tools.web_search 参数
通义千问接口含 dashscope / aliyun，使用 enable_search 参数
Kimi / Moonshot接口含 moonshot，使用 builtin_function.$web_search 参数

DeepSeek 官方 API 暂不支持联网搜索。豆包/火山引擎仅 Responses API 支持，Chat API 暂不支持。MiniMax 联网搜索需通过 MCP 协议，Chat API 暂不支持。后续版本将支持更多搜索方式和模型厂商。

支持检测
系统根据接口地址自动判断是否支持联网搜索，无需手动开启。
